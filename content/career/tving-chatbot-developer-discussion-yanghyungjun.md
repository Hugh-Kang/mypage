# 챗봇 AI 개발자(양형준, 마인드로직)와의 토의 — 구조화 및 시사점

> 작성 목적: 티빙 2차 면접을 앞두고 챗봇/AI 개발 경험이 있는 지인(양형준, 마인드로직)과 나눈 카카오톡 대화를 구조화하고, 그 안에서 나온 피드백의 시사점과 추가로 고민해야 할 지점을 정리
> 작성일: 2026-10-14
> 근거자료: 양형준(마인드로직)과의 카카오톡 대화 전문(2026-10-14), `tving-chatbot-mvp-design-socratic-result.md`(V1), `tving-chatbot-mvp-v2-viral-trend-agent-design.md`(V2)

## 핵심 요약 (두괄식)

양형준님의 피드백에서 가장 중요한 지점은 두 가지입니다. ① **바이럴 에이전트는 "개인화가 전혀 없어서 챗봇이라는 인터페이스를 쓸 이유가 없다"**는 지적 — 이는 "그냥 메인 페이지 큐레이션이 더 낫지 않나"는 질문으로 이어졌고, 이미 V2 설계에서 "챗봇이 아니라 홈 화면 자동 노출 카드"로 정리했던 방향과 기술자 관점에서도 일치합니다. ② **"답정너" 문제** — 모두에게 동일한 트렌드 정보만 준다면 사용자와의 "대화"라는 형식 자체가 의미 없어질 수 있다는 지적으로, 아직 명확한 해법이 없는 지점입니다. 반대로 일반 컨텐츠 추천 챗봇(원래 V1, 기분 기반)은 "기능과 플로우가 구체적이라 MVP 제작이 더 간단하다"는 긍정적 평가를 받았고, 시청기록/리뷰 데이터 활용, 버튼형 UI, 지표 설계라는 실질적 보완 방향도 함께 받았습니다.

---

## 1. 대화 구조화

### 1-1. 질문 배경

- 강해우가 티빙 2차 면접을 앞두고, 1차 면접에서 받은 "홈 화면 챗봇 에이전트 MVP 설계" 질문에 대비해 양형준(AI 스타트업 마인드로직 재직, 챗봇 개발 경험)에게 자문을 구함
- 본인이 고민한 2가지 안을 제시: ① 바이럴 에이전트(진선규 일본어 바이럴 → 컬렉션 추천), ② 일반 컨텐츠 추천 챗봇(기분 기반, 방향감 없는 사용자 타겟)

### 1-2. 바이럴 에이전트(①)에 대한 1차 피드백 — "챗봇으로서 차별점이 뭔가"

> "1번은 아이디어가 새롭긴 한데 설명해주신 플로우대로는 회원의 관심사가 반영될 부분이 없어서 그냥 모두에게 동일한 정보를 추천해주게 되는 서비스가 될 것 같아요. 이게 챗봇으로서 가져야 할 차별점이 뭘까요? 챗봇보다는 티빙 메인 페이지 큐레이션으로 더 좋은 기능이 아닐지?"

| 지적 내용 | 의미 |
|---|---|
| 개인화 요소 부재 | 바이럴 정보는 모든 사용자에게 동일하게 적용되므로, "대화"라는 상호작용 형식이 필요 없을 수 있음 |
| "챗봇 vs 큐레이션" 구분 | 개인화 없는 정보 제공은 챗봇(대화형 UI)보다 정적 배너/큐레이션 섹션으로 구현하는 게 더 적합할 수 있다는 기술자 관점의 판단 |

### 1-3. 일반 추천 챗봇(②)에 대한 1차 피드백 — "MVP로서 더 구체적"

> "2번은 기능이나 플로우가 더 구체적으로 느껴져서 MVP 제작이 더 간단할 것 같아요. 여기에 유저별 시청 기록이나 리뷰평가... 반영하는 걸 추후 확장성으로 삼을 수 있을 것 같고요. 추천받고 싶은 유저는 아마 구구절절히 설명하기 귀찮아 할 가능성이 높아 보여서, 유저가 챗봇에 입력하는 걸 귀찮아 할 때 어떤 기능이 도움 될지 생각해보면 좋을 것 같기도 하구요."

- 긍정 평가: 플로우가 구체적이라 MVP 범위로 현실적
- 확장 아이디어: 시청기록·리뷰평가를 반영한 개인화 고도화(단, "티빙에 리뷰평가 기능이 있는지"는 양형준도 확신하지 못해 **사실 확인이 필요한 질문으로 남음**)
- 리스크 지적: 사용자가 자기 취향을 길게 설명하는 걸 귀찮아할 가능성 → 입력 부담을 줄이는 UI가 필요

### 1-4. 공통 피드백 — "지표와 가치 측정을 고민하면 좋다"

> "챗봇 말고도 다른 기능도 마찬가지겠지만 운영하면서 성능 지표 설정과 측정을 어떻게 할지, 이 챗봇이 가져다 주는 밸류를 어떻게 측정할 수 있는지 고민해보고 이야기하면 회사 사람들이 좋아하지 않을까요?"

- 지표/가치 측정 체계를 먼저 챙기라는 일반적이지만 중요한 조언

### 1-5. 강해우의 보완 설명 (재질문에 대한 답)

- 바이럴 에이전트에 대해: "회원의 관심사는 반영되지 않고, 현재 트렌드만 보여주는 게 목표"라고 **의도적 설계임을 재확인** — 홈 화면 추천 알고리즘이 만든 트렌드가 아니라 실제 트렌드를 보여주는 것이 핵심 가치라고 재정의
- 입력 부담 해결책으로 **버튼형 UI** 제안
- 지표: 두 에이전트 모두 **CTR, 재생 전환율, 시청시간**이 핵심 지표이며, ①의 가치는 "실제 트렌드 반영", ②의 가치는 "버튼 몇 번으로 편하게 취향 탐색"이라고 구분해서 설명

### 1-6. 양형준의 2차 피드백 — "답정너" 문제 제기 + 새 아이디어 제안

> "1. 그러면 이제 어떻게 답정너처럼 챗봇이 자기 할 말만 안 하고 유저의 만족도를 높여줄지가 관건이겠군요"
> "3. 얘기 들으면서 드는 생각인데, 뭐 하나 보고 나면 방금 본 거 어땠냐고 물어보면서 뭐가 좋은지 대화 기반으로 유저 취향을 더 디테일하게 저장해주는 챗봇 만드는 것도 재밌겠네요"

- **"답정너" 지적**: 바이럴 에이전트가 의도적으로 비개인화됐다는 해명을 들은 뒤에도, "일방적으로 정해진 말만 하는 챗봇이면 사용자 만족도를 어떻게 높일 것인가"라는 더 날카로운 질문으로 되돌아옴 — 아직 해결되지 않은 핵심 과제
- **시청 후 피드백 수집 아이디어**: "방금 본 거 어땠어?"라고 물어 대화 기반으로 취향을 축적하는 챗봇 — 기존에 없던 새로운 확장 아이디어

## 2. 시사점

### 2-1. V2(바이럴 커넥터) 설계 방향이 기술자 관점에서도 재확인됨

이미 `tving-chatbot-mvp-v2-viral-trend-agent-design.md`에서 바이럴 아이디어는 "챗봇이 아니라 홈 화면에 선제적으로 노출되는 카드" 형태로 설계해뒀는데, 양형준님의 "챗봇보다는 메인 페이지 큐레이션이 낫지 않나"는 지적은 정확히 같은 결론에 기술자 입장에서 독립적으로 도달한 것입니다. **다만 카톡에서는 이 아이디어를 여전히 "챗봇"으로 설명했기 때문에**, 실제 면접에서는 "바이럴 정보는 카드/큐레이션 형태로, 대화형 챗봇은 개인화 추천에만 쓴다"는 구분을 처음부터 명확히 전달해야 이런 지적을 선제적으로 차단할 수 있습니다.

### 2-2. "답정너" 문제는 바이럴 에이전트의 가장 날카로운 약점

"회원 관심사 미반영이 의도된 설계"라고 해명해도, "그럼 사용자와의 상호작용에 무슨 의미가 있냐"는 질문은 여전히 남습니다. 이는 `tving-chatbot-mvp-v2-selfdraft-critique-tailquestions.md`에서 다룬 질문들과는 또 다른 각도의 비판이라, **면접에서 나올 가능성이 높은 새로운 꼬리질문**으로 추가해둘 필요가 있습니다.

### 2-3. 일반 추천 챗봇(원래 V1)이 "기술적 실현 가능성" 측면에서 더 안정적이라는 외부 검증

세령님과의 토의에서는 "안전빵"이라는 평가를 받았던 V1이, 개발자 관점에서는 오히려 "플로우가 구체적이라 MVP로 더 간단하다"는 정반대의 긍정 평가를 받았습니다. 이는 **"창의성"과 "구현 가능성"이 서로 다른 축**이라는 뜻이며, 면접에서는 둘 중 하나를 버리기보다 "V1은 구현 가능성이 검증된 베이스, V2는 그 위에 얹는 확장 아이디어"로 함께 제시하는 전략이 유효함을 다시 한번 확인시켜줍니다.

### 2-4. 확인되지 않은 사실(리뷰평가 데이터) 관리 필요

양형준님이 "티빙에 리뷰평가 기능이 있나요?"라고 물었을 때 강해우가 답하지 않고 넘어간 부분이 있습니다. 실제 면접에서 "유저 리뷰 데이터를 활용하겠다"고 말하려면, 티빙에 실제 리뷰/평점 기능이 있는지 사전에 확인해두는 것이 안전합니다.

## 3. 더 고민해야 할 점

1. **"답정너" 문제의 해법**: 바이럴 정보 자체는 비개인화 상태로 유지하더라도, 그 바이럴 대상(배우/작품)과 **사용자의 과거 시청 이력을 교차**시켜 "평소 OO 장르를 즐겨보신 분들께 지금 화제인 이 작품을 추천합니다"처럼 "트렌드(비개인화) + 추천 메시지(개인화)"를 결합하는 하이브리드 구조를 고민해볼 가치가 있습니다.
2. **리뷰/평점 데이터 존재 여부 확인**: 티빙에 실제 리뷰·평점 기능이 있는지 사전 확인 필요 — 있다면 확장 아이디어로 그대로 쓰고, 없다면 "시청 완료 여부/재시청 여부" 같은 암묵적 신호로 대체 설명을 준비
3. **시청 후 피드백 수집 아이디어의 구체화**: "방금 본 거 어땠어?"라는 대화형 피드백을 채택할지, 채택한다면 몇 턴짜리 대화로 할지, 그리고 이 데이터를 추천 로직에 어떻게 반영할지(즉시 반영 vs 배치 반영)를 더 구체화할 필요
4. **바이럴 아이디어를 설명할 때 "챗봇"이라는 단어 사용 자제**: 면접에서 바이럴 아이디어를 말할 때는 처음부터 "대화형 챗봇"이 아니라 "에이전트가 자동으로 큐레이션하는 카드"라고 명확히 표현해, 형준님이 지적한 것과 같은 의문이 나오기 전에 선제적으로 정리
5. **지표/가치 측정을 더 구체적으로 다듬기**: 이미 준비된 North Star+가드레일 구조(`tving-ai-agent-mvp-kpi-deep-dive-answers.md`)를 활용하되, "이 챗봇이 가져다주는 밸류"를 정성적으로도 한 문장 설명할 수 있도록 준비(예: "사용자가 탐색에 쓰는 시간을 줄여준다" 등)
