# 티빙 챗봇 에이전트 MVP 설계안 (소크라틱 질문법으로 직접 도출)

> 작성 목적: `tving-chatbot-mvp-socratic-metaprompt.md`의 소크라틱 코칭 세션을 통해, 스스로 질문에 답해가며 도출한 티빙 챗봇 에이전트 MVP 설계를 하나의 완결된 설계안으로 정리
> 작성일: 2026-10-13
> 근거자료: 세션 내 소크라틱 Q&A(문제정의→진입점→대화 플로우→실패조건→콘텐츠 범위→지표→인과검증 순으로 전개)

## 핵심 요약 (두괄식)

이 MVP는 **"뭘 볼지 몰라 이탈하는 사용자"만을 좁게 겨냥**합니다. 홈 화면에 "오늘 뭐 볼지 추천받기"라는 별도 진입 버튼을 신설해, 이미 장르 선호가 뚜렷한 사용자는 기존 검색·필터로 자연스럽게 분리하고, 방향감이 없는 사용자만 챗봇으로 유입시킵니다. 대화는 "기분"을 축으로 2~3턴 안에 추천까지 이어지고, 불만족 시 다른 기준으로 1회 더 시도한 뒤에는 기존 홈 화면 추천으로 자연스럽게 폴백합니다. 추천 대상 콘텐츠도 전체 카탈로그가 아닌 오리지널·화제작 20~30개로 좁혀 콜드스타트 리스크를 줄였습니다. 성공 여부는 "추천 클릭 후 10분 이상 시청"을 전환으로 정의해 기존 홈 화면 추천 대비 비교하고, A/B 테스트(대조군은 버튼 자체 미노출)로 순수 인과효과를 분리합니다.

---

## 1. 문제 정의와 왜 "대화형"이어야 하는가

- **풀려는 문제**: 뭘 볼지 몰라서 탐색하다 이탈하는 사용자
- **왜 기존 추천 알고리즘만으로는 부족한가**: 알고리즘은 사용자의 암묵적 행동 데이터로 취향을 추정할 뿐이라, 사용자가 "오늘 이런 걸 보고 싶다"는 걸 직접 구체화할 기회가 없음
- **왜 하필 지금인가**: 챗GPT·제미나이 같은 대화형 LLM으로 검색하는 습관이 보편화되면서, 콘텐츠 탐색 방식도 이 흐름에 맞춰 변화할 필요가 있음

## 2. 진입점 설계 — 왜 "버튼 두 개 분리"인가

- 홈 화면에 **"오늘 뭐 볼지 추천받기"** 버튼을 신설해, 방향감 없는 사용자만 여기로 유입
- 이미 보고 싶은 장르·작품이 명확한 사용자는 **기존 검색·필터 기능**으로 자연스럽게 분리 — 장르는 이미 기존 UI가 잘 커버하고 있어, 챗봇이 굳이 재현할 필요가 없는 영역
- 첫 질문 하나로 장르/기분 분기를 태우는 대신, **진입 버튼 자체를 둘로 나누는 것이 가장 단순한 구조**라는 결론에 도달 — 복잡한 분기 로직 없이도 두 사용자군이 자연히 갈라짐

## 3. 대화 플로우 (턴 수·실패 조건·폴백)

1. "기분으로 찾기" 진입 → **"기분"을 묻는 질문으로 시작** (장르는 이미 다른 경로로 커버되므로, 챗봇은 기존 UI가 못 하는 축부터 공략)
2. **2~3턴** 대화 후 추천 콘텐츠 제시
3. 추천이 마음에 안 들면, **같은 기준이 아닌 다른 기준(화제성·톤 반전·추가 질문 등)으로 1회 재시도**
4. 이마저도 불만족이면 **기존 홈 화면 추천으로 자연스럽게 전환** — 최대 2회 반복 후 폴백해 사용자를 무한 루프에 가두지 않음

## 4. 콘텐츠 범위와 신선도 유지

- 전체 카탈로그가 아니라 **오리지널·화제작 중심 20~30개 타이틀**로 좁힘 — 데이터가 충분히 쌓인 대표 콘텐츠부터 안전하게 검증
- 좁은 범위로 인한 **반복 추천 문제는 리스트를 주기적으로 갱신**해 완화

## 5. 향후 개인화 확장 계획 (MVP 이후)

- MVP는 **모든 사용자에게 동일한 "기분" 질문**으로 시작(데이터 유무에 따른 분기는 넣지 않음 — 과도한 초기 복잡도 방지)
- 이후 시청 데이터가 쌓인 사용자에게는 **개인화된 첫 질문으로 분기를 추가**하는 식으로 단계적으로 확장

## 6. 핵심 지표와 인과관계 검증

- **핵심 지표**: 추천 클릭 후 **10분 이상 재생 = 전환**으로 정의
- **비교 기준**: 기존 홈 화면 추천의 전환율 대비 비교
- **인과관계 검증**: A/B 테스트로 실험군·대조군을 나누고, **대조군에는 "오늘 뭐 볼지 추천받기" 버튼 자체를 노출하지 않음** — 순수하게 이 기능이 만들어낸 증분 효과만 분리해서 측정
