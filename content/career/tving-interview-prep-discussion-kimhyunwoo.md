# 티빙 면접 준비 미팅(김현우) — 구조화 및 추가 학습 항목

> 작성 목적: 티빙 2차 면접 준비 과정에서 김현우와 나눈 회의(Gemini 자동 회의록 기반)를 구조화하고, 면접 전 추가로 공부해야 할 항목을 정리
> 작성일: 2026-10-14
> 근거자료: 김현우와의 회의 요약본(2026-10-14, Gemini 자동 생성 회의록)

## 핵심 요약 (두괄식)

이번 미팅에서 가장 완성도 높게 평가받은 아이디어는 **"팬톡(커뮤니티) 데이터를 챗봇 에이전트로 수집해 스포일러 방지와 홍보 문구 생성에 활용"**하는 방안으로, 김현우로부터 "기술적으로 명확하고 구현 가능성이 높으며 최신 트렌드를 반영했다"는 긍정 평가를 받았습니다. 다만 두 가지는 추가로 공부가 필요합니다. ① **검색 트렌드 활용 방안**은 "그래서 실무에서 구체적으로 어떻게 쓰이는지"에 대한 깊이가 아직 부족하다는 지적을 받았고, ② **스포일러 판별에 제안된 "Jev" 모델**(사용자 정정: 회의록상 "ZEV"는 "Jev"의 오기)은 실제로 조사해보니 **"오픈AI가 공개한 모델"이라는 회의 중 설명 자체가 부정확**했던 것으로 확인되어, 정확한 사실관계로 바로잡아야 하는 항목입니다.

---

## 1. 대화 구조화

### 1-1. 미팅 목적
- 티빙 2차 면접 준비 과정에서 논의했던 내용을 정리하고, 기술적 궁금증과 해법을 가볍게 이야기하기 위한 자리

### 1-2. 크롤링 및 검색 트렌드를 활용한 바이럴 콘텐츠 추천
- 강해우: 면접에서 "크롤링 활용 경험"을 물을 경우에 대비해, 유튜브·인스타그램 해시태그 수와 구글 트렌드·네이버랩 검색 트렌드를 활용해 바이럴 콘텐츠를 발굴하고 관련 컬렉션을 추천하는 방안을 설명
- 김현우: "검색 트렌드를 실무에 어떻게 활용할지"에 대한 면접관의 추가 질문에 대비할 필요가 있다는 의견 → **아직 구체성이 부족하다는 신호**

### 1-3. 팬톡 커뮤니티 데이터 + 챗봇 에이전트를 활용한 홍보/스포일러 방지 (가장 긍정적 평가)
- 강해우: 티빙 팬톡(커뮤니티 기능)에서 실시간으로 오가는 사용자 반응을 챗봇 에이전트가 수집해, 스포일러 방지와 콘텐츠 홍보 문구 생성에 활용하는 방안 제안
- 김현우: "기술적으로 명확하고 구현 가능성이 높으며 최신 트렌드를 반영한 유용한 접근"이라고 평가 — **지금까지 나온 모든 아이디어 중 가장 좋은 외부 평가**

### 1-4. Jev 모델을 활용한 스포일러 판별
- 김현우: 스포일러 여부 판별을 위해, 자연어 이해 성능과 구조화된 답변 출력이 가능한 "Jev" 인공지능 의사결정 모델이나 유사 모델 활용을 제안
- 합의 내용: 이런 경량 모델을 쓰면 일반 언어 모델 대비 API 호출 비용이 저렴하고, 레이턴시·컴퓨팅 비용이 줄어 MVP 단계에서 시간·비용 효율적으로 구현 가능
- 회의 중 조언: "오픈AI가 공개한 모델이므로 직접 파인튜닝보다는 API 활용 관점으로 접근해야 한다"는 설명이 있었음

> ⚠️ **사실관계 정정 (웹 검색으로 확인)**: 회의에서 "오픈AI가 공개한 모델"이라고 설명됐지만, 이는 부정확합니다. **Jev는 OpenAI가 아니라 TypeSafe AI라는 스타트업이 2026년 9월 15일 공개한 모델**이며, 창업자 Diogo Almeida가 과거 OpenAI에서 RLHF·InstructGPT 개발에 참여했던 이력 때문에 "오픈AI 출신"이 "오픈AI가 공개"로 와전된 것으로 보입니다. Jev는 텍스트를 생성하지 않는 **비생성형(non-generative) 모델**로, 입력된 상황(state)을 미리 정의한 타입이 있는 질문들에 대해 평가해, 각 질문마다 확률 분포와 신뢰도(confidence)가 포함된 구조화된 답변을 한 번의 API 호출로 반환하는 방식입니다. 다만 **현재는 자체 호스팅 API를 통한 얼리 액세스(대기열) 단계의 독점(proprietary) 모델**이라, 지금 바로 자유롭게 연동할 수 있는 상태는 아닙니다. "기존 LLM 대비 최대 200배 빠르다"는 식의 속도·비용 수치는 모두 벤더(TypeSafe AI) 자체 발표 자료에서 나온 것이며, 독립적인 벤치마크로 검증된 수치는 아직 확인되지 않았습니다. 면접에서 이 모델을 언급할 때는 "오픈AI가 만든 모델"이 아니라 "오픈AI 출신 연구자가 만든 스타트업의 신생 특화 모델"이라고 정확히 표현해야 하며, 아직 얼리 액세스 단계라는 한계도 함께 언급하는 것이 안전합니다.

### 1-5. 챗봇 기반 콘텐츠 추천의 UX 설계
- 강해우: 썸네일이나 키워드 압축형 문장으로 리스트를 제공하고, 버튼형 UI로 사용자가 기분·취향에 따라 선택하게 하는 방식을 설명
- 김현우: 버튼형 UI와, 사용자가 직접 텍스트를 입력해 추천받는 에이전트 기반 방식의 차이점을 짚으며 논의

### 1-6. PM과 AI 엔지니어의 역할 구분
- 강해우: PM은 모델 선택에 과도하게 개입하기보다, 예상 입력·출력값과 서비스 정책을 세부적으로 설계해 전달해야 한다는 기존 입장을 재확인
- 과거 아이돌 챗봇 기획 당시 MBTI·말투·이모지 사용 여부·존댓말 설정표 등으로 챗봇 간 차별성을 뒀던 경험을 예시로 듦 (기존 `tving-interview-pm-modeler-boundary-two-answers.md` 답변 3과 동일한 사례)
- 김현우: 긍정적으로 공감

## 2. 더 공부해야 할 것

### 2-1. Jev 모델의 기술적 원리 심화 학습 — 최우선 액션 아이템
- 회의 자체에서 "다음 단계"로 명시된 항목: Jev와 같은 AI 의사결정 모델의 기술적 원리와 면접 활용 방안을 조사하고, 이를 MVP 단계의 스포일러 방지 솔루션 적용 전략으로 구체화할 것
- 기본 사실관계는 위에서 정정·확인 완료(TypeSafe AI 개발, 비생성형 구조화 판단 모델, 현재 얼리 액세스 단계)
- 추가로 확인할 내용: OpenAI의 "structured outputs" 기능과의 기술적 차이(Jev는 토큰 단위 디코딩이 아니라, 미리 선언한 선택지에 대한 확률 분포를 직접 계산하는 방식이라는 점이 핵심 차이로 소개됨 — 다만 "환각 없음"이라는 주장은 출력 형식에 대한 보장일 뿐, 답변 내용 자체의 사실 정확성까지 보장하는 것은 아니라는 비판도 있음), 현재 얼리 액세스 단계라 실제 서비스에 당장 적용하기 어렵다는 점을 면접 답변에서 어떻게 솔직하게 다룰지(예: "현재는 왜곡 없이 검토 중인 신생 기술이고, 대안으로는 기존 경량 분류 모델/프롬프트 엔지니어링으로 MVP를 먼저 검증하겠다"는 식의 현실적인 단계적 접근 답변 준비)

### 2-2. 검색 트렌드의 "실무 활용 방식" 구체화
- 김현우가 지적한 약점: "검색 트렌드를 수집했다"까지는 있지만 "그래서 실제 서비스에서 어떻게 쓰이는가"가 약함
- 이미 작성해둔 `tving-viral-detection-methods-two-examples.md`(네이버 데이터랩·소셜 버즈 SaaS 기반 탐지 파이프라인)와 연결해, "수집 → 판정 → 매칭 → 승인 → 노출"까지 이어지는 흐름을 이번 미팅에서 나온 유튜브/인스타그램 해시태그 수치까지 포함해 업데이트할 필요

### 2-3. 유튜브·인스타그램 해시태그 데이터의 실제 수집 가능 범위 확인
- 유튜브는 YouTube Data API로 해시태그 검색이 가능하지만, 인스타그램은 Graph API 정책상 비즈니스 계정 중심으로 제약이 많아 해시태그 집계가 생각보다 제한적일 수 있음 — 면접에서 "인스타그램 데이터는 실제로 어떻게 가져오나요?"라는 질문에 대비해 플랫폼별 API 정책 차이를 미리 확인해둘 필요

### 2-4. 버튼형 UI vs 텍스트 입력 기반 에이전트의 차이 정리
- 김현우와 짚었던 이 차이를, 어떤 상황에 어느 방식이 더 적합한지(예: 선택지가 명확할 땐 버튼형, 자유도 높은 요청엔 텍스트+자연어 이해)로 한 번 더 정리해두면 "왜 버튼형을 택했는가"라는 꼬리질문에 바로 답할 수 있음

### 2-5. 스포일러 방지 기능과 기존 바이럴 탐지 설계의 통합 여부
- 지금까지 준비한 바이럴 탐지 에이전트(V2)와, 이번에 새로 나온 "팬톡 데이터 기반 스포일러 방지"는 둘 다 "외부/내부 반응 데이터를 모니터링한다"는 공통점이 있음 — 이 둘을 하나의 "콘텐츠 반응 모니터링 에이전트"라는 더 큰 틀로 묶어 설명할 수 있을지, 아니면 완전히 별개 기능으로 분리해서 말할지 정리가 필요
