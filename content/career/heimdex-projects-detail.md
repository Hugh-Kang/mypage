## (1) LG헬로비전 — AI 블러·검수 UX 설계

**기간**: 2026.04–07 · **역할**: 디자이너 1인(본인) · **협업**: PM(공동대표), 개발 리더(공동대표), 백엔드 1, AI 3 / 고객사 담당자

**요약**: 방송 편성심의 담당자가 영상 방영 전 PPL·브랜드 로고, 선정성·폭력성, 개인정보 노출, 블랙 프레임·미디어 노이즈 같은 편집 사고를 확인·처리하는 과정을 돕는 AI 블러·검수 기능을 처음부터 설계.

**문제**
- 90분 마스터 영상 한 편 검수에 약 1.5시간, 블러·후처리에 다시 약 1.5시간 — 총 3시간 이상 소요, PPL 집중 검수는 3~4일
- 선정성/폭력성/개인정보/브랜드로고 등 여러 탐지 유형이 한 화면에 섞여 구분 어려움, 블러 대상과 기술적 결함(블랙프레임·노이즈)도 미구분
- AI 오판정을 사용자가 직접 확인·수정할 방법 없음
- 민감도·로고 최소크기 등 처리 기준을 결과 확인 후에만 변경 가능해 재처리 필요
- 검수·블러 후에도 실제 후반 편집 툴(Premiere)로 재작업해야 해 검수·편집이 이중화

**역할**
- 고객사 미팅 기반 문제·요구사항 정리, 전체 유저플로우(설정→AI처리→검수→내보내기) 설계
- 태그 기반 타임라인·장면 리스트 UI, AI 기준 사전설정+실시간 Preview UI, Premiere 내보내기 UX Writing 설계, 고객사 시안 공유 및 개발팀 전달

**구현**
- 8가지 탐지 유형을 색상 태그+필터로 구분, 블랙프레임·노이즈는 블러 대상과 시각적으로 분리
- 장면마다 8개 태그 버튼을 두어 사용자가 잘못된 판정을 직접 켜고 끌 수 있게 함(초기 "더보기" 메뉴 방식에서 변경)
- 처리 순서를 사후설정 → 사전설정(영상선택→블러처리→기준설정→AI처리→결과검수)으로 재설계, 로고 최소크기는 슬라이더+실시간 Preview로 체감 가능하게 구현
- 내보내기 방식을 "선택 장면 포함"에서 "제외"로 전환(고객 실제 작업 방식 반영), 확인 문구도 실제 처리 결과 기준으로 수정
- 블랙프레임·노이즈 구간은 Premiere로 넘어가면 마커로 자동 표시되도록 구현

**결과(사실)**: 위 설계(태그 타임라인·사전설정·실시간 Preview·내보내기 방식 변경·마커 표시)를 개발팀에 전달해 제품에 배포. 배포 이후 검수 시간 변화·고객 반응은 별도 측정하지 않음(원본 명시).

**제안 성과 문구(사실 기반, 확인 필요)**
- "고객 인터뷰로 확인된 3시간 이상 소요·최대 3~4일 걸리는 PPL 검수 병목(다중 탐지결과 혼재, 사후설정 재처리 구조)을 제거하는 방향으로 설계"
- "8개 탐지 유형에 대한 태그 체계, AI 처리 사전설정 흐름, Premiere 연동 방식(마커 자동표시 포함)을 확정해 개발 착수"
- (본인 확인 필요) "설계안을 일정 내 전달해 개발 착수" — 실제 일정 준수 여부를 알려주시면 이 문구를 추가할 수 있습니다.

## (2) LiveNow — AI 영상 검색·편집 제품 설계

**기간**: 2026.04–06 · **역할**: 디자이너 1인(본인) · **협업**: 대표(PM), 개발 리더, 백엔드 1, AI 3 / 고객사 담당자 3

**요약**: 라이브커머스·홈쇼핑 고객사 LiveNow 요청에 맞춰 방송 영상에서 장면·출연자·상품 구간을 검색하고 숏폼으로 재가공하는 제품을 설계. 기능 추가로 복잡해진 흐름을 재점검·정리.

**문제**
- 기능이 AI 구간분할·AI 쇼츠생성·선택장면편집·블러처리 4개로 늘며 배치 혼선
- 쇼츠 제작 화면과 타임라인 편집 화면이 모두 컷 편집을 제공해 같은 작업이 두 화면에 중복
- 삭제가 아닌 "제외" 기능에 '휴지통'이라는 이름을 붙여 기능과 명칭이 어긋남
- 고객은 컷 편집보다 AI 자막 오타 수정을 주로 했지만 이를 빠르게 처리할 환경이 부족

**역할**
- 화면 설계 및 최종 디자인 결정, AI 기능 추가에 따른 영상 상세 화면 기능 배치 설계
- 쇼츠 제작·AI 쇼츠 생성 옵션 흐름 설계, 고객 인터뷰 참관·질문, 자막 편집 기능 설계, 에딧 패널 디자인, 개발팀 전달용 설계안·스펙 작성

**구현**
- "영상만 고르면 바로 쓰는 기능인가, 장면을 고른 뒤 쓰는 기능인가" 기준으로 헤더/탭 배치를 재설계(헤더 전체 배치안·탭 위계안 등 복수 시도 후 확정)
- 중복되던 쇼츠 제작 중간 화면을 제거해 **영상 선택→편집 화면 수를 3개에서 2개로 축소**
- AI 쇼츠 생성 흐름(유형 선택→구간/쇼츠길이/개수 설정→상품 선택→생성) 설계
- '휴지통' → '제외된 영상'으로 명칭을 바꾸고 위치도 인물 라벨 관리 화면 내부로 이동
- 고객 인터뷰에서 확인한 요구(오타 수정 우선, 컷 편집 최소화)를 반영해 문장·장면 단위 자막 구조화, 클릭 재생, 임시저장·되돌리기, 자막 분할 기능 설계

**결과(사실)**: 위 기능을 개발팀에 전달해 제품에 배포. **화면 수 3→2개 축소**는 확인 가능한 수치. 명칭 오류·중복 편집 단계는 재점검 과정에서 직접 발견해 수정. 별도의 정량적 사용성 검증·개선 효과 측정은 진행하지 않음(원본 명시).

**제안 성과 문구**
- "영상 선택 후 편집까지 거치는 화면 수를 3개에서 2개로 줄여 조작 단계를 단순화"
- "기능 추가 후 재점검 과정에서 명칭·정보구조 오류(휴지통 등)를 스스로 발견해 출시 전 수정"

## (3) B2C AI 브이로그 생성 제품 설계

**기간**: 명시 없음(LiveNow와 유사 시기로 추정 — 본인 확인 필요) · **역할**: 디자이너 1인(본인)

**요약**: 개인 크리에이터가 업로드한 여러 영상 클립을 AI가 분석해 하이라이트를 제안하고, 사용자가 확인·수정해 브이로그를 완성하는 신규 B2C 웹 제품의 초기 화면·사용자 흐름을 설계. 초기 "쇼츠 자동 생성"에서 "16:9 브이로그용 러프컷 생성"으로 제품 방향이 전환됨.

**문제**: 초기 제품 전략·PRD는 대표와 팀이 정의했지만, 화면으로 구체화하는 과정에서 7가지 미정의 사항 발생 — AI 추천/제외 장면 확인·수정 방식, 장면 판단에 필요한 정보량, Auto/Guided 분리 여부, 하이라이트 검수 위치(별도 화면 vs Editor 내부), 영상 길이 설정 시점, 예외 상황(업로드·분석 실패, 메타데이터 손실) 처리, 전체 화면 연결 방식.

**역할**
- 초기 PRD·User Flow 기반 주요 화면 최초 설계, 전체 화면 구성(가입→업로드→AI분석→장면확인→Editor→결과생성)
- 화면 인벤토리·정상/예외 상태 정리, AI 하이라이트 검수 화면·인터랙션 설계, 카드 정보구조 비교, 자막 수정 Editor·Progress UI 설계, 부가 Flow 설계, 회의를 통한 미정의 사항 공유·반영

**구현**
- AI 추천 장면(하이라이트)과 제외 장면을 함께 확인하고 양방향 Drag로 이동 가능하도록 설계, Auto/Guided를 별도 화면으로 분리하지 않고 한 화면에서 확정·수정 가능하게 정리
- **카드 크기 실측 비교**: 콘텐츠 영역 1101px 기준 120px→8개, 160px→6개, 180px→5개 노출 가능 → **160px+2줄 텍스트**로 확정(수치 기반 UI 의사결정)
- 하이라이트(최대 약 60개)와 제외 장면(최대 수백 개)의 정보량을 차등 설계(하이라이트는 썸네일+요약, 제외는 점수순 정렬+검색)
- 장면판단(썸네일+AI요약)/전체흐름확인(Player+자막동기화)/세부수정(Editor)으로 화면 역할 분리
- 별도였던 하이라이트 검수 화면을 Editor 내부로 통합, 오픈소스 편집기 OpenCut 기반 활용 결정에 맞춰 UI 조정(색상 Token 매핑 등)
- 업로드 실패, 분석 실패, 메타데이터 손실 등 예외 상태 및 회원가입·온보딩·결제 등 부가 Flow 설계

**결과(사실)**: 신규 B2C 제품의 주요 화면·전체 사용자 흐름 구체화, 제품 구조 변경(하이라이트 검수→Editor 통합) 등 완료. **출시 전 단계**라 사용자 지표·전환율·편집시간 단축 등 정량 성과는 측정하지 않음(원본 명시).

**제안 성과 문구**
- "카드 크기 3안(120/160/180px)을 실측 비교해 정보 노출량과 판단 용이성의 최적점(160px)을 수치로 도출"
- "정상 흐름뿐 아니라 7가지 예외 상황까지 포함한 전체 화면·상태를 설계해 개발 착수 기반 마련"

## 지원 페이지 프로젝트 항목용 — Heimdex 업데이트 (413자)

`lg-cns-project-entries.md`의 1번 항목을 아래로 교체 제안합니다. 기존 항목은 "3개 제품을 기획해 납품"이라는 요약뿐이었는데, 이제 가장 구체적인 문제(90분 영상 검수 3시간+)와 확인 가능한 수치(화면 수 3→2개)를 넣어 훨씬 설득력이 높아졌습니다.

[Heimdex · 2026.01–04 · 프리랜서 AI·UX 컨설턴트]
웹클라우드 기반 영상 자연어검색 서비스 기업 Heimdex에서 프리랜서로 AI·UX 컨설팅을 수행하며, 3개 B2B/B2C 제품의 화면·흐름 설계를 리드했습니다. LG헬로비전 대상 AI 블러·검수 제품에서는 90분 영상 한 편을 검수하는 데 3시간 넘게 걸리고 PPL 집중검수는 3~4일이 걸린다는 고객 인터뷰를 바탕으로, 8개 탐지유형을 태그·필터로 구분하고 AI 처리 기준을 사후설정에서 사전설정으로 전환하며 실시간 Preview를 추가했습니다. 라이브커머스 고객사 LiveNow의 영상 검색·편집 제품에서는 편집 화면을 3개에서 2개로 줄이고, 기능 명칭·위계 오류를 재점검해 직접 수정했습니다. 세 제품 모두 설계안을 개발팀에 전달해 제품에 반영·배포했습니다.

## 본인 확인이 필요한 사항

1. **일정 준수 여부**: LG헬로비전 프로젝트의 설계안을 정해진 기한 내에 제출했는지 — 맞다면 "제안 성과 문구"에 추가하겠습니다.
2. **B2C 브이로그 프로젝트 기간**: 원본에 기간이 명시되지 않아 LiveNow와 겹치는지, 별도 기간인지 확인 부탁드립니다.
3. **3개 제품 중 지원 페이지에 1개만 쓸지, 슬롯 여유가 있다면 LiveNow나 B2C 브이로그도 별도 항목으로 추가할지** 결정해 주세요(현재 프로젝트 항목은 6개 슬롯 중 6개를 이미 채운 상태입니다 — 추가하려면 기존 항목 중 하나를 대체해야 합니다).
