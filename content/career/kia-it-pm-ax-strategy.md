## 2. 직무를 AI 과제 라이프사이클로 다시 보기

```
[발굴] → [타당성·심사] → [솔루션 매칭·소싱] → [PoC] → [Pilot] → [본사업 전환] → [KPI 평가·Post-Mortem]
 Pain Point   실현성 × ROI     LLM/Vision/예측      기술 검증  현장 검증   Go / No-Go       정량·정성 효과, 교훈 환류
 요구 분석     Go/No-Go         내/외부 벤더 선정
```

| 단계 | 면접관이 확인하려는 것 | 답안에서 보여줄 증거 |
|---|---|---|
| 발굴 | 현업 말에서 **진짜 문제**를 찾아내는가 | 요구·VOC를 모아 과제로 정의한 경험 |
| 심사 | **안 할 과제를 거를 수 있는가** | 우선순위를 정하거나 반려한 사례와 판단 기준 |
| 솔루션 매칭·소싱 | 문제에 맞는 **기술·파트너를 고를 수 있는가** | 외부 파트너(카카오모빌리티 등)·벤더 선정·협업 경험 |
| PoC / Pilot | **작게 검증하고 단계적으로 키우는가** | 소규모 실험 → 확대 적용한 경험(프로모션, 단계 배포) |
| 본사업 전환 | **데이터로 Go/No-Go를 판단**하는가 | 실험 결과를 보고 확대·중단을 결정한 사례 |
| KPI·Post-Mortem | 효과를 **숫자로 증명**하고 **교훈을 남기는가** | 전후 지표, ROI 계산, 회고 문서 |

> 핵심 포인트: 대부분의 지원자는 "AI 과제를 잘 추진하겠다"고 씁니다. **"안 될 과제를 초기에 거르고, PoC 결과로 본사업 여부를 판정한다"**는 심사자 관점을 보여 주면 컨트롤 타워 역할과 가장 잘 맞아 차별화됩니다.

## 4. 자기소개서 1번 문항 해부

> **지원하신 직무에 본인이 적합하다고 판단하신 이유를 본인의 경험과 Skill Set, 또는 장점과 연계하여 서술해 주십시오.**

### 4-1. 출제 의도
- "왜 기아인가"가 아니라 **"왜 당신이 이 직무에 맞는가"**를 묻습니다. 지원동기보다 **직무 적합성 증명**이 중심입니다.
- 이 공고의 자소서 항목은 **이 문항 하나**입니다. 즉 이 문항이 **필수 자격 Q3~Q6을 증명하는 유일한 서술 공간**입니다.
- "경험 + Skill Set + 장점"을 **연계**하라는 요구는 나열이 아니라 "이 경험 → 이 역량 → 이 업무에 이렇게 쓰임"이라는 연결 고리를 보겠다는 뜻입니다.

### 4-2. 평가 기준 (예상)
1. **필수 자격 커버리지**: Q3(AI/DT), Q4(WBS·리소스), Q5(Pain Point·ROI), Q6(기술↔현업 조율)이 모두 보이는가
2. **직무 이해도**: 이 자리가 개발이 아니라 심사·소싱·PMO·평가라는 점을 아는가
3. **증거의 구체성**: 역할, 규모, 기간, 수치, 본인 기여분이 있는가
4. **이전 가능성**: EV 충전·결제 경험이 제조 AX 과제에도 통한다는 논리가 있는가

### 4-3. 자주 하는 실수
- AI 기술 스택만 나열 → 개발자 지원서처럼 읽힘
- "소통을 잘한다" 같은 근거 없는 장점
- 시간순 서술 → 결론이 뒤에 묻힘 (두괄식으로)
- 결과 수치가 없거나 ROI를 "효과가 컸다"로 뭉뚱그림
- PoC/Pilot/본사업 전환, KPI, Post-Mortem 같은 **공고 언어를 하나도 안 씀**
