# "티빙 챗봇을 만든다면, 기존 추천 알고리즘과는 어떻게 결합할 것인가" — 구조화 답변

## 0. 설계 프롬프트

> 너는 "티빙에 이미 존재할 추천 알고리즘 자산을 챗봇 도입 시 어떻게 활용할 것인가"라는 질문에 답하는 지원자다. 챗봇을 기존 추천과 무관한 새 시스템으로 제안하지 말고, 기존 랭킹 기반 추천 자산을 재사용하면서 챗봇이라는 새 인터페이스를 결합하는 현실적 설계를 8단계로 구조화하라. 이건 실행한 프로젝트가 아니라 제안이므로, "결과"는 실측 성과가 아니라 기대 효과로 정직하게 표현하라.

## 1. 개요

티빙 Discovery팀에 합류한다면, 기존에 이미 운영 중일 랭킹 기반 추천 알고리즘을 대체하지 않고, 그 위에 챗봇이라는 대화형 인터페이스를 결합하는 하이브리드 구조를 제안하고 싶습니다.

## 2. 문제정의

기존 추천 알고리즘은 과거 시청 이력·협업 필터링 같은 축적된 데이터를 기반으로 콘텐츠를 랭킹해서 보여주는 방식인데, "오늘 기분", "지금 이런 걸 보고 싶다"처럼 그때그때 달라지는 실시간 맥락은 반영하지 못합니다. 그렇다고 챗봇을 기존 추천과 완전히 별개로 새로 만들면, 이미 검증된 개인화 자산(수년간 쌓인 시청 데이터, 튜닝된 랭킹 로직)을 처음부터 다시 쌓아야 하는 비효율이 생깁니다. 즉 핵심 문제는 "기존 추천 자산을 버리지 않으면서, 챗봇 특유의 실시간 대화 맥락을 어떻게 결합할 것인가"입니다.

## 3. 목적

사용자가 자연어로 대화하듯 원하는 콘텐츠를 찾을 수 있게 하면서도, 기존 추천 알고리즘이 이미 확보한 개인화 신호를 재사용해 처음부터 다시 학습시키는 비효율을 피하는 것이 목적입니다.

## 4. 활용할 데이터

| 데이터 유형 | 내용 | 활용 목적 |
|---|---|---|
| 기존 추천 알고리즘의 랭킹 결과 | 이미 검증된 사용자별 개인화 후보 리스트 | 챗봇의 1차 후보군으로 그대로 재사용(콜드스타트 회피) |
| 콘텐츠 메타데이터(온톨로지성) | 장르, 출연진, 시리즈 연결 관계 | "이 배우가 나온 다른 작품" 같은 명확한 관계 질문 보완 |
| 콘텐츠 줄거리·리뷰 임베딩(벡터DB) | 분위기·톤 기반 유사도 | 챗봇의 실시간 대화 맥락과 유사도 매칭 |
| 사용자의 실시간 대화 인풋 | 대화 중 남긴 기분·상황 표현 | 그 자리에서 벡터화해서 기존 랭킹 결과를 재정렬(re-ranking)하는 데 사용 |
| 사용자 프로필·구독 등급(일반DB) | 자격 조건 | 최종 후보 필터링 |

## 5. 분석 내용 (설계 절차)

사용자 질의가 들어오면 먼저 의도를 분류합니다(추천 요청 vs 정보성 문의). 추천 요청이면, **처음부터 새로 추천을 계산하지 않고 기존 랭킹 알고리즘이 이미 만들어둔 그 사용자의 개인화 후보 리스트를 1차로 가져옵니다.** 그 위에 사용자가 대화로 남긴 실시간 맥락(예: "우울한데 가볍게 볼 거 없나")을 벡터화해서, 기존 후보 리스트를 그 맥락에 맞게 재정렬(re-ranking)합니다. "이 배우가 나온 다른 작품" 같은 명확한 관계 질문이 섞이면 온톨로지로 후보를 보완합니다. 최종적으로 좁혀진 후보를 LLM에 프롬프트로 전달해 자연어 답변을 생성합니다.

## 6. 통찰

챗봇을 "기존 추천을 대체하는 새로운 시스템"이 아니라 **"기존 추천 결과에 실시간 대화 맥락이라는 신호를 하나 더 얹어서 재정렬하는 레이어"**로 설계하면, 기존에 검증된 자산을 버리지 않으면서도 챗봇 특유의 유연함을 더할 수 있다는 것이 핵심 통찰입니다. 이렇게 하면 신규 사용자(콜드스타트)라도 기존 알고리즘의 인기 콘텐츠 랭킹을 기본값으로 활용할 수 있어, 챗봇이 아예 추천할 게 없는 상황도 방지할 수 있습니다.

## 7. 기대 효과 (아직 실행하지 않은 제안이므로 "결과"가 아닌 "기대 효과"로 표현)

- 실시간 대화 맥락이 반영되어 추천 정확도(CTR·CVR) 개선 기대
- 기존 랭킹 인프라를 재사용하므로 챗봇 도입에 필요한 개발 리소스·학습 데이터 요구량 절감
- 신규 사용자도 기존 랭킹의 기본값을 활용할 수 있어 콜드스타트 문제 완화

## 8. 의의

"완전히 새로운 AI 시스템을 처음부터 만든다"가 아니라, **이미 검증된 자산 위에 새로운 인터페이스를 결합하는 점진적 설계**라는 점에서 현실적입니다. 이는 화려한 신규 기술 도입보다, 기존 자산을 존중하면서 리스크를 통제하는 PM의 실무적 판단을 보여줄 수 있는 답변이라고 생각합니다.
