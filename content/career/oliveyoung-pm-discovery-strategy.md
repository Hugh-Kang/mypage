- 서비스 상세 설계 기획 및 운영 역량
- 프로젝트 관리 역량
- 지라, 컨플루언스 툴 활용 역량

**우대 요건 (동점자 사이 차별화)**

- 라이브, 웰니스 서비스 경험
- 데이터 분석, Figma 툴 활용 경험

**주요업무 성격**: 발견탭 / 라이브·셔터·매거진·리뷰 / 어필리에이트·쇼핑 큐레이터 — 즉 **컨텐츠 커머스 + 크리에이터 이코노미 + 데이터 기반 큐레이션**이 핵심 축. "20년 이상 축적된 경험과 데이터", "온·오프 경계를 허무는 End-to-End 플랫폼" 문구에서 **데이터 기반 의사결정**과 **오프라인 자산과의 연계**가 팀 문화 시그널로 읽힘.

## 4. 전형 단계별 대응 전략

### ① 서류 전형
- 이력서 최상단 3줄: PM 경력 4년 · 데이터 기반 추천/큐레이션 설계 임팩트(CTR +7%p, VoC -47%) · Agile 기반 프로젝트 관리
- 자기소개서 핵심 관점: "데이터로 추천 우선순위를 재설계해 CTR과 VoC를 동시에 개선한 경험"을 발견탭·큐레이터 서비스의 "노출 로직 설계"와 직접 연결
- 포트폴리오 3사례: 추천/큐레이션 설계형(충전구역 추천) · 콘텐츠 기반 추천형(건강디저트, 챗봇 대화주제) · 효율화형(대시보드, 언어패키지)

### ② 1차 면접 (직무 인터뷰로 예상)
예상 질문:
- Jira/Confluence 없이 어떻게 프로젝트를 관리했나? (→ 갭 방어 필요, 3번 질문 참조)
- 발견탭/어필리에이트처럼 다뤄본 적 없는 도메인을 어떻게 3개월 안에 캐치업할 것인가?
- 충전구역 추천 로직 개선에서 본인이 최종 의사결정한 지점은 정확히 어디인가? (기여도 80%의 실체)
- 정량 데이터와 정성 피드백(VoC)이 상충할 때 어떻게 우선순위를 정했는가?

### ③ 온라인 인성검사
- 특이사항 없음. 이직 주기가 짧은 편(오비이랩 2.4년 → 마인드로직 1.2년 → 볼트업 6개월)이므로, 인성검사 이후 면접에서 "왜 짧은 주기로 이직했는가"에 대한 논리적 답변 준비 필요 (전문연구요원 병역 특성 등 사실 기반으로 정리)

### ④ 2차 면접 (컬처핏 성격 포함 가능)
- "먼저 나서서 직무를 확장한 사례"(언어패키지 자체 구축, 빵그리의 오븐에서 기획자였지만 추천모델 설계까지 참여) 준비
- "실패를 인정하고 회고에서 방향을 바꾼 사례" — 챗봇 프로젝트 회고("사용자는 본인이 원하는 기능을 명확히 모른다") 활용

### ⑤ 3차 전형 (평판조회·처우협의)
- 오비이랩·마인드로직 레퍼런스 대상자에게 "데이터 기반 의사결정", "직무 확장" 강조 포인트 사전 공유
- 희망 연봉 시장 밴드 조사, 현재 연봉 근거자료 정리

## 5. STAR 스토리 3슬롯

1. **추천/큐레이션 로직 재설계형** — S: 즐겨찾기 등록자 CTR이 5배 높다는 세그먼트 분석, T: 홈 화면 노출 우선순위 재설계, A: 조건 재배치 및 배포, R: CTR 18.2%→25.2%(+7%p), VoC 월평균 47% 감소
2. **콘텐츠 기반 추천 설계형** — S: 콜드스타트(사용자 데이터 부재), T: 상품 접근성 개선, A: 크롤링 데이터로 콘텐츠 기반 추천모델 설계·세그먼트 4종 구분, R: MAU 1,300명, 재방문 의사 7.0점
3. **직무 확장/효율화형** — S: 언어별 문구 수정마다 개발 공수 소요, T: 비개발자도 수정 가능한 협업 환경, A: 구글시트+API 연동 언어패키지 자체 설계, R: 추가 개발 공수 없이 자동 배포되는 협업 구조 구축

## 6. 실전 사례 매핑 — 발견(Discovery) JD와의 연결

| JD 업무 | 매핑할 실제 경험 | 연결 논리 |
|---|---|---|
| 발견탭 서비스 기획/운영 | 볼트업 홈화면 추천 충전구역 고도화 | "행동 데이터 기반 노출 우선순위 재설계"는 발견탭의 컨텐츠 노출 로직 설계와 동일한 문제 구조 |
| 어필리에이트/쇼핑 큐레이터 | 빵그리의 오븐 유사상품 추천(찜 기반), 세그먼트별 홈 추천 | "사용자 행동 신호 → 추천 → 전환"이라는 어필리에이트의 핵심 루프와 개념적으로 연결되나, 정산/트래픽 구조는 별도 학습 필요(6장 참조) |
| 라이브/매거진/리뷰 | 마인드로직 챗봇 실시간 대화 설계, 채팅 로그 기반 콘텐츠 주제 선정 | 실시간 상호작용에서 "사용자가 원하는 것"을 데이터로 역추적한 방법론은 매거진/리뷰의 콘텐츠 기획에도 적용 가능 |
| 정량/정성 데이터 분석 | 전 프로젝트 공통 (AB test, GA 퍼널, 세그먼트 군집화) | 가장 강력한 매칭 지점 — 발견탭 JD의 "인사이트 도출" 요건과 이력서 전체가 정합 |

## 7. 비판적 질문 3가지 (보완 필요 항목에 대한 방어 논리 준비)

1. **Jira/Confluence 공백** — 이력서·포트폴리오 어디에도 Jira/Confluence 사용 이력이 없다. "Agile과 Scrum 기반으로 개발 관리"라고만 쓰여 있는데, 실제로는 어떤 툴로 스프린트를 운영했는가? 면접관이 "지라로 백로그를 어떻게 우선순위화했나"라고 구체적으로 물으면, 2주 학습만으로 실전처럼 답할 수 있는가, 아니면 "학습했다"는 답변에 머물러 신뢰도가 깎일 위험이 있는가?

2. **어필리에이트/SNS 도메인 공백을 유사 경험으로 메우는 논리의 설득력** — 빵그리의 오븐 추천 시스템(콘텐츠 기반 유사상품 추천)을 어필리에이트·쇼핑 큐레이터 경험으로 연결하는 것은, "추천 알고리즘 설계"와 "제휴 트래픽·정산·크리에이터 생태계 운영"이라는 서로 다른 문제를 같은 것처럼 포장하는 것 아닌가? 면접관이 "정산 구조나 어뷰징 방지 정책을 설계해본 적 있느냐"고 파고들면, 유사성 논리가 무너지지 않는가?

3. **잦은 이직 주기와 "3년 이상 유관 경력"의 실질적 깊이** — 오비이랩 2.4년, 마인드로직 1.2년, 볼트업 6개월로 각 재직 기간이 짧고, 특히 볼트업은 입사 6개월 차에 지원하는 셈이다. "3년 이상 경력"은 합산으로 충족하지만, 한 도메인에서 상위 기획(전사 전략 수준)까지 올라가 본 경험이 실제로 있는가? 아니면 각 회사에서 실무 설계·실행 단계에만 머물다 이직을 반복한 패턴으로 보일 위험이 있는가?

이 세 질문에 스스로 명확히 답한 뒤 4장 학습 플랜과 5장 STAR 슬롯을 완성할 것.
