# 계정 공유로 취향이 뒤섞일 때 — 정책 설계 및 추천 전략

> 작성 목적: "한 티빙 계정을 여러 사람이 공유해서 취향이 뒤바뀌는 경우, 어떤 정책을 세우고 콘텐츠를 추천해야 하는가"에 대한 답변을 구조화 — 디스커버리 PM 면접에서 나올 수 있는 추천 설계 심화 질문 대비

## 핵심 요약 (두괄식)

이 문제의 본질은 **"1계정 = 1취향"이라는 추천 시스템의 암묵적 가정이 깨지는 것**입니다. 해법은 한 번에 완성되는 것이 아니라 **① 이미 존재하는 프로필 인프라를 추천 개인화에도 연동하는 구조적 해법, ② 프로필 전환을 하지 않는 상황까지 가정한 암묵적 세션 분리, ③ 한 사람의 취향으로 화면 전체를 획일화하지 않는 UX 설계**를 단계적으로 쌓아가야 한다고 생각합니다. 특히 조사해보니 티빙은 이미 프로필 기능(현재는 시청등급 설정 목적)과 가구 외 공유를 위한 추가 계정(프로필 1개+기기 1대) 체계를 운영 중인데, 이 프로필 구조가 추천 개인화에도 연동되는지는 공식적으로 확인되지 않아 — 이 자체가 제가 입사 후 먼저 확인하고 싶은 지점이라고 답할 수 있습니다.

---

## 1. 문제의 본질 — 추천 시스템의 암묵적 가정이 깨지는 상황

콘텐츠 추천 알고리즘은 보통 "하나의 계정 ID = 하나의 취향 벡터"라고 가정하고 시청 이력을 누적합니다. 그런데 가족·커플 등 여러 명이 한 계정(또는 한 프로필)을 공유하면, 서로 다른 취향이 하나의 시청 이력에 섞이면서 ① 추천이 누구에게도 맞지 않는 평균적·무난한 콘텐츠로 수렴하거나, ② 가장 최근에 많이 본 사람의 취향 쪽으로 쏠려 다른 구성원에게는 전혀 안 맞는 추천이 나오는 두 가지 실패 양상이 나타납니다.

## 2. 티빙의 현재 상황 (조사 결과)

- 티빙은 **프로필 기능**을 운영 중이나, 현재 공식적으로 확인되는 용도는 **"프로필 시청 등급"**(전체/7세/12세/15세/19세 이상 5단계) 설정을 통한 자녀 보호 목적입니다.
- **계정 공유 정책**: 가입자 본인과 동일 가구 구성원에게만 계정 공유를 허용하며, 함께 거주하지 않는 가족·지인과 공유하려면 **추가 계정**(동시 시청 1대 + 프로필 1개 제공)을 별도로 운영해야 합니다.
- **개인화 추천이 프로필 단위로 분리되는지는 공식적으로 확인되지 않았습니다.** 즉 프로필 인프라 자체는 있지만, 그것이 추천 개인화와 연동돼 있는지는 불분명합니다 — 이 점은 실제 면접에서 "프로필 기반 추천이 이미 되고 있나요?"를 역으로 여쭤보거나, 입사 후 가장 먼저 확인하고 싶은 지점으로 답변에 활용할 수 있습니다.

## 3. 단계적 해법 프레임워크

| 단계 | 해법 | 핵심 내용 | 한계·보완 필요 |
|---|---|---|---|
| 1단계 (구조적) | 프로필별 추천 완전 분리 | 이미 존재하는 프로필 인프라에 "프로필 ID 단위로 시청 이력·추천을 분리"하는 로직을 연동. 가장 근본적인 해법 | 프로필 전환을 사용자가 직접 해야 하는데, 넷플릭스 사례에서도 보듯 매번 전환하는 사용자는 일부에 불과함 — **프로필이 있어도 안 쓰면 소용없음** |
| 2단계 (행동 유도) | 프로필 전환 넛지 정책 | 시청 패턴이 급격히 바뀌는 시점(예: 디바이스 전환, 심야↔낮 시간대 전환, 장르가 완전히 달라지는 시점)을 감지해 "지금 보시는 분이 맞으신가요?"라는 가벼운 확인 UI를 노출 | 지나치게 자주 뜨면 UX 피로도가 올라가므로, 노출 빈도·조건을 신중하게 설계해야 함(예: 하루 1회 이하) |
| 3단계 (암묵적 분리) | 세션 기반 암묵적 세그먼트 추정 | 프로필 전환을 안 하는 경우를 가정해, 디바이스 ID·시청 시간대·연속 시청 장르 패턴을 피처로 사용해 "같은 로그인이지만 다른 암묵적 세그먼트"를 추정하고, 추천 시 전체 누적 이력보다 **최근 세션(예: 최근 30분~1시간)에 가중치**를 둠 | 완벽한 분리는 불가능하므로 보조 수단으로만 사용, 1·2단계의 보완재 성격 |
| 4단계 (UX 설계) | 홈 화면 캐러셀 다변화 | 하나의 "당신을 위한 추천" 섹션으로 화면 전체를 획일화하지 않고, "최근 시청 기반", "가족 모두가 좋아하는 인기작", "지금 이 시간대 인기 콘텐츠"처럼 **여러 취향을 동시에 수용하는 복수 캐러셀 구조**로 설계 | 복수 캐러셀이 너무 많아지면 오히려 선택 피로를 유발할 수 있어, 2~3개로 제한하는 것이 적절 |

## 4. 정책 설계 시 우선순위 — MVP 관점

리소스가 제한적이라면, 저는 **4단계(캐러셀 다변화) → 3단계(세션 가중치 조정) → 2단계(넛지) → 1단계(프로필-추천 완전 연동)** 순으로 접근하겠습니다. 이유는 4단계와 3단계는 **기존 추천 엔진이나 UI 구조를 크게 바꾸지 않고도** 적용 가능한 반면, 1단계(프로필-추천 완전 연동)는 데이터 파이프라인 자체를 프로필 단위로 재설계해야 해 개발 공수가 훨씬 크기 때문입니다 — 이는 앞서 정리한 쿠폰 어뷰징 사례(`tving-interview-developer-collaboration-coupon-abuse-answer.md`)와 동일하게, **구조적 재설계보다 정책·UX 조정으로 먼저 문제의 체감 크기를 줄이고, 효과가 검증되면 구조적 해법에 투자하는** 접근입니다.

## 5. 효과 검증 방법

- **A/B 테스트**: 캐러셀 다변화 적용군 vs 기존 단일 추천 유지군으로 나눠, 클릭률·재생전환율·재생완료율을 비교
- **코호트 분석**: 가구 내 다수 프로필을 사용하는 계정과 단일 프로필만 사용하는 계정을 나눠, 추천 적중률(클릭 후 완주 비율)의 차이를 추적 — 차이가 크다면 "취향 혼합 문제"가 실제로 유의미한 크기임을 보여주는 근거가 됨

## 6. 예상 꼬리질문

| 꼬리질문 | 대응 방향 |
|---|---|
| 프로필 전환을 그냥 강제하면 되지 않나요? | 매번 프로필을 선택하게 강제하면 로그인 단계가 늘어나 이탈률이 올라갈 위험이 있어, 강제보다는 특정 조건에서만 가볍게 묻는 넛지 방식이 UX 비용 대비 효과적이라고 판단 |
| 세션 기반 암묵적 분리가 틀릴 수도 있지 않나요? | 맞습니다. 완벽한 분리는 불가능하다고 보고, 그래서 "틀려도 피해가 작은" 설계(캐러셀 다변화로 여러 취향을 동시에 노출)를 함께 두어 암묵적 추정이 틀렸을 때의 리스크를 분산 |
| 이 문제가 실제로 비즈니스에 어떤 임팩트가 있나요? | 추천이 안 맞으면 콘텐츠 발견 실패로 이어져 시청 세션이 짧아지고, 이는 결국 구독 가치 체감 저하와 이탈로 연결되므로, 추천 적중률 개선은 궁극적으로 구독 유지율과 직결된다고 설명 |
