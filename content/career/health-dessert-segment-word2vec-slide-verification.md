## 0. 설계 프롬프트

> 너는 포트폴리오 슬라이드 원문과 이전 모의면접 답변을 대조 검증하는 코치다. 슬라이드에 명시된 수치와 절차만 근거로 ① 세그먼트를 나눈 배경과 기준, ② Word2Vec 모델의 입력 데이터와 활용 절차를 다시 정확하게 정리하라. 이전 모의면접 답변에서 "10초 설문으로 나눴다"거나 "고도화 과정"이라고 뭉뚱그린 부분이 슬라이드 원문과 정확히 일치하는지 검증하고, 다르면 슬라이드 기준으로 바로잡아라. 슬라이드만으로는 알 수 없는 부분(정확한 알고리즘명, 서로 다른 슬라이드에 등장하는 표본 수의 관계, 정성평가 방식 등)은 추측하지 말고 사용자에게 구체적으로 되물어라.

## 1. 세그먼트 — 배경·기준 재정리

### 1-1. 슬라이드 원문 기준 정확한 절차

1. **문제 인식**: "사용자가 선택한 방문 목적과 실제 선호하는 아이템은 다를 수 있음" — 즉 사용자가 스스로 답한 방문 목적(다이어트, 근성장 등) 하나만으로는 실제 선호를 완전히 설명하지 못한다는 문제의식에서 출발
2. **군집화 기준 데이터**: 방문 목적뿐 아니라 **성별, 나이, 기피 재료, 알러지**까지 함께 고려한 사용자 특성 데이터를 군집화(clustering)에 사용
3. **군집 수 결정**: **Elbow Method**(WCSS가 완만해지는 지점을 찾는 방법)를 통해 **4개 세그먼트**로 나누는 것이 최적이라고 판단
4. **결과 세그먼트 4종**:
   - 근성장 or 다이어트 (42.9%) — 방문 목적이 근성장 또는 다이어트인 집단
   - 유당 불내증 (28.0%) — 기피 재료가 우유이거나 유당불내증이 있는 집단
   - 근성장/다이어트 ∩ 유당불내증 (18.6%) — 위 두 집단의 교집합
   - 기타 사용자 (10.6%) — 위 세 집단에 속하지 않는 집단

### 1-2. 이전 답변과 달라지는 점

이전 모의면접 답변(및 `mock-interview-kimchanyoung-analysis-and-improved-answers.md` 3-4절)에서는 "10초 미만의 설문으로 4개 세그먼트를 나눴다"는 식으로 **설문 자체가 세그먼트를 직접 정했다**는 뉘앙스로 설명했습니다. 슬라이드 원문에 따르면 정확히는:

- 설문으로 **원자료(raw data)**(방문 목적, 성별, 나이, 기피 재료, 알러지)를 수집한 것이고
- 그 원자료를 바탕으로 **Elbow Method 기반 군집화 알고리즘**을 돌려서 **4개라는 세그먼트 개수 자체를 데이터 기반으로 도출**한 것입니다

즉 "설문으로 나눴다"보다는 **"설문으로 수집한 사용자 특성 데이터에 군집화 알고리즘을 적용해서, 몇 개로 나누는 게 최적인지까지 데이터 기반으로 결정했다"**는 게 더 정확하고, 훨씬 더 설득력 있는 표현입니다. 이 부분이 김찬영 면접관이 지적했던 "왜 4개로 나눴는지의 논리"에 대한 정확한 답이기도 합니다.

### 1-3. 확인된 사실 (사용자 답변 반영, 2026-09-29)

| 질문 | 확인된 답변 |
|---|---|
| 성별·나이·방문목적으로 나눠본 결과 | **성별·나이는 큰 차이가 나타나지 않음** |
| 어떤 축이 실제로 유의미했는가 | **유당불내증 여부**가 집단 규모 자체가 크고, "유당불내증만 있는 집단" / "방문목적이 다이어트·근성장인 집단" / "이 둘의 교집합" 사이에서 **선호 상품 범위 차이가 가장 크게** 나타남 |
| 세그먼트 개수(4개) 선정 근거 | Elbow Method에서 **WCSS(군집 내 분산)가 급격히 꺾이는 지점**이 4개 구간이었고, 그 이상 나눠도 선호 차이가 크게 벌어지지 않아 4개로 확정 |
| 160명 / 113명의 관계 | **160명**은 기본 회원(전체 가입자) 수, **113명**은 그중 실제로 서비스에 가입해서 선호도에 맞게 "찜"을 1회 이상 설정한 사용자 수 |

**정리하면**: 처음엔 성별·나이·방문목적·기피재료·알러지를 모두 입력해 군집화를 시도했지만, 실제로 선호 상품 차이를 만들어낸 핵심 변수는 **유당불내증(기피재료) 여부와 방문목적**이었고, 성별·나이는 유의미한 차이를 만들지 않았습니다. 그래서 최종 세그먼트 4종(근성장/다이어트, 유당불내증, 교집합, 기타)이 방문목적·기피재료 조합으로만 정의된 것입니다. 이건 단순히 "성별·나이 데이터를 안 썼다"가 아니라, **"여러 변수로 시도해봤는데 실제로 차이를 만드는 변수만 남겼다"는, 오히려 더 설득력 있는 데이터 기반 의사결정 과정**입니다.

### 1-4. 아직 확정되지 않은 사소한 사항 (선택)

19p의 "초기 사용자 132명 설문(재방문 의사 7.0점)"이 160명·113명과 정확히 어떤 관계인지는 이번 답변에서 다루지 않으셨습니다. 필요하시면 나중에 확인해서 반영하겠지만, 면접에서 핵심적으로 캐물을 가능성은 낮은 세부 수치라 우선순위는 낮게 보고 있습니다.

### 1-5. 최종 답변 스크립트

> "처음엔 사용자의 방문 목적뿐 아니라 성별, 나이, 기피 재료, 알러지까지 함께 고려해서 군집화를 시도했습니다. 그런데 실제로 나눠보니 성별과 나이는 선호 상품에 큰 차이를 만들지 않았고, 오히려 유당불내증 같은 기피 재료 여부와 방문 목적(다이어트·근성장)이 선호 상품 범위에 가장 큰 차이를 만드는 변수였습니다. 그래서 이 두 축을 기준으로, Elbow Method로 WCSS가 급격히 꺾이는 지점을 찾아 4개 세그먼트가 최적이라고 판단했습니다 — 그 이상 나눠도 선호 차이가 크게 벌어지지 않았기 때문입니다. 최종적으로 근성장·다이어트 집단, 유당불내증 집단, 이 둘의 교집합, 그리고 기타 집단, 이렇게 4개로 나눠서 각 집단의 찜 순위에 따라 홈 화면 추천을 다르게 구성했습니다."

## 2. Word2Vec 모델 — 활용 데이터·방식 재정리

### 2-1. 슬라이드 원문 기준 정확한 절차

1. **활용 목적**: 사용자가 상품에 "찜"(긍정 반응)을 하면, 그 상품과 유사한 상품 3종류를 바텀시트에 추천
2. **입력 데이터(feature)** — 상품의 두 가지 공통 feature를 모델 입력으로 사용:
   - **자연어 특성**: 상품명, 옵션 제목, 소비자 리뷰 (예: "파운드 쿠키", "한라봉 얼그레이", "한라봉맛, 고소함")
   - **상품 특성**: 가격, 분류, 그리고 고단백/글루텐프리/저당/비건/키토제닉 여부를 0·1로 표기한 이진(binary) 속성
2. **모델 선정 절차**: 상품 특성·리뷰 데이터를 활용해 추천 모델 **후보 2개를 직접 개발해서 비교** — BoW+TF-IDF 모델과 Word2Vec 모델
3. **평가 방법**: 0(유사하지 않음)~2(매우 유사함) 척도의 **내부 정성 평가**로 각 후보를 채점 — BoW+TF-IDF는 0.8점, Word2Vec은 1.2점(2점 만점) — Word2Vec을 최종 채택
4. **입출력 구조**: Input = 사용자가 찜을 선택한 상품명 → Output = 후보군 중 가장 유사한 제품 목록
5. **커버리지 검증**: 전체 211개 상품 중 **82%의 상품이 (한 번이라도) 추천에 등장**하도록 설계 — 일부 인기 상품에만 추천이 몰리지 않게 하기 위한 지표로 별도 확인

### 2-2. 이전 답변과 달라지는 점

이전 모의면접 답변에서는 "세그먼트 안에서 인기순만 보여줬더니 다양성이 떨어지는 문제가 보여서 Word2Vec을 도입했다"는 **문제→재문제→해결** 서사로 설명했습니다. 슬라이드 원문을 보면:

- Word2Vec은 **세그먼트별 홈 화면 추천(찜 순위 기반 정렬)과는 별개의 기능**입니다. 홈 화면 추천은 "세그먼트별 찜 순위 내림차순 정렬"(explicit data 활용, 17p 아님 19p)이고, Word2Vec은 "특정 상품에 찜을 했을 때 뜨는 바텀시트의 유사 상품 3개 추천"(17p)으로, **서로 다른 화면·다른 목적의 기능**입니다.
- 즉 "세그먼트 다양성 문제 때문에 Word2Vec을 도입했다"는 인과관계는 슬라이드상 명확히 확인되지 않고, 오히려 **Word2Vec은 처음부터 콜드스타트 상황에서 콘텐츠 기반 유사 상품 추천을 위해 별도로 설계된 모델**로 보입니다. 82% 커버리지도 "세그먼트 내 다양성" 문제가 아니라 **"찜한 상품과 유사한 상품 추천 시, 일부 인기 상품에만 쏠리지 않게"** 하기 위한 것이었습니다.

**[2026-09-29 확인 완료]** 사용자 확인: 세그먼트 기반 홈 화면 추천과 Word2Vec 기반 유사 상품 추천은 **서로 독립된 기능**이었습니다. 즉 하나의 한계를 보완하기 위해 다른 하나가 나온 것이 아니라, 애초에 서로 다른 화면·다른 목적을 위해 각각 기획된 기능입니다. 따라서 면접에서는 이 둘을 "문제→재문제→해결"이라는 하나의 연속된 서사로 묶어서 설명하면 안 되고, **두 개의 독립적인 기능으로 각각 설명**하는 것이 정확합니다.

### 2-3. 확인된 사실 (사용자 답변 반영)

| 질문 | 확인된 답변 |
|---|---|
| 정성 평가 규모·평가자 | 약 **210건**의 상품에 대한 유사 상품 추천 결과를, **내부 평가자 10인**이 평가 |
| 평가 척도 정의 | 0점 = 유사 상품 추천이 적절하지 않음 / 1점 = 보통 / 2점 = 추천된 상품이 유사함 |
| 자연어 특성 데이터 범위 | 상품 메타데이터 + **해당 상품의 최신 리뷰 100개**를 정리해서 입력으로 사용 |
| 두 기능(세그먼트 추천 vs Word2Vec 유사상품 추천)의 관계 | **독립된 기능** — 인과관계 없음 |

### 2-4. 자연어 특성 + 상품 특성(이진 속성)을 함께 넣는 일반적인 방법 — 구체적 예시 2가지

정확히 어떤 방식으로 결합했는지까지는 기억이 명확하지 않다고 하셨으므로, 실무에서 흔히 쓰이는 두 가지 구체적 방법을 제안합니다. 아래 중 기억과 더 가까운 쪽을 골라주시면 그걸로 답변을 확정하겠습니다.

**방법 A — 벡터 결합(Concatenation) 방식**

1. 상품명 + 옵션 제목 + 최신 리뷰 100개를 하나의 텍스트 뭉치로 합친 뒤, Word2Vec으로 단어 단위 임베딩을 학습
2. 상품별로 그 안에 등장하는 단어 벡터들을 평균 내서(또는 TF-IDF 가중 평균으로) 상품 하나당 "텍스트 임베딩 벡터" 하나를 생성
3. 가격(정규화), 분류(원-핫 인코딩), 고단백/글루텐프리/저당/비건/키토제닉(0·1) 같은 상품 특성을 별도의 "구조화 피처 벡터"로 만듦
4. 이 두 벡터를 옆으로 이어 붙여(concatenate) 상품 하나당 하나의 최종 벡터를 만들고, 벡터 간 코사인 유사도로 유사 상품을 계산
5. **특징**: 구현이 간단하고 직관적. 다만 텍스트 벡터와 구조화 벡터의 스케일이 다르면 한쪽이 유사도 계산을 지배할 수 있어, 보통 정규화(스케일링)를 함께 적용

**방법 B — 1차 필터링 + 2차 랭킹 분리(하이브리드) 방식**

1. 먼저 상품 특성(글루텐프리·저당·비건·키토제닉 여부, 가격대, 분류)을 이용해 사용자가 찜한 상품과 **속성이 겹치는 상품들로 후보군을 1차로 좁히거나, 속성 일치 개수만큼 가중치를 부여**
2. 그 좁혀진 후보군 안에서만, 텍스트(상품명+최신 리뷰) 기반 Word2Vec 임베딩의 코사인 유사도로 최종 순위를 매김
3. 즉 "구조화 데이터는 1차 필터·가중치", "텍스트 데이터는 2차 랭킹 기준"으로 역할을 분리
4. **특징**: 예를 들어 글루텐프리가 필요한 사용자에게 글루텐 함유 상품이 추천되는 실수를 원천 차단할 수 있어 정확도 면에서 유리. 다만 필터링이 너무 엄격하면 후보군 자체가 좁아져 커버리지가 낮아질 위험이 있음

**참고**: 슬라이드에 "82% 커버리지"를 별도로 신경 써서 확인했다는 점을 보면, 후보군을 과도하게 좁히지 않는 **방법 A(벡터 결합)** 쪽이 실제 설계와 더 잘 맞을 가능성이 있습니다. 방법 B처럼 엄격하게 필터링했다면 커버리지가 자연히 낮아지는 경향이 있기 때문입니다. 다만 이건 추정이므로, 실제로 어느 쪽에 더 가까웠는지는 본인의 기억에 따라 판단해주시면 됩니다.

### 2-5. 최종 답변 스크립트 (확인된 사실 반영)

> "상품명, 옵션 제목, 그리고 그 상품의 최신 리뷰 100개를 정리한 자연어 데이터와, 가격·분류·고단백·글루텐프리·저당·비건·키토제닉 여부 같은 상품 특성 데이터를 함께 입력으로 써서 Word2Vec 모델을 학습시켰습니다. 텍스트 데이터는 임베딩 벡터로 변환하고, 상품 특성은 별도의 구조화된 벡터로 만들어 함께 결합하는 방식으로 유사도를 계산했습니다.
>
> 이 모델을 BoW+TF-IDF 방식과 비교하기 위해, 약 210건의 상품에 대한 유사 상품 추천 결과를 내부 평가자 10명이 0점(적절하지 않음)~2점(매우 유사함) 척도로 정성 평가했고, BoW+TF-IDF는 0.8점, Word2Vec은 1.2점을 기록해 Word2Vec을 최종 채택했습니다. 그리고 전체 211개 상품 중 82%가 추천에 등장하도록 설계해서, 일부 인기 상품에만 추천이 쏠리지 않게 했습니다.
>
> 이 유사 상품 추천 기능은, 세그먼트 기반으로 홈 화면에 상품을 정렬해서 보여주는 기능과는 서로 독립적으로 기획된 별개의 기능입니다. 세그먼트 추천은 사용자의 방문 목적·기피 재료 같은 특성을 군집화해서 홈 화면 전체의 상품 순서를 정하는 것이고, 이 Word2Vec 유사 상품 추천은 사용자가 특정 상품에 찜을 눌렀을 때 그 자리에서 바로 관련 상품을 보여주는, 서로 다른 화면·다른 목적의 기능입니다."

## 3. 남은 확인 사항 — 정리

세그먼트(1절)와 Word2Vec(2절) 모두 핵심 질문에는 답변을 받아 최종 답변 스크립트를 확정했습니다. 남은 건 132명 표본의 정확한 위치(1-4절)뿐이며, 우선순위가 낮아 필요 시 추후 보완합니다.
