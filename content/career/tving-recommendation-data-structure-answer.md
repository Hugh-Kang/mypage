# "티빙의 추천 서비스는 어떤 데이터를 활용했을까요?" — 구조화 + 비판적 검토 + 최종 답변

## 0. 설계 프롬프트

> 너는 OTT 추천 시스템 도메인 지식을 검증하는 면접 코치다. "티빙의 추천 서비스는 어떤 데이터를 활용했을까요?"라는 질문에 대해, 지원자가 실제로 티빙 내부 데이터를 알 수 없다는 것을 전제로 ① 일반적인 OTT 추천 시스템이 활용하는 데이터 유형을 구조화하고, ② 이를 바탕으로 한 초안 답변을 작성하라. 그 다음 이 초안을 비판적으로 검토하라 — 특히 (a) 확인되지 않은 사실을 단정적으로 말하는 위험, (b) 일반론에 그쳐 티빙 특유의 맥락(무료광고요금제 AVOD, KBO 실시간 중계, 프로필 기반 시청)을 놓치는 위험, (c) 최근 개인정보 유출 이슈가 있었던 회사 앞에서 데이터 활용을 무신경하게 말하는 위험을 짚어라. 마지막으로 이 세 가지를 보완한 최종 면접용 답변을 작성하라.

## 1. 일반적인 OTT 추천 시스템이 활용하는 데이터 — 구조화

| 구분 | 데이터 유형 | 구체적 예시 |
|---|---|---|
| 명시적(Explicit) 신호 | 사용자가 직접 남긴 의사표시 | 별점/평가, 찜하기·좋아요, "이 콘텐츠 보고 싶지 않음" 같은 명시적 거부 신호 |
| 암묵적(Implicit) 행동 데이터 | 시청 로그 | 시청 시작 여부, 시청 완료율(끝까지 봤는지), 중도 이탈 지점, 재생 위치(이어보기), 재시청 여부 |
| 암묵적 행동 데이터 | 탐색 로그 | 검색어, 클릭했지만 시청하지 않은 콘텐츠(노출-클릭-무시 로그), 스크롤/체류 시간 |
| 콘텐츠 메타데이터 | 정형 속성 | 장르, 출연진, 감독, 방영연도, 시즌/회차, 자체제작(오리지널) 여부 |
| 콘텐츠 메타데이터 | 비정형/의미 태그 | 무드·톤(힐링, 몰입, 스릴), 키워드, 줄거리 임베딩(콘텐츠 기반 필터링용) |
| 사용자 컨텍스트 | 프로필/계정 단위 | 티빙처럼 프로필 분리가 있는 서비스는 "누구 프로필"인지가 협업 필터링의 단위가 됨 |
| 사용자 컨텍스트 | 시간/디바이스 | 시청 요일·시간대(주말 몰아보기 vs 평일 저녁), 디바이스(TV vs 모바일), 재생 환경(와이파이/이동 중) |
| 협업 신호 | 유사 사용자 그룹 | "이 콘텐츠를 본 사람들이 함께 본 콘텐츠" 기반 협업 필터링(Collaborative Filtering) |
| 비즈니스/전략적 신호 | 노출 우선순위 조정용 | 오리지널·독점 콘텐츠 전략적 가중치, 라이선스 만료 임박 콘텐츠 소진 등 사업적 판단이 섞인 신호 |
| 티빙 특유 신호(추정) | 실시간 라이브 데이터 | KBO 중계처럼 실시간성이 강한 콘텐츠는 "지금 몇 명이 보고 있는가" 같은 실시간 시청 스파이크 데이터가 추천/배너 노출에 영향을 줄 가능성이 높음 |

## 2. 초안 예상답변 (1차 초안)

> "티빙 같은 OTT 서비스는 크게 세 가지 데이터를 활용한다고 생각합니다. 첫째는 시청 이력이나 평점 같은 사용자 행동 데이터, 둘째는 장르·출연진 같은 콘텐츠 메타데이터, 셋째는 비슷한 취향의 사용자들이 함께 본 콘텐츠를 추천하는 협업 필터링 데이터입니다. 이 세 가지를 조합해서 개인화된 추천을 만들 것 같습니다."

## 3. 초안에 대한 비판적 검토

**문제점 (a) — 확인되지 않은 사실을 단정형으로 말하고 있음**: 초안은 "~라고 생각합니다"로 끝나지만 문장 자체는 "이 세 가지를 조합해서 만들 것 같습니다"처럼 마치 내부 구조를 아는 것처럼 들릴 위험이 있습니다. 지원자는 티빙 내부 데이터나 알고리즘을 실제로 본 적이 없으므로, "일반적인 OTT 추천 시스템의 구조로 미루어 추론하면"이라는 전제를 명시적으로 깔지 않으면 근거 없는 확신으로 비칠 수 있습니다.

**문제점 (b) — 일반론에 그쳐 티빙 특유의 맥락이 빠져 있음**: 넷플릭스나 왓챠에도 그대로 적용되는 뻔한 답변입니다. 티빙은 (1) 무료광고요금제(AVOD)가 있어 광고 시청 패턴도 추천/타겟팅에 활용될 가능성이 있고, (2) KBO 중계권을 보유해 실시간 스포츠 시청이라는 다른 OTT에 없는 데이터 유형이 있으며, (3) 프로필 기반 시청(가족 계정 내 개인 프로필)이 있다는 점에서 "누구의 프로필인가"가 추천 단위가 된다는 차별점이 있습니다. 이런 티빙 고유 맥락이 빠지면 "그냥 일반적인 OTT 얘기만 하네"라는 인상을 줄 위험이 있습니다.

**문제점 (c) — 최근 개인정보 유출 이슈 앞에서 데이터 활용을 무신경하게 말할 위험**: `tving-recent-news-2026-09.md`에서 확인했듯 최근 개인정보 유출 이슈(약 3,954만 계정 규모)가 있었던 회사입니다. 이런 맥락에서 "사용자의 시청 이력, 검색어, 위치성 정보를 다 활용해서 추천한다"는 식으로만 답하면, 데이터 활용의 편익만 말하고 민감성에 대한 인식이 없는 것처럼 보일 수 있습니다. 데이터 활용을 말할 때 최소한 "민감할 수 있는 데이터인 만큼 활용 범위와 보안에 대한 인식이 함께 필요하다"는 한 마디를 덧붙이는 것이 안전합니다.

## 4. 보완된 최종 면접용 답변

> "정확한 내부 구조는 제가 직접 본 적이 없어서, 일반적인 OTT 추천 시스템의 구조로 미루어 추론해서 말씀드리겠습니다.
>
> 크게 네 가지 층위의 데이터가 쓰일 것 같습니다. 첫째는 사용자 행동 데이터로, 시청 시작 여부뿐 아니라 끝까지 봤는지, 어디서 이탈했는지, 재시청했는지까지가 '진짜 만족도'를 보여주는 신호일 것입니다. 둘째는 콘텐츠 메타데이터로, 장르·출연진 같은 정형 정보뿐 아니라 '힐링', '몰입감' 같은 무드 태그까지 활용해서 콘텐츠 기반 추천을 보완할 것 같습니다. 셋째는 협업 필터링 데이터, 즉 비슷한 시청 패턴을 가진 사용자 그룹이 함께 본 콘텐츠 정보입니다.
>
> 그리고 넷째로, 티빙만의 특징을 반영한 데이터도 있을 거라고 생각합니다. 티빙은 프로필 단위로 계정이 분리되니까 '누구의 시청 이력인가'가 추천의 기본 단위가 될 것이고, KBO 중계권처럼 실시간성이 강한 콘텐츠는 '지금 몇 명이 보고 있는가' 같은 실시간 시청 데이터가 추천이나 배너 노출에 영향을 줄 수 있을 것 같습니다. 무료광고요금제 이용자라면 광고 시청 패턴도 추천이나 타겟팅에 함께 쓰일 가능성이 있고요.
>
> 다만 이런 데이터는 사용자의 시청 습관이나 취향을 세밀하게 보여주는 만큼 민감한 정보이기도 해서, 추천 정확도를 높이는 것만큼이나 어떤 데이터를 어디까지 활용할지에 대한 기준과 보안도 함께 고려되어야 한다고 생각합니다."

### 4-1. 짧은 버전 (30~40초, 후속 질문이 이어질 것을 대비)

> "정확한 내부 구조는 모르지만 일반적인 OTT 구조로 추론하면, 시청완료율·이탈지점 같은 행동 데이터, 장르·무드 태그 같은 콘텐츠 메타데이터, 비슷한 취향 사용자 그룹 기반의 협업 필터링, 이렇게 세 층위가 기본이고, 티빙은 프로필 기반 시청과 KBO 실시간 중계 데이터라는 특유의 신호가 하나 더 있을 것 같습니다. 다만 이런 데이터가 민감할 수 있는 만큼, 활용 범위와 보안에 대한 고려도 같이 필요하다고 생각합니다."
