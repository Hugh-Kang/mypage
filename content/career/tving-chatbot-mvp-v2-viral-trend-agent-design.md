# 티빙 챗봇 에이전트 MVP 재설계 V2 — "바이럴 커넥터 에이전트" (세령님 피드백 반영)

> 작성 목적: 남세령 책임님(OBE 디자인)과의 카카오톡 대화를 구조화하고, "안전빵"으로 평가받은 기존 설계(V1, `tving-chatbot-mvp-design-socratic-result.md`)의 한계를 짚은 뒤, 대화에서 나온 크레이지 아이디어를 기준으로 더 과감한 MVP(V2)를 설계
> 작성일: 2026-10-13
> 근거자료: 남세령 책임님과의 카카오톡 대화 전문(2026-10-13), `tving-chatbot-mvp-design-socratic-result.md`(V1)

## 사용한 최적의 프롬프트

```
역할
너는 카카오톡 대화 원문을 분석해 핵심 피드백을 구조화하고, 그 피드백을
반영한 실전 MVP 설계안을 만드는 PM 코치다.

입력
- 남세령 책임님(OBE 디자인, UX/서비스 디자이너)과 나눈 카카오톡 대화 전문
- 기존에 설계했던 티빙 챗봇 에이전트 MVP(V1, "뭘 볼지 몰라 이탈하는 사용자"
  타겟, 기분 기반 대화형 추천)
- V1에 대한 평가: "다소 안전하고 평범하다"

과제
1. 대화를 시간순으로 구조화하고, 그 안에서 나온 비판 포인트와 대안
   아이디어를 명확히 분리해서 정리한다. 감탄사·잡담은 걸러내고 실질적인
   피드백/아이디어만 추출한다.
2. V1이 왜 "안전빵"으로 평가받았는지, 대화 속 근거를 바탕으로 구조적
   원인을 짚는다(기능이 평범한 게 아니라, 에이전트라는 형태를 쓸 '당위성'이
   약하다는 지점까지 짚을 것).
3. 대화에서 나온 크레이지 아이디어(① 소비자→생산자 전환, ② 외부 실제
   바이럴 트렌드를 크롤링해 내부 콘텐츠와 연결하는 에이전틱 구조)를
   구분해서 정리하고, 그 중 면접에서 말하기에 더 완성도 있는 쪽을 골라
   본격적인 MVP(V2)로 설계한다.
4. V2는 V1과 같은 포맷(문제정의 → 왜 이 형태인가 → 범위 → 플로우 →
   리스크 축소 → 지표)으로 설계하되, "왜 챗봇이 아니라 이 구조인가"를
   V1과 대비해서 분명히 설명한다.
5. 실제 면접에서 V1과 V2를 어떤 순서/전략으로 함께 말하면 좋을지
   제안한다(안전한 답을 베이스로 깔고 크레이지 아이디어를 덧붙이는 식의
   화법 전략 포함).

출력 형식
마크다운 문서. 두괄식 요약 → 대화 구조화 → V1 한계 분석 → V2 설계 →
면접 화법 전략 순.
```

## 핵심 요약 (두괄식)

V1("기분 기반 대화형 추천 챗봇")이 안전빵으로 평가받은 이유는 기능 자체가 평범해서가 아니라, **"이미 잘 작동하는 내부 ML 추천 모델을 챗봇이라는 대화형 UI로 감싼 것"에 불과해 '왜 굳이 에이전트인가'에 대한 당위성이 약했기 때문**입니다. 대화에서 나온 대안은 두 가지였고, 그 중 더 완성도 있게 다듬을 수 있는 것은 **"외부에서 실제로 바이럴 중인 트렌드(배우 언급, 화제 장면, 밈)를 에이전트가 스스로 크롤링·분석해서, 티빙 내부 콘텐츠와 자동으로 연결해 먼저 보여주는 구조"**입니다. 이 구조는 사용자가 질문해야 답하는 '챗봇'이 아니라, 외부 세계를 스스로 탐색하고 내부 자산과 연결해 먼저 행동하는 '에이전트'라는 이름값에 맞으며, 넷플릭스식 개인화 추천을 사용자가 신뢰하지 않는다는 대화 속 지적과도 정확히 맞물립니다. 면접에서는 V1(안전하지만 1차를 통과시킨 답)을 베이스로 깔고, "동료 PM/디자이너와 논의하며 더 과감한 방향도 고민했다"는 서사로 V2를 자연스럽게 얹는 전략을 추천합니다.

## 1. 대화 구조화

### 1-1. 질문 배경

- 강해우가 티빙 2차 면접을 앞두고, 1차 면접에서 받았던 "챗봇 AI 에이전트를 만든다면 어떤 방향이 좋을까"라는 질문에 대해 세령님(UX 디자이너, 타사 소속)에게 조언을 구함
- 지원 팀(Discovery팀)의 실제 업무 범위를 공유: 메인홈/AI 챗봇 에이전트 기획, 검색/추천/Push/배너/Growth 모듈, A/B Test 플랫폼

### 1-2. V1에 대한 1차 반응 — "피곤하다", "굳이?"

| 발언 | 의미 |
|---|---|
| "듣자마자 사용자 입장에서 확 피곤해지긴 하는듯요... 왜 티빙 보면서 에이전트를 써야 하지" | 티빙은 "보러 들어오는 플랫폼"이라, 대화라는 추가 행동 자체가 피로 요소가 될 수 있다는 지적 |
| "추천같은건 당연히 해줄 텐데" | 추천 자체는 이미 당연한 기본 기능이라, 챗봇으로 대화해서 추천받는 것에 특별한 가치가 안 느껴진다는 지적 |
| "이미 지금도 ML모델로 잘 추천해주고 있는데 굳이 챗봇 에이전트까지 개발하는 공수를 들이고, 사용자 입장에서는 익숙하지 않은 플로우/UI인데 굳이?" (강해우가 스스로 정리) | **핵심 자각**: V1은 기존에 이미 잘 작동하는 추천 시스템을 "새로운 UI"로 재포장한 것에 가깝고, 이 전환 비용을 정당화할 이유가 약함 |

### 1-3. 세령님의 직접 평가

> "해우님이 생각한 답변은 안전빵 같아서... 크레이지 아이디어 같이 가져가보면 좋을듯"

이 평가는 "기능이 틀렸다"가 아니라 "더 과감한 걸 보여줄 수 있는 여지가 있다"는 의미로, 1차 면접은 이미 이 답변으로 통과했음(안전하지만 효과적이었던 답).

### 1-4. 크레이지 아이디어 ① — 소비자에서 생산자로 전환

- 네이버웹툰 "짤 만들기" 사례 연상
- 티빙에 이미 생긴 **팬톡(팬 커뮤니티)**, **쇼츠 구간** 기능과 연결
- 제안: 더빙/TTS 기능으로 사용자가 특정 장면에 직접 대사를 입히거나, 감상을 생산물(짤/쇼츠/클립)로 만들어 공유할 수 있게 하는 구조
- "여러분 저 됐어요.. 성덕됐어요" 같은 밈화된 리액션 콘텐츠를 사용자가 직접 만들 수 있는 판을 깔아주자는 아이디어
- 강해우가 즉각 연결: "특정 컨텐츠 구간을 가지고 추가 생성(에이전트 활용)하거나 보완해서 가지고 놀 수 있게"

### 1-5. 크레이지 아이디어 ② — 외부 실제 바이럴 트렌드 크롤링 + 내부 콘텐츠 연결 (세령님이 가장 힘주어 설명)

- "에이전틱 봇이라면 굳이 내부의 알고리즘만 갖고 추천할 필요 없으니, 외부에서 크롤링해온 걸 가지고 진짜 띄워줘도 되죠"
- 구체적 예시: tvN "100일의 거짓말"에서 배우 진선규의 일본어 연기가 실제로 SNS에서 바이럴 중 → 이 실제 바이럴 숏폼을 보여준 뒤, 바로 아래에 "진선규 콜렉션(범죄도시, 극한직업 등)"을 자동으로 띄워주는 구조
- **에이전트 vs 챗봇의 정의 차이를 명확히 제시**: "그 밑에 나온 영상이 실제 어디의 몇 분대인지... 이러면 그건 에이전틱 인텔리전스가 맞죠. 물어봐야 답하는 건 챗봇이고" → 즉 **사용자가 질문해야 작동하는 것은 챗봇, 스스로 외부를 탐색해서 먼저 찾아 보여주는 것이 에이전트**라는 기준
- 근거로 든 사용자 행동 패턴: "넷플릭스에서 취향이라며 추천해주는 거 단 한 번도 클릭 안 해봄" / "결국 제가 뒤져서 찾아서 봄" → 개인화 알고리즘 추천에 대한 신뢰도는 낮지만, **실제로 화제가 되고 있는 것(사회적 증거)에는 반응**한다는 심리
- "한국사람들 트렌드에 진짜 민감한데, 만들어낸 트렌드엔 반응 안 하니, 외부 진짜 날것 바이럴 중인 걸 들고 와서 내부 버즈로 바꾼다"는 전략으로 요약됨
- 확장 아이디어: 파라마운트 등 외부 파트너십 콘텐츠 연결, 배우/작품 단위가 아니라 "일제강점기 배경 영화" 같은 테마 단위 확장도 가능

### 1-6. 지원 팀 범위와의 정합성

- 강해우가 애초에 V1을 좁게 설계했던 이유: 지원한 Discovery팀이 "메인홈/추천/챗봇 에이전트"를 담당하는 팀이라, 그 범위 안에서만 고민하다 보니 보수적인 답이 나왔음을 스스로 인지
- 아이디어 ②는 이 범위(메인홈 노출, 추천 모듈)를 벗어나지 않으면서도 "외부 데이터 활용"이라는 새로운 축을 더하는 방식이라 실현 가능성이 높음

## 2. V1이 "안전빵"으로 평가받은 구조적 원인

V1("기분 기반 대화형 추천, 2~3턴 내 추천, 홈 화면 추천 대비 전환율 비교")을 다시 보면:

1. **입력 데이터가 내부 데이터에 한정됨**: 사용자의 기분을 몇 마디로 받아도, 결국 추천 대상은 기존 카탈로그 내 콘텐츠이고 추천 로직도 기존 추천 시스템과 본질적으로 다르지 않음
2. **에이전트의 핵심 속성(자율적 탐색·선제적 행동)이 없음**: 사용자가 버튼을 누르고 질문에 답해야만 작동하는, 철저히 "물어야 답하는" 구조 — 세령님이 정확히 짚은 "그건 챗봇이고"에 해당
3. **전환 비용을 정당화할 근거가 약함**: 이미 익숙한 홈 화면 추천 UI가 있는데, 왜 새로운 대화형 UI로 전환해야 하는지에 대한 설득력이 "방향감 없는 사용자"라는 좁은 페르소나 설정 외에는 부족함

결국 V1의 문제는 "기능 아이디어의 참신함 부족"이 아니라, **"에이전트"라는 기술/형태를 선택해야만 하는 이유(에이전트가 아니면 할 수 없는 일)가 빠져 있었다는 점**입니다.

## 3. 새 MVP 설계 (V2) — "바이럴 커넥터 에이전트"

### 핵심 요약

V2는 **"티빙 외부에서 실시간으로 바이럴 중인 배우·장면·밈을 에이전트가 스스로 탐지하고, 이를 티빙 카탈로그 내 관련 콘텐츠와 자동으로 연결해 홈 화면에 먼저 노출"**하는 구조입니다. 사용자가 질문하지 않아도 작동하며, 추천의 근거가 "내가 과거에 본 것"이 아니라 "지금 세상이 화제 삼고 있는 것"이라는 점에서 기존 개인화 추천과 완전히 다른 신뢰 기반을 만듭니다.

### 왜 챗봇이 아니라 이 구조인가 (V1과의 결정적 차이)

| 구분 | V1 (기분 기반 대화형 추천) | V2 (바이럴 커넥터 에이전트) |
|---|---|---|
| 작동 트리거 | 사용자가 버튼을 눌러야 시작 | 에이전트가 외부를 상시 탐색, 결과를 선제적으로 노출 |
| 데이터 소스 | 내부 카탈로그 + 사용자 응답 | 외부 실시간 바이럴 데이터 + 내부 카탈로그 매칭 |
| "에이전트"라는 이름값 | 약함(사실상 대화형 UI를 가진 추천 시스템) | 강함(자율적으로 탐색·판단·연결·실행하는 전형적 에이전틱 워크플로우) |
| 사용자 신뢰 기반 | "내 취향을 안다"는 개인화 신뢰(대화에서 효과가 낮다고 지적됨) | "지금 다들 화제 삼는 것"이라는 사회적 증거 기반 신뢰 |

### MVP 범위

1. **외부 소스**: 초기엔 범위를 좁혀 1~2개 채널만 사용 — 예: 유튜브 쇼츠(조회수/댓글 급상승) + 특정 커뮤니티(더쿠 등) 중 하나만 먼저 연동
2. **분석**: 바이럴 콘텐츠에서 언급되는 배우/장면/대사/테마를 추출하고, 티빙 카탈로그와 매칭(배우 필모그래피, 동일 테마 작품 등)
3. **노출 형태**: 챗봇 대화창이 아니라, **홈 화면에 "지금 화제예요" 카드**로 자동 생성 — 바이럴 원본(숏폼 클립 또는 캡션)과 함께 "OOO 컬렉션"을 바로 아래 붙여서 제시
4. **1차 MVP는 반자동**: 완전 자동화(크롤링→매칭→노출까지 무인)는 리스크가 크므로, 초기엔 에이전트가 후보를 추출하면 **담당 에디터가 승인**하는 반자동 구조로 시작 — 오탐(배우 동명이인, 맥락 오해 등) 리스크를 통제

### 리스크와 범위 축소 근거

- 완전 자동 크롤링은 저작권/맥락 오류/부적절 콘텐츠 노출 리스크가 있어, MVP 단계에서는 **에이전트가 제안하고 사람이 승인**하는 "Human-in-the-loop" 구조로 좁힘
- 소스도 처음부터 다채널이 아니라 1~2개로 한정해, 매칭 품질과 오탐률을 먼저 검증한 뒤 확장

### 성공 지표

- **핵심 지표**: "지금 화제예요" 카드 클릭 후 본편 재생 전환율 (기존 홈 화면 추천 배너 대비)
- **가드레일 지표**: 오탐(실제로는 관련 없는 콘텐츠 매칭) 신고율 — 일정 수준 이상이면 반자동 승인 비중을 늘림
- **비교군**: 카드를 노출하지 않은 대조군 대비 체류시간·재생전환율 증가분을 A/B 테스트로 측정

## 4. 참고 메모 — 아이디어 ①(소비자→생산자 전환)

이번엔 V2로 채택하지 않았지만, 폐기하지 않고 메모:

- 더빙/TTS 기반 2차 창작, 팬톡과 연계된 감상 생산 기능은 "참여형 에이전트"로 별도 설계 가능
- 다만 이 방향은 콘텐츠 저작권/가이드라인 검토가 선행되어야 하는 영역이라, 2차 면접에서 깊이 들어가기보다는 "향후 확장 아이디어로 언급"하는 선에서 짧게 다루는 것을 추천

## 5. 면접에서 말하는 전략

1. 1차 면접 답변(V1)을 먼저 짧게 요약해서 베이스로 깐다 — 이미 통과시켜준 답변이므로 안정성을 보여주는 용도
2. 이어서 **"이후 실제로 동료 PM/디자이너와 이 주제로 토의하면서, 더 과감한 방향도 함께 고민했다"**는 자연스러운 전환 멘트로 V2를 꺼낸다 — 혼자만의 생각이 아니라 협업을 통해 아이디어를 발전시키는 태도를 함께 보여줄 수 있음
3. V2를 말할 때는 반드시 **"왜 이게 챗봇이 아니라 에이전트인가"**를 한 문장으로 짚는다 — 면접관이 "에이전트"라는 단어의 의미를 깊이 묻는 경우가 많았으므로(1차 면접 기록 참고), 이 구분을 스스로 먼저 제시하면 설계력을 증명할 수 있음
4. 추천 멘트 예시:
   > "1차 때는 '기분 기반 추천 챗봇'으로 답했는데, 이후 동료들과 논의하면서 이 답이 결국 기존 추천 시스템을 대화형 UI로 감싼 것뿐이라는 한계를 느꼈습니다. 그래서 '에이전트'라는 형태가 꼭 필요한 지점이 무엇인지 다시 고민했고, 외부에서 실시간으로 바이럴 중인 콘텐츠를 에이전트가 스스로 탐지해서 내부 카탈로그와 연결하는 방향을 추가로 설계해봤습니다. 이건 사용자가 질문해야 작동하는 챗봇이 아니라, 에이전트가 선제적으로 탐색하고 행동한다는 점에서 '에이전트'라는 이름값에 더 맞는 구조라고 생각합니다."
