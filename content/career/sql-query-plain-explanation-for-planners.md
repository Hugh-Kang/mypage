# "비교군 포함 재방문율 쿼리" — 기획자도 이해할 수 있는 쉬운 설명

> 작성 목적: `data-analysis-expected-questions-2026-prediction.md`의 예상 질문 1번에서 제시한 SQL 답변 스케치("1단계 CTE + 2단계 RANK() + 조인")를 비개발자(기획자)도 바로 이해할 수 있도록 쉬운 말로 재설명
> 작성일: 2026-10-05

## 핵심 한 줄 (두괄식)

이 쿼리가 하는 일은 딱 하나입니다 — **"이 콘텐츠가 잘된 게 콘텐츠 자체의 힘인지, 아니면 그냥 그 시기·그 장르가 원래 다 잘됐던 건지"를 구분하기 위해, 비교 기준을 두 개 만들어서 점수를 매기는 것**입니다.

## 왜 비교 기준이 두 개나 필요한가 (비유로 이해하기)

학생 성적에 비유하면 쉽습니다.

- **기준 1 (자기 과거 대비)**: "이번 시험 점수가 지난 시험보다 올랐나?" — 그 학생 혼자의 변화만 보는 것
- **기준 2 (또래 비교군 대비)**: "이번 시험에서 전교 상위권 평균과 비교하면 내 점수는 어느 정도인가?" — 그 시험 자체가 쉬웠는지 어려웠는지까지 감안하는 것

기준 1만 보면 "내가 올랐다"고 착각할 수 있습니다. 사실은 이번 시험이 전체적으로 쉬워서 다 같이 오른 것일 수도 있으니까요. 그래서 "전교 상위권과 비교해도 올랐는가"까지 같이 봐야 진짜 내 실력이 는 건지 알 수 있습니다.

콘텐츠 분석도 똑같습니다.
- **기준 1**: "이 드라마 방영 후, 방영 전보다 구독 유입이 늘었나?"
- **기준 2**: "같은 시기에 방영한 비슷한 장르의 잘나가는 다른 작품들과 비교해도, 이 드라마가 더 늘었나?"

기준 1만 보면 "그냥 그 계절에 OTT 이용자가 다 같이 늘어난 것"과 "이 드라마만의 효과"를 구분할 수 없습니다. 그래서 기준 2(비슷한 시기·같은 장르 잘나가는 작품들)까지 같이 봐야 "이 콘텐츠만의 순수한 힘"을 가려낼 수 있습니다.

## 쿼리 구조를 쉬운 말로 풀면

| 어려운 용어 | 쉬운 말로 번역 |
|---|---|
| CTE (Common Table Expression) | 복잡한 계산을 한 번에 다 하지 말고, "임시 결과표"를 미리 만들어서 이름 붙여두는 것. 엑셀로 치면 "보조 시트"를 하나 더 만드는 느낌 |
| 윈도우 함수로 "방영 전 30일" 구간 뽑기 | "방영일 기준으로 거꾸로 30일 치만 따로 모아서 평균 내기" 버튼 누르는 것 |
| 베이스라인 인덱스(100) | 비교하기 편하게, "방영 전 평균 = 100점"이라고 기준점을 잡아두는 것. 그래야 "방영 후엔 240점이 됐다 = 2.4배 늘었다"처럼 바로 비교 가능 |
| `RANK() OVER (PARTITION BY 장르, 방영분기 ORDER BY ...)` | "장르별로, 분기별로 각각 따로 순위를 매기는" 기능. 엑셀 피벗테이블에서 "장르/분기 묶음마다 순위 매기기"를 자동으로 해주는 것과 같음 |
| 상위 5개만 필터링 | 그 순위에서 1~5등만 골라내는 것 — 이게 "비교군"이 됨 |
| 두 표를 조인(join)해서 지수화 | "임시표 1(이 콘텐츠의 자기 과거 대비 점수)"과 "임시표 2(비교군 평균 점수)"를 나란히 붙여서, "내 점수 ÷ 비교군 점수 × 100" 계산으로 최종 지수를 뽑는 것 |

## 한 문장 요약

**"이 콘텐츠가 방영 전보다 얼마나 늘었는지(자기 과거 대비) 표 하나, 그리고 비슷한 시기·같은 장르 잘나가는 작품들은 평균 얼마나 늘었는지(비교군) 표 하나를 각각 만든 다음, 두 표를 붙여서 '우리 콘텐츠가 비교군보다 몇 배 더 잘됐는지'를 숫자 하나로 계산하는 쿼리"**입니다. 복잡해 보이는 이유는 "비교군을 자동으로 찾아주는 부분"(장르·분기별 순위 매기기) 때문이지, 개념 자체는 "내 과거 대비 + 또래 대비, 둘 다 본다"는 아주 단순한 생각에서 출발합니다.
