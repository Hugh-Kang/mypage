# 포트폴리오 프로젝트 요약본 ③ — 상품 추천 시스템 기획 (건강 디저트 추천 플랫폼, 빵그리의 오븐)

> 작성 목적: 포트폴리오 9개 프로젝트 요약 작업의 세 번째. 이 프로젝트는 포트폴리오 자체에 "회고 없음(보완 필요)"로 명시적으로 플래그돼 있던 항목이라, 요약본에 자가 회고를 새로 채워 넣는 작업도 함께 진행
> 작성일: 2026-10-02
> 근거자료: `portfolio-all-projects-hypothesis-structure.md`(포트폴리오 원문 구조화), `health-dessert-segment-word2vec-slide-verification.md`(슬라이드 원문 대조, 세그먼트·Word2Vec 세부 사실 확정)

## 0. 설계 프롬프트

> 너는 지원자의 포트폴리오 프로젝트 "건강 디저트 추천 플랫폼 상품 추천 시스템 기획"을 면접에서 바로 설명할 수 있는 요약본으로 만드는 코치다. 이미 슬라이드 원문 대조로 확정된 세그먼트(Elbow Method 기반 4개 군집)와 Word2Vec(콜드스타트 상황의 콘텐츠 기반 유사 상품 추천, BoW+TF-IDF 대비 정성평가 우위)의 사실관계를 정확히 반영하고, 두 기능이 서로 독립적이라는 점(하나가 다른 하나의 해결책이 아님)을 혼동 없이 서술하라. 이 프로젝트는 포트폴리오에 명시적 회고가 없다고 플래그돼 있으므로, 지금까지 확인된 한계(정성평가 소규모, 설문 기반 지표와 실제 행동의 괴리, 리뷰 기반 추천의 신상품 한계)를 근거로 자가 회고를 새로 작성하라.

## 1. 1분 요약 스크립트 (면접에서 바로 말할 버전)

> "건강 디저트 구매 경험자 100명 설문에서 63%가 '접근성이 낮다'(비싼 가격·다양성 부족·맛 정보 부족)고 답했고, 방문자의 60%는 다이어트·근성장 목적, 27%는 유당불내증이 있다는 것도 확인했습니다. 그래서 방문 목적과 기피 재료에 맞춘 개인화 추천을 제공하면 접근성 문제를 풀 수 있다는 가설을 세웠습니다. 먼저 성별·나이·방문목적·기피재료·알러지를 모두 넣어 군집화를 시도했는데, 실제로는 성별과 나이는 선호 차이를 만들지 않았고 유당불내증 여부와 방문 목적이 가장 큰 차이를 만드는 변수였습니다. 그래서 이 두 축으로 Elbow Method를 적용해 4개 세그먼트(근성장·다이어트 42.9%, 유당불내증 28.0%, 교집합 18.6%, 기타 10.6%)가 최적이라고 판단했고, 세그먼트별 찜 순위로 홈 화면 추천을 구성했습니다. 별도로, 초기 서비스라 사용자 행동 데이터가 부족한 콜드스타트 상황이었기 때문에, 상품명·옵션명·최신 리뷰 100개 같은 자연어 데이터와 가격·고단백·글루텐프리 등 상품 특성을 입력으로 쓰는 콘텐츠 기반 추천 모델을 BoW+TF-IDF와 Word2Vec 두 후보로 만들어 비교했고, 내부 평가자 10명의 정성평가에서 Word2Vec이 1.2점(BoW+TF-IDF 0.8점, 2점 만점)으로 더 높아 채택했습니다. 전체 211개 상품 중 82%가 추천에 등장하도록 설계해 일부 인기 상품에만 쏠리지 않게 했고요. 이 두 기능은 서로 다른 화면·다른 목적을 위한 독립적인 기능입니다. 결과적으로 재방문 의사 7.0점, 구매 의사 6.3점(10점 만점)을 받았고, 마케팅 없이 베타 출시만으로 MAU 약 1,300명을 달성했습니다."

## 2. 구조화 (문제정의 → 가설 → 방법론 → 결과 → 회고)

| 단계 | 내용 |
|---|---|
| 문제정의 | 건강 디저트 구매 경험자 100명 중 63%가 '접근성 낮음'을 지적(비싼 가격·다양성 부족·맛 정보 부족). 방문자의 60%는 다이어트·근성장 목적, 27%는 유당불내증 |
| 가설 | 방문 목적과 기피 재료에 맞춘 개인화 추천을 제공하면 접근성 문제가 풀려 재방문·구매 의사가 오를 것이다 |
| 방법론 — 세그먼트 | 성별·나이·방문목적·기피재료·알러지로 군집화 시도 → 성별·나이는 무의미, 유당불내증·방문목적만 유의미 → Elbow Method로 WCSS 급변 지점 확인 → 4개 세그먼트 확정(근성장·다이어트 42.9% / 유당불내증 28.0% / 교집합 18.6% / 기타 10.6%) → 세그먼트별 찜 순위로 홈 화면 정렬 |
| 방법론 — Word2Vec | 콜드스타트(행동 데이터 부족) 상황이라 크롤링한 상품 정보·리뷰로 콘텐츠 기반 추천 설계 → BoW+TF-IDF와 Word2Vec 두 후보 비교 → 내부 평가자 10명이 약 210건을 0~2점 척도로 정성평가(BoW+TF-IDF 0.8점, Word2Vec 1.2점) → Word2Vec 채택 → 211개 상품 중 82% 커버리지 확보 |
| 결과 | 재방문 의사 7.0점, 구매 의사 6.3점(10점 만점), 마케팅 없이 베타 출시만으로 MAU 약 1,300명 |
| 회고(포트폴리오 원문) | 명시적 회고 없음 — **보완 필요(아래 3절에서 자가 회고로 보완)** |

## 3. 자가 회고 (포트폴리오에 없던 부분, 새로 정리)

포트폴리오에는 이 프로젝트의 회고가 비어 있어, 지금까지 확인된 사실을 근거로 스스로 정리한 회고입니다. 핵심은 세 가지입니다. 첫째, 재방문 의사 7.0점·구매 의사 6.3점은 설문에서 "그렇게 하겠다"고 응답한 의향 점수일 뿐, 실제 재방문·구매로 이어졌는지는 별도로 추적하지 못했습니다. AI 챗봇 프로젝트에서도 설문 응답과 실제 행동 로그가 달랐던 경험이 있었던 만큼, 이 프로젝트도 의향 점수를 실제 행동 지표(재방문율, 구매 전환율)로 검증하는 단계가 빠졌다는 한계가 있습니다. 둘째, Word2Vec과 BoW+TF-IDF를 비교한 정성평가가 내부 평가자 10명이라는 작은 인원으로 이뤄졌고, 평가자가 내부 인원이라 실제 최종 사용자의 체감과 다를 수 있다는 한계가 있습니다. 셋째, 이 모델은 상품의 리뷰 데이터를 입력으로 쓰기 때문에, 아직 리뷰가 쌓이지 않은 신상품 자체의 콜드스타트는 완전히 해결하지 못하는 구조적 한계가 있습니다.

## 4. 핵심 꼬리질문 1 — "재방문 의사 7.0점, 구매 의사 6.3점이 실제 재방문·구매로 이어졌는지 검증했나요?"

**모범답안(직접답변 우선)**: "아니요, 솔직히 그 부분은 검증하지 못했습니다. 이 점수는 설문에서 '그렇게 하겠다'고 응답한 의향 점수이지, 실제 재방문율이나 구매 전환율 같은 행동 지표로 추적한 건 아니었습니다. 저도 다른 프로젝트(아이돌 챗봇)에서 설문으로 답한 선호와 실제 채팅 로그상 행동이 달랐던 경험이 있어서, 의향 점수를 그대로 성과로 내세우는 게 위험하다는 걸 알고 있습니다. 이 프로젝트 역시 베타 출시 이후 실제 재방문·구매 데이터를 추적해서 의향 점수와 비교 검증했어야 한다고 생각하고, 이게 지금 제가 스스로 꼽는 이 프로젝트의 가장 큰 보완점입니다."

## 5. 핵심 꼬리질문 2 — "콜드스타트 상황이라면서 리뷰 데이터를 썼는데, 리뷰가 없는 신상품은 어떻게 추천되나요?"

**모범답안(직접답변 우선)**: "정확한 지적입니다. 여기서 콜드스타트는 '사용자 행동 데이터(찜·구매 이력)가 없는 서비스 초기 상황'을 의미했고, 그래서 사용자 행동 대신 크롤링한 상품 메타데이터와 리뷰라는, 서비스 초기부터 확보 가능한 콘텐츠 데이터로 추천을 설계한 것이었습니다. 다만 말씀하신 대로, 리뷰가 아직 쌓이지 않은 개별 신상품 자체의 콜드스타트는 이 모델이 완전히 해결하지 못합니다. 이 경우에는 상품명·옵션명 같은 리뷰 외 메타데이터만으로 우선 유사도를 계산하고, 리뷰가 일정 수 쌓이면 자동으로 그 가중치를 높이는 방식의 보완이 필요하다고 생각하는데, 이 프로젝트 당시에는 거기까지는 설계하지 못했습니다."

## 6. 그 외 예상 꼬리질문 2가지

### 6-1. "정성평가 10명, 210건 비교로 Word2Vec이 더 낫다고 결론 내린 게 통계적으로 충분한가요?"

**모범답안**: "충분하다고 말씀드리긴 어렵습니다. 10명이라는 평가자 수는 작고, 유의성 검정을 거친 것도 아니라서, 0.8점과 1.2점의 차이가 우연한 평가자 편차 범위 안에 있을 가능성도 배제할 수 없습니다. 다만 두 모델이 같은 조건(같은 210건, 같은 평가자, 같은 척도)에서 비교됐다는 점에서 상대적 우위를 판단하는 참고 지표로는 의미가 있었고, 절대적으로 'Word2Vec이 확실히 낫다'는 통계적 증명이라기보다는 '제한된 리소스 안에서 더 나은 후보를 고르기 위한 실용적 비교'로 보는 게 정확합니다."

### 6-2. "세그먼트 기반 추천과 Word2Vec 유사상품 추천이 독립적인 기능이라면, 왜 둘 다 만들었나요? 하나로 통합하면 안 됐나요?"

**모범답안**: "두 기능이 푸는 문제 자체가 달랐기 때문입니다. 세그먼트 추천은 사용자가 홈 화면에 처음 들어왔을 때 '이 사람 그룹에게는 어떤 상품을 먼저 보여줄까'를 정하는 문제이고, Word2Vec 추천은 사용자가 이미 특정 상품에 반응(찜)을 보인 직후 '이것과 비슷한 걸 더 보여줄까'를 정하는 문제입니다. 전자는 그룹 단위의 초기 노출 순서 문제이고 후자는 개별 상품 단위의 실시간 연관 추천 문제라, 하나의 로직으로 통합하기보다 각자의 목적에 맞게 독립적으로 설계하는 게 더 명확하다고 판단했습니다."
