# 바이럴 커넥터 에이전트 — "실제 화제성"을 탐지하는 구체적 방법 2가지

> 작성 목적: "에이전트가 외부에서 실제로 화제가 되고 있는 걸 구체적으로 어떻게 탐지하는가"에 대한 질문에 답하기 위해, 실제 적용 가능한 탐지 방법 2가지를 구체적으로 설계
> 작성일: 2026-10-13
> 근거자료: `tving-chatbot-mvp-v2-interview-answer-revised.md`(바이럴 판단 기준 필요성 지적), `tving-chatbot-mvp-v2-selfdraft-critique-tailquestions.md`(꼬리질문 #3, #5)

## 핵심 요약 (두괄식)

"바이럴 여부"를 직접 SNS·커뮤니티를 크롤링해서 판단하는 방식은 플랫폼 약관 위반 리스크와 구현 난이도가 크므로, 실제로 적용 가능한 방법은 **① 네이버 데이터랩의 공식 검색어 트렌드 API로 특정 키워드의 검색량 급증을 탐지하는 방식**과 **② 이미 소셜 버즈 데이터를 라이선스로 수집·제공하는 소셜 리스닝 SaaS(예: 썸트렌드류 서비스)의 API를 구독해서 버즈량 지수를 받아오는 방식**입니다. 두 방법 모두 "직접 크롤링"이 아니라 **이미 합법적으로 수집·가공된 데이터를 API로 받아오는 방식**이라 법적 리스크가 낮고, 실제 구현 난이도도 현실적입니다.

---

## 공통 파이프라인 구조

```
① 키워드 세트 정의(배우명·작품명·테마 키워드)
     ↓
② 외부 데이터 소스에서 신호 수집 (검색량 또는 버즈량)
     ↓
③ 급상승 판정 로직 적용 (평소 대비 몇 배 이상 증가했는가)
     ↓
④ 임계치 초과 시 "바이럴 후보"로 플래그
     ↓
⑤ 티빙 카탈로그와 매칭 (현재 서비스 중인 작품만)
     ↓
⑥ 에디터 승인 후 홈 화면 카드로 노출
```

---

## 사례 1 — 네이버 데이터랩 "검색어 트렌드" API 기반 탐지

### 데이터 소스
- 네이버가 공식 제공하는 **데이터랩 검색어 트렌드 API**(무료, 신청制 공식 Open API)를 사용
- 특정 키워드(예: "진선규", "백일의 거짓말")의 기간별 상대 검색량 지수를 일 단위로 받아올 수 있음

### 급상승 판정 로직
- 모니터링 대상 키워드 세트(출연 배우명 + 작품명 조합)를 사전에 등록
- 최근 1일 검색량 지수를 과거 7~14일 평균 및 표준편차와 비교해, **평균 대비 2표준편차 이상 벗어나면** "급상승"으로 1차 플래그
- 간단한 대안으로는 "전주 동일 요일 대비 검색량 100% 이상 증가"처럼 더 직관적인 증가율 기준도 사용 가능

### 장점 / 한계
- 장점: 공식 API라 법적 리스크가 거의 없고, 비용도 무료에 가까워 MVP 단계에 적합
- 한계: 검색어 자체만으로는 "왜" 화제인지(배우의 연기력 때문인지 다른 이슈 때문인지) 알 수 없어, 최종 승인 전에는 사람이 실제 맥락(어떤 콘텐츠·반응 때문인지)을 확인하는 과정이 필요

---

## 사례 2 — 소셜 버즈 분석 SaaS(라이선스 기반) API 연동

### 데이터 소스
- 자체 크롤링 대신, 이미 트위터(X)·인스타그램·블로그·커뮤니티 등 여러 채널의 언급량을 합법적으로 수집·정제해서 제공하는 **소셜 리스닝 B2B 서비스**(국내에 이미 이런 버즈 분석 SaaS들이 존재)의 API를 구독
- 이런 서비스는 보통 "버즈량 지수", "감성 분석(긍정/부정)", "급등률" 같은 가공된 지표를 함께 제공

### 급상승 판정 로직
- 모니터링 키워드(배우명, 작품명)에 대해 **전일 대비 버즈량 증가율이 일정 임계치(예: 200% 이상)를 넘으면** 바이럴 후보로 플래그
- 감성 분석 점수가 함께 제공되므로, 부정적 이슈(논란)로 인한 급증과 긍정적 반응(연기력 호평 등)으로 인한 급증을 1차적으로 구분할 수 있음 — 이는 "자극적·선정적 콘텐츠도 그대로 노출하는가"라는 리스크 질문에도 대응 가능

### 장점 / 한계
- 장점: 직접 크롤러를 만들 필요가 없어 플랫폼 정책 위반 리스크를 피할 수 있고, 여러 채널을 한 번에 커버하며, 감성 분석까지 포함돼 있어 품질 필터링에 유리
- 한계: 외부 서비스 구독 비용이 발생하고, 해당 SaaS의 데이터 커버리지·신뢰도에 의존하게 됨

---

## 두 방법의 결합 전략 (MVP 단계 제안)

1. **1차 신호**: 네이버 데이터랩 검색어 트렌드(무료)로 넓게 모니터링해 "검색량이 튀는" 후보를 저비용으로 걸러냄
2. **2차 교차 검증**: 1차에서 걸러진 후보만 소셜 버즈 SaaS로 정밀 확인(원인·감성까지 확인) — 비용이 드는 2차 검증을 1차로 좁혀진 소수 후보에만 적용해 비용 효율화
3. **최종 승인**: 두 신호가 모두 임계치를 넘고, 티빙 카탈로그에 매칭되는 작품이 있을 때만 에디터 승인 단계로 전달

## 면접에서 말할 때 요약 문장

> "직접 SNS를 크롤링하기보다는, 네이버 데이터랩 검색어 트렌드 API처럼 공식적으로 제공되는 데이터로 1차 신호를 저비용으로 모니터링하고, 그 중 급상승한 후보만 소셜 버즈 분석 서비스로 2차 검증해서 원인과 감성까지 확인한 뒤 에디터 승인을 거치는 2단계 구조로 설계하고 싶습니다. 이렇게 하면 직접 크롤링에 따르는 법적 리스크 없이도 '실제 화제성'을 비용 효율적으로 탐지할 수 있습니다."
