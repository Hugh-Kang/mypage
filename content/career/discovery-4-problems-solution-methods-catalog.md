# 콘텐츠 발견 4대 문제 — 문제별 해결 방법론 카탈로그

> 작성 목적: `discovery-team-content-discoverability-problem-and-solutions.md`에서 정의한 4가지 문제(① 발견성 ② 매칭 ③ 쏠림/롱테일·콜드스타트 ④ 포장)별로, 추천 시스템·OTT 업계에서 일반적으로 쓰이는 해결 방법론을 폭넓게 조사해서 구조화
> 작성일: 2026-10-01
> 주의: 아래 방법론들은 **추천 시스템/OTT 업계에 일반적으로 알려진 기법**을 조사·정리한 것이며, 티빙이 실제로 이 중 무엇을 쓰고 있는지는 확인된 바 없습니다. 넷플릭스 개인화 썸네일처럼 공개적으로 잘 알려진 사례는 업계 사례로 인용했습니다.

## 0. 설계 프롬프트

> 너는 OTT 추천 시스템에서 발견성·매칭·쏠림·포장이라는 4가지 문제 각각에 대해, 업계에서 일반적으로 쓰이는 해결 방법론을 폭넓게 조사해서 구조화하는 리서처다. 각 방법론은 한 줄 설명과 함께, 가능하면 왜 그 문제에 효과적인지 근거를 짧게 덧붙여라. 티빙이 실제로 무엇을 쓰고 있는지는 확인된 바 없으므로 "이렇게 하면 효과적이라고 알려져 있다"는 식으로 서술하고, 티빙 내부 사실로 단정하지 마라.

## 1. 문제 ① 발견성(Discoverability) — 해결 방법론

| 방법론 | 설명 |
|---|---|
| 자연어/의미 기반 검색(Semantic Search) | 정확한 제목이 아니라 "우울할 때 볼만한 거" 같은 자연어 질의도 이해해서 결과를 반환 |
| 오타 허용·유사어 매칭 | 제목 철자가 틀려도, 다른 표현(별칭)으로 검색해도 원하는 콘텐츠를 찾을 수 있게 함 |
| 세분화된 메타데이터/태깅 | 장르뿐 아니라 무드·분위기·테마·키워드까지 세밀하게 태깅해서 필터·검색 정확도를 높임 |
| 테마별/장르별 브라우징 페이지 | "스릴러만 모아보기", "이번 주말 몰아보기 좋은 작품" 같은 탐색 전용 큐레이션 페이지 |
| 에디토리얼 큐레이션 | 운영자가 직접 "숨은 명작" 등 주제별 목록을 선별해서 노출 — 알고리즘이 놓친 콘텐츠를 사람이 보완 |
| 연관 콘텐츠 안내 | 시청 직후 "같은 감독/배우의 다른 작품", "세계관이 연결된 작품"을 바로 안내 |
| 관심 태그 구독 알림 | 사용자가 특정 배우·장르·시리즈를 구독해두면 신작 출시 시 능동적으로 알림 |
| 대화형 탐색 에이전트 | 사용자가 명확히 원하는 바를 모를 때 대화로 좁혀가며 발견을 돕는 기능(이 세션에서 이미 단계적 검증 전제로 설계한 바 있음) |
| 짧은 미리보기 제공 | 호버 시 자동 재생되는 짧은 트레일러 클립으로, 탐색 중 빠르게 판단할 수 있게 지원 |

## 2. 문제 ② 매칭(Relevance) — 해결 방법론

| 방법론 | 설명 |
|---|---|
| 협업 필터링(Collaborative Filtering) | 비슷한 시청 패턴을 가진 사용자들이 함께 본 콘텐츠를 추천 |
| 콘텐츠 기반 필터링(Content-based Filtering) | 콘텐츠의 메타데이터·줄거리 임베딩 유사도를 기반으로 추천 |
| 하이브리드 추천 | 협업 필터링과 콘텐츠 기반을 결합해 각각의 약점(콜드스타트, 과도한 유사성)을 상호 보완 |
| 암묵적 행동 신호 확대 반영 | 평점 같은 명시적 데이터뿐 아니라, 시청 완료율·중도 이탈 지점·재시청·스킵 여부까지 추천 신호로 활용 |
| 세션 기반 추천(Session-based Recommendation) | 그날그날의 맥락(오늘 뭘 보고 있었는지)을 반영해 실시간으로 추천을 조정 |
| 프로필별 추천 분리 | 가족 계정 내 여러 프로필의 시청 패턴을 분리해서 서로 다른 취향이 섞이지 않게 함 |
| 명시적 선호 수집 강화 | 온보딩 설문, "싫어요" 버튼 등으로 네거티브 피드백까지 적극적으로 수집 |
| 컨텍스트 인식 추천 | 시간대(주말 몰아보기 vs 평일 저녁), 디바이스(모바일 vs TV)에 따라 다른 추천 로직 적용 |
| 지속적 A/B 테스트 기반 모델 튜닝 | 추천 모델을 한 번 배포하고 끝내는 게 아니라, 지속적으로 실험하며 가중치·피처를 튜닝 |

## 3. 문제 ③ 쏠림(롱테일/콜드스타트) — 해결 방법론

| 방법론 | 설명 |
|---|---|
| 탐색-활용 알고리즘(Explore-Exploit, 예: Multi-armed Bandit) | 확실히 좋은 인기 콘텐츠(활용)만 계속 보여주지 않고, 일정 비율은 새로운/불확실한 콘텐츠(탐색)에 트래픽을 할당 |
| 추천 목적함수에 다양성 명시적 반영 | 정확도만이 아니라 "커버리지"(얼마나 다양한 콘텐츠가 노출됐는지)를 추천 알고리즘의 평가 지표·목적함수에 함께 포함 |
| 세렌디피티(의외성) 전용 슬롯 | "당신이 평소 안 볼 것 같지만 추천하는" 전용 섹션을 별도로 운영해 새로운 취향 발견을 유도 |
| 콜드스타트 콘텐츠의 메타데이터 기반 초기 추천 | 신작은 아직 행동 데이터가 없으니, 메타데이터 유사도로 기존 인기작과 비슷하면 초기에 추천 후보로 포함 |
| 신작 전용 노출 슬롯/알림 | 신작이 나왔을 때 일정 기간 동안 보장된 노출 영역을 배정 |
| Growth 캠페인과 연계한 초기 트래픽 확보 | 신작 출시 시 알림·이벤트로 초기 시청자를 인위적으로 확보해, 추천 알고리즘이 학습할 데이터를 빠르게 쌓게 함 |
| 콘텐츠 재조명 큐레이션 | 과거작을 시즌·이슈에 맞춰 재발굴(예: 특정 배우가 화제될 때 그 배우의 과거작을 다시 노출) |
| 콘텐츠 수명주기 관리 | 신작·인기작·장기 보유작 등 단계별로 서로 다른 노출 전략을 적용해 전체 카탈로그 활용을 관리 |

## 4. 문제 ④ 포장(썸네일/설명) — 해결 방법론

| 방법론 | 설명 |
|---|---|
| 개인화 썸네일 | 같은 콘텐츠라도 사용자 취향(액션 선호/로맨스 선호 등)에 따라 다른 이미지를 노출 — 넷플릭스가 공개적으로 소개한 바 있는 업계에 잘 알려진 사례 |
| 썸네일 A/B 테스트 자동화 | 여러 썸네일 후보를 자동으로 테스트하고, 성과가 좋은 이미지를 자동 채택하는 운영 체계 |
| 개인화된 시놉시스/카피 | 같은 작품도 사용자 취향에 따라 강조하는 문구를 다르게 구성(예: 액션 팬에게는 액션 요소 강조) |
| 하이라이트 클립 자동 생성 | 전체를 다 안 봐도 매력을 느낄 수 있도록 명장면을 자동으로 추출해 짧은 클립으로 제공 |
| 신뢰 신호 노출 | 평점·리뷰·한줄평처럼 제3자 신호를 함께 보여줘 클릭 결정을 보조 |
| 포장 정확성 가드레일 | 과장된 포장으로 클릭만 유도하는 것을 방지하기 위해, 클릭 후 이탈률·시청완료율을 함께 모니터링하는 가드레일 지표 운용 |

## 5. 종합 — 문제별 "가장 먼저 시도해볼 만한 것" 한 가지씩

| 문제 | 가장 먼저 시도해볼 만한 방법 | 이유 |
|---|---|---|
| ① 발견성 | 연관 콘텐츠 안내(시청 직후 추천) | 이미 있는 시청 완료 시점 UI에 붙이는 것이라 구현 비용이 낮고, 효과(클릭률) 측정도 즉시 가능 |
| ② 매칭 | 암묵적 행동 신호 확대 반영 | 기존 추천 알고리즘의 입력 피처만 늘리는 점진적 개선이라, 이 세션에서 이미 확립한 "기존 알고리즘 먼저 개선" 원칙과 가장 잘 맞음 |
| ③ 쏠림 | 콜드스타트 콘텐츠의 메타데이터 기반 초기 추천 | 복잡한 bandit 알고리즘보다 구현이 단순하면서도, 신규 콘텐츠 노출 부족이라는 가장 시급한 하위 문제를 먼저 완화 |
| ④ 포장 | 썸네일 A/B 테스트 | 투자 대비 가장 빠르고 확실하게 CTR 개선을 검증할 수 있는 항목(앞서 ROI 분석에서도 1순위로 확인됨) |
