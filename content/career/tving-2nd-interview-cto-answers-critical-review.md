# 실제 2차 면접 — CTO 질문 중 아쉬웠던 답변 정리

> 작성 목적: 2026-10-20 실제 2차 면접에서 CTO가 던진 질문들 중, 돌이켜봤을 때 답변이 아쉬웠던 부분을 비판적으로 재검토하고 개선 방향을 정리
> 작성일: 2026-10-21
> 근거자료: `tving-2nd-interview-actual-2026-10-20-structured.md`

## 핵심 요약 (두괄식)

가장 아쉬웠던 지점은 **CTO가 "왜 이 기능이 아직 적용 안 됐다고 생각하는가"를 물었을 때, 진짜 이유(자체 LLM 부재, 메타데이터 미비, 비용 구조, ROI 불확실성)를 스스로 짚지 못하고 "아직 문제로 인식 안 됨, 시기가 안 옴"이라는 추상적인 답을 한 것**입니다. 이후 CTO가 질문을 세 번이나 더 구체화해가며 메타데이터·서빙 비용 문제를 직접 끄집어냈다는 것 자체가, 처음 답변이 CTO가 원하는 깊이에 못 미쳤다는 신호입니다. 이 패턴(질문의 기술적 핵심을 바로 짚지 못하고, 면접관이 여러 번 구체화해야 답이 나옴)이 이번 CTO 질문들에서 반복적으로 나타났습니다.

---

## 아쉬웠던 답변 Top 4

### 1. "그 기능이 왜 아직 적용 안 되고 있을까요?" (가장 아쉬움)

**실제 답변**: "아직은 그게 문제가 되지 않아서라고 생각해요... 챗봇 에이전트까지 추천 알고리즘을 활용하기엔 아직 시기가 오지 않았다."

**무엇이 아쉬운가**: 이 질문은 사실 CTO가 뒤이어 직접 보여준 **진짜 이유들**(① 티빙은 자체 LLM이 없어 외부 모델 의존, ② 콘텐츠·사용자 반응에 대한 메타데이터가 아직 정리되지 않음, ③ 영상을 매번 모델에 먹이면 비용·트래픽·응답지연이 커짐)을 미리 짚어낼 수 있는지를 떠보는 질문이었습니다. "아직 문제로 인식 안 됐다"는 답은 틀린 말은 아니지만, **PM이라면 당연히 알아야 할 기술·비용 제약을 스스로 거론하지 못했다**는 인상을 줬을 수 있습니다.

**개선 방향**: "아직 OTT 업계 전반에서 수요가 명확해지지 않은 것도 있지만, 기술적으로도 자체 LLM 없이 외부 모델에 의존해야 하고, 콘텐츠에 대한 메타데이터가 충분히 쌓이지 않으면 비용·응답속도 측면에서 쉽지 않은 문제라고 생각합니다"처럼, **질문이 유도하는 다음 단계(기술적 제약)를 먼저 선점해서 언급**했어야 합니다.

### 2. "그러면 쉽게 해결하지 못하는 문제가 될까요?" (LLM 아키텍처 질문)

**실제 답변**: (질문을 한 번에 이해 못해 되물음) → "사용자 행동 데이터를 확실하게 수집하고 그걸 어떻게 활용할지 정리하는 게 1차 단계"

**무엇이 아쉬운가**: CTO의 질문은 "인터페이스는 쉽게 해결되는데, 콘텐츠 분석→사용자 피드백→추천 모델 반영까지의 파이프라인은 뭘 해야 하는가"라는 구체적 질문이었는데, 답변은 "사용자 행동 데이터 수집"이라는 **원론적 수준**에 머물렀습니다. 그 결과 CTO가 "사용자 데이터가 있다면?", "그 레벨의 디테일한 장면(김성규 일본어 대사)을 어떻게 알아볼 수 있을까요?"라고 **질문을 세 번이나 더 구체화**해야 비로소 메타데이터·서브타이틀 활용이라는 핵심 답이 나왔습니다.

**개선 방향**: 질문을 받자마자 "콘텐츠 자체에 대한 메타데이터(장면 단위 태깅, 서브타이틀)가 핵심"이라는 결론을 먼저 제시한 뒤, "그걸 위한 데이터 수집이 1차 단계"로 이어갔어야 CTO가 추가로 캐묻지 않아도 됐을 것입니다.

### 3. "그 장면을 어떻게 알아볼 수 있을까요?" — 메커니즘 설명 미완성

**실제 답변**: "에이전트를 활용하면 좋을 것 같아요... 바이럴되는 구간을 에이전트가 1차 파악하고, 사람이 중간에 개입해서 승인"

**무엇이 아쉬운가**: "에이전트가 파악한다"는 결론만 말하고, **그 에이전트가 무슨 데이터를 보고 파악하는지**(서브타이틀/채팅 로그)는 바로 다음 질문(영상 데이터를 다 줘야 하냐는 질문)에서야 나왔습니다. 즉 답변이 한 단계 앞서 나가지 못하고, 매번 CTO의 추가 질문에 끌려가는 모양새가 됐습니다.

**개선 방향**: "에이전트가 채팅 로그나 서브타이틀 같은 텍스트 데이터를 기반으로 바이럴 구간을 1차로 좁히고, 사람이 최종 승인하는 방식"이라고 **데이터 소스까지 한 번에** 답했으면 훨씬 매끄러웠을 것입니다.

### 4. "티빙에서 개선하고 싶은 다른 기능" — 알림 기능 설명의 장황함

**실제 답변**: 알림 기능이 아쉬웠다는 취지였으나, "예전에 팬톡이 없어서 단톡을 팠었다", "그걸 티빙으로 가져오면 선순환이 이루어지지 않을까"처럼 **논리적 연결이 매끄럽지 않은 설명**이 이어졌습니다.

**무엇이 아쉬운가**: 핵심 주장("같이 보기를 유도하는 알림·공유 기능이 아쉽다")과 뒷받침 경험(과거 단톡방 운영)이 분리되지 않고 뒤섞여, 듣는 입장에서 결론을 파악하기 더 어려웠을 수 있습니다. 이는 이전 모의면접들에서도 반복 지적됐던 "장황함·급격한 전환" 패턴과 동일한 유형입니다.

**개선 방향**: "본방 사수를 유도하는 공유·알림 기능이 아쉬웠습니다. 예를 들어 예전에는 팬톡이 없어서 따로 단톡방을 만들어 '같이 보자'고 얘기했는데, 이런 상호작용을 티빙 안에서 할 수 있다면 더 좋을 것 같습니다"처럼 **결론을 먼저 말한 뒤 경험으로 뒷받침**하는 순서가 더 명확합니다.

## 전체 패턴 정리

네 가지 모두 **"질문이 원하는 한 단계 더 깊은 답을 먼저 제시하지 못하고, 면접관이 추가로 캐물어야 핵심이 나온다"**는 공통된 패턴입니다. 이는 실력이 없어서가 아니라(실제로 메타데이터·서브타이틀 아이디어는 다 가지고 있었음), **질문을 받았을 때 "이 질문의 다음 단계가 뭘까"를 먼저 예측하고 답변 순서를 설계하는 습관**이 조금 더 필요하다는 신호로 보입니다.
