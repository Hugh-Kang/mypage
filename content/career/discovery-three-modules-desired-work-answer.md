## 0. 설계 프롬프트

> 너는 Discovery팀의 세 모듈 각각에 대해 "하고 싶은 업무"를 묻는 질문에, 이 세션에서 이미 정리된 4대 문제(발견성·매칭·쏠림·포장)와 ROI 분석, 해결 방법론, 챗봇/에이전트 단계적 적용 논의를 모듈별로 재배치해서 답하라. 각 모듈마다 "어떤 문제에서 출발해서, 어떤 지표를 개선하고, 어떤 기능을 설계해서, 구체적으로 어떤 방안을 쓸 것인가"의 순서로 답하고, 마지막엔 면접에서 바로 말할 수 있는 압축된 스크립트를 덧붙여라.

## 1. 모듈 ① 메인홈 / AI 챗봇 에이전트 서비스 기획, 전체 서비스 구조 설계

| 단계 | 내용 |
|---|---|
| 문제정의 | **발견성 문제** — 좋은 콘텐츠가 있어도 사용자가 그 존재를 모르거나, 탐색 마찰 때문에 찾는 과정에서 이탈 |
| 개선하려는 지표 | 검색 성공률(검색 후 클릭률), 체류시간, 카탈로그 활용 폭(얼마나 다양한 콘텐츠가 실제로 시청되는지) |
| 설계할 기능 | 대화형 탐색 기능을 메인홈에 결합 — 다만 처음부터 완전한 에이전트가 아니라, 검증 단계를 거쳐 단계적으로 자율성을 높이는 구조 |
| 구체적 방안 | 1단계로 "이 배우 나온 다른 작품 뭐있어?" 같은 질문에 메타데이터를 검색해 답하는 RAG 기반 챗봇부터 시작하고, 2단계로 "더 가벼운 거 없어?" 같은 다중 턴 대화로 사용자가 직접 좁혀나가게 하고, 실행까지 필요한 근거가 쌓이면 3단계로 에이전트가 스스로 검색·추천 도구를 반복 호출하며 사용자 반응을 관찰해 제안을 조정하는 구조로 확장하겠습니다. |

**면접용 답변**:
> "저는 메인홈·챗봇 영역에서는 '좋은 콘텐츠가 있어도 발견되지 못하는' 발견성 문제를 풀고 싶습니다. 검색 성공률과 체류시간을 핵심 지표로 보고, 대화형 탐색 기능을 메인홈에 결합하고 싶습니다. 다만 처음부터 완전한 에이전트를 만들기보다, 먼저 메타데이터 기반 RAG 챗봇으로 명확한 질문에 정확히 답하는 것부터 시작하고, 다중 턴 대화로 좁혀나가는 단계를 거쳐, 실행 근거가 쌓이면 에이전트가 자율적으로 검색·제안을 반복하는 구조로 단계적으로 확장하고 싶습니다."

## 2. 모듈 ② 검색 / 추천 / Push / 배너 / Growth 모듈

| 단계 | 내용 |
|---|---|
| 문제정의 | **매칭 문제**(인기는 있어도 취향에 안 맞음) + **쏠림 문제**(인기작만 노출되어 잠재적 취향 콘텐츠가 노출 기회를 못 받음) |
| 개선하려는 지표 | 매칭: CVR(클릭→시청), 시청완료율, 재방문율 / 쏠림: 카탈로그 커버리지, 신작 초기 시청 획득 속도 |
| 설계할 기능 | 기존 추천 알고리즘에 암묵적 행동 신호(시청완료율·이탈지점·재시청)를 추가하는 점진적 개선, 신작·롱테일 전용 노출 슬롯, 시즌 종료 등 이탈 신호 기반 리텐션 Push, 배너 개인화 |
| 구체적 방안 | 추천 알고리즘은 완전히 새로 만들지 않고 기존 로직에 행동 신호를 추가하는 방식으로 먼저 개선하고, 콜드스타트 콘텐츠는 메타데이터 유사도로 초기 추천 후보에 포함시키고, KBO 시즌 종료처럼 이탈 경향이 보이는 시점에 맞춰 Push로 다음 콘텐츠를 미리 안내하고, 배너는 소수 대작에 고정되지 않도록 개인화하겠습니다. 롱테일 노출 비율을 높일 때는 CTR·CVR과 상충할 수 있다는 걸 감안해 가드레일 지표를 함께 모니터링하겠습니다. |

**면접용 답변**:
> "검색·추천·Push·배너·Growth 모듈에서는 두 가지 문제를 풀고 싶습니다. 하나는 인기 콘텐츠인데도 그 사용자 취향과 안 맞는 매칭 문제이고, 다른 하나는 인기작만 노출되어 잠재적으로 취향에 맞을 콘텐츠가 노출 기회조차 못 받는 쏠림 문제입니다. 매칭은 CVR과 시청완료율을, 쏠림은 카탈로그 커버리지와 신작 초기 시청 속도를 지표로 보고 싶습니다. 구체적으로는 기존 추천 알고리즘에 시청완료율 같은 행동 신호를 추가하는 점진적 개선부터 하고, 신작은 메타데이터 유사도로 초기 추천에 포함시키고, 시즌 종료 같은 이탈 신호에 맞춰 Push로 다음 콘텐츠를 안내하고, 배너도 소수 대작에 쏠리지 않게 개인화하겠습니다. 다만 쏠림을 해소하려고 다양성을 높이면 단기적으로 CVR이 떨어질 수 있어서, 가드레일 지표를 함께 보면서 점진적으로 조정하겠습니다."

## 3. 모듈 ③ A/B Test Platform, 커뮤니케이션·메시지 서비스

| 단계 | 내용 |
|---|---|
| 문제정의 | **검증 인프라 부재 문제** — 발견성·매칭·쏠림·포장 문제에 대한 개선안이 아무리 많아도, 이를 일관되고 신뢰할 수 있게 검증할 표준 실험 체계가 없으면 각 팀이 매번 다른 방식으로 검증해서 신뢰도가 떨어지고, 개인화 메시지도 피로도 관리 없이 발송되면 오히려 이탈을 유발할 수 있음 |
| 개선하려는 지표 | 실험의 통계적 신뢰도(무작위 배정·공변량 균형), 포장(④) 문제 해결의 핵심 지표인 CTR·CVR의 검증 정확도, 메시지 피로도(알림 차단율·수신 거부율) |
| 설계할 기능 | A/B Test Platform(실험 설계·배정·모니터링·거버넌스 4단계 구조), 개인화 메시지 큐레이션 + 피로도 가드레일 |
| 구체적 방안 | 포장 문제 해결의 핵심 수단인 썸네일 A/B 테스트를 이 플랫폼의 표준 실험 템플릿으로 우선 구축하고, 무작위 배정과 실험 간 트래픽 격리를 플랫폼이 자동 보장하게 하고, 개인화 메시지는 발송 전 가드레일(과도한 알림 빈도 제한)을 걸어 운영하겠습니다. |

**면접용 답변**:
> "A/B Test Platform·커뮤니케이션 모듈에서는, 다른 모듈에서 아무리 좋은 개선안을 내도 그걸 신뢰할 수 있게 검증할 표준 체계가 없으면 소용없다는 문제의식에서 출발하고 싶습니다. 특히 포장 문제처럼 썸네일 A/B 테스트가 핵심 해법인 영역은 이 플랫폼이 표준 실험 템플릿을 갖추는 게 중요하다고 생각합니다. 무작위 배정과 실험 간 트래픽 격리를 플랫폼이 자동으로 보장하는 걸 가장 먼저 만들고 싶고, 개인화 메시지도 발송 전에 피로도 가드레일을 걸어서 운영하고 싶습니다."

## 4. 세 모듈이 어떻게 연결되는지 (종합, 후속 질문 대비)

> "세 모듈은 따로 노는 게 아니라 하나의 흐름으로 연결됩니다. ①메인홈/챗봇에서 발견성을, ②검색·추천·Push·배너에서 매칭과 쏠림을 풀고, 그 모든 개선이 실제 효과가 있는지는 ③A/B Test Platform이 검증합니다. 그리고 이 세 모듈에서 제가 공통적으로 지키고 싶은 원칙은, 화려한 기술(챗봇·에이전트)을 먼저 들이미는 게 아니라 문제와 지표를 먼저 검증하고, 가장 적은 투자로 빠르게 확인 가능한 것부터 순서대로 접근하는 것입니다."
