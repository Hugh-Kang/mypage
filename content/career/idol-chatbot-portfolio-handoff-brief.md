## 프로젝트 한 줄 요약

마인드로직(아이돌 챗봇 플랫폼 'A2Z' 담당)에서, 버블식 1:多 메시지 구조의 비개인화 한계를 풀기 위해 아이돌 페르소나 챗봇을 설계했고, 출시 후 발견된 "대화 몰입도 저하" 문제를 분석해 "아티스트만의 실시간 정보 제공"이라는 솔루션으로 전환, AB테스트(100명·5일)로 만족도 30%·대화참여도 25% 향상을 검증했습니다.

---

## 1. 배경

- 버블은 아이돌 1명이 다수의 팬에게 동일 메시지를 보내는 1:多 구조의 소통 플랫폼
- 팬 입장에서는 1:1 DM처럼 느껴지지만, 실제로는 모든 구독자에게 동일한 메시지가 발송되는 구조적 한계가 있음
- 이 한계(개인화된 메시지 제공 불가)를 보완하기 위한 대안으로 아이돌 페르소나 챗봇이 기획됨

## 2. 문제 정의 (1차 → 2차)

| 단계 | 문제 | 비고 |
|---|---|---|
| 1차(배경 문제) | 버블의 1:多 구조로는 팬 개개인에게 맞춘 개인화 메시지를 줄 수 없음 | 챗봇 기획의 출발점 |
| 2차(출시 후 발견된 문제) | 챗봇 출시 후, 사용자들이 챗봇과의 대화를 꾸준히 이어가지 못함(몰입도 저하) | 18~20명 정성 인터뷰 + 채팅 로그 교차검증으로 원인 파악 |

- 2차 문제의 원인: 대화 주제가 지나치게 일반적이었음(인터뷰·로그 양쪽에서 공통 확인)
- 인터뷰 표본(18~20명)의 한계: 주 사용자층이 10대 여성(미성년자)이라 보호자 동의 등 모집 제약이 있어 현실적 최대 규모였음. 이후 정량 검증(AB테스트, 100명)으로 보완하는 2단계 설계 사용

## 3. 가설

> **가설**: 아티스트만이 줄 수 있는 실시간 정보(스케줄, 생각, 식사 등 일상 에피소드)를 대화 주제로 제공하면, 사용자의 몰입도와 대화 지속성이 높아질 것이다.

- 솔루션 설계에는 대화 주제 전환 외에, 챗봇의 "진정성(authenticity)" 문제를 보완하는 장치도 포함됨
  - 장치 ①: AI 챗봇임을 숨기지 않되 "아이돌이 직접 만든 챗봇"이라는 서사로 설득(원리를 이해할수록 수용도가 높아진다는 점 활용)
  - 장치 ②: 실시간 정보 제공 자체가 "이 챗봇만이 줄 수 있는 가치"라는 인식을 형성해, 모방이 아닌 보완적 채널로 수용되게 함

## 4. 검증 설계

| 항목 | 내용 |
|---|---|
| 비교 대상 | 기존 챗봇(일반 대화 주제) vs 개선된 챗봇(실시간 정보 중심 대화) |
| 실험군·대조군 규모 | 100명 |
| 실험 기간 | 5일 |
| 측정 지표 1 | 만족도 — 10점 척도 설문("대화가 가치있었다", "대화가 기다려진다" 등 복수 문항) |
| 측정 지표 2 | 대화참여도 — Interaction Cue(대화 총 단어 수), Linguistic Cue(인지적 과정 반영 단어 사용 빈도, 예: because·think·remind) |

- 자기개방 깊이(self-disclosure depth) 같은 일부 후보 지표는 유의미한 차이가 없어 폐기 — 측정 난이도와 실험기간(5일)의 한계로 추정

## 5. 결과 (성과 수치)

| 지표 | 결과 |
|---|---|
| 만족도 | 30% 향상 |
| 대화참여도 — Interaction Cue | 25% 향상 |
| 대화참여도 — Linguistic Cue | 25% 향상 |
| 비즈니스 연결 | 메시지 건수 과금 구조 → 대화참여도 향상이 곧 매출 임팩트로 해석됨. 단, LLM API 비용 구조상 챗봇 자체 마진은 낮아 굿즈 샵 기능과 연계해 보조 수익모델로 설계 |

## 6. 이 경험을 "PMF를 찾은 경험"으로 서술할 때의 핵심 논리

- 문제의식(버블의 비개인화 한계)은 프로젝트 이전부터 존재했지만, **그 문제를 실제로 풀어내는 구체적 솔루션의 형태(실시간 정보라는 대화 주제)는 검증되지 않은 상태**였음
- 정성 탐색 → 데이터 교차검증(인터뷰+채팅로그) → 솔루션 설계(주제 전환+진정성 장치) → 정량 검증(AB테스트) → 비즈니스 연결(굿즈 수익모델)이라는 단계를 거쳐 **"무엇이 실제로 작동하는가"를 처음 발견**했다는 점에서 솔루션 레벨의 PMF 발견 서사로 서술 가능

## 7. 포트폴리오 작성 시 참고 — 제안 구성 순서

1. 배경·문제(버블의 구조적 한계 → 챗봇 기획)
2. 1차 가설과 출시
3. 출시 후 발견된 2차 문제(몰입도 저하)와 조사 과정(정성+정량 교차검증)
4. 2차 가설(실시간 정보 중심 대화) 및 솔루션 설계(진정성 장치 포함)
5. 검증 설계와 결과(수치 포함)
6. 비즈니스 임팩트 및 한계(수익모델 보완)
7. 배운 점 / 다음에 보완하고 싶은 지표(자기개방 깊이 폐기 사례 등)
