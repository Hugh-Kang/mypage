# C레벨·팀장·실무진 소통 방법 — 예시 답변

> 작성 목적: "C레벨/팀장/실무진을 설득하는 방법"에 대한 질문에 대비해, 피드백받은 내용(C레벨에게는 더 요약하고, 강점과 우려사항을 수치화해서 전달력을 높인다)을 반영한 답변 구성
> 작성일: 2026-10-16
> 근거자료: `tving-2nd-interview-question-bank-gap-analysis.md`(해당 질문 "부분 준비" 상태로 플래그), 모의면접 중 받은 피드백

## 핵심 요약 (두괄식)

핵심 원칙은 **"상대방의 의사결정 범위에 맞춰 정보의 추상화 수준을 다르게 전달한다"**는 것입니다. C레벨에게는 **성과와 리스크를 수치로 압축한 한두 줄**, 팀장에게는 **정책의 근거와 우선순위까지 포함한 중간 디테일**, 실무진에게는 **실제 구현에 필요한 세부 스펙**까지 전달하는 식으로 깊이를 조절합니다.

## 면접용 답변 (그대로 말하기 용)

> "저는 상대방이 어떤 결정을 내려야 하는 사람인지에 따라 전달하는 정보의 깊이를 다르게 가져갑니다.
>
> C레벨에게 보고할 때는 배경 설명을 길게 하기보다, **강점이 되는 성과와 우려되는 리스크를 각각 수치로 압축해서 한두 줄로 먼저 제시**합니다. 예를 들어 EV 충전구역 추천을 고도화했을 때, 'CTR이 7%포인트 개선돼 25%가 됐고, 다만 이 개선은 아직 즐겨찾기 등록자(전체의 15%)에게만 적용된 상태라 나머지 85% 사용자에 대한 확장 검증이 필요하다'는 식으로, **결과와 다음 의사결정 포인트를 동시에 숫자로 전달**합니다. C레벨은 디테일보다 '이게 어느 정도 임팩트가 있고, 지금 무엇을 결정해줘야 하는지'를 빠르게 판단해야 하기 때문입니다.
>
> 팀장에게는 그 수치가 나온 배경, 즉 '왜 이 정책을 선택했는지'까지 포함해서 전달합니다. 예를 들어 '즐겨찾기 집단의 CTR이 비등록 집단보다 5배 높았고, 그중 85%가 동일 구역을 반복 사용한다는 패턴을 근거로 우선순위를 바꿨다'는 식으로, 의사결정의 논리까지 보여드립니다.
>
> 실무진(개발자·데이터 엔지니어)에게는 실제 구현에 필요한 세부 사항까지 전달합니다. 예를 들어 제휴 쿠폰 기능을 추가할 때는 API 연동 문서를 먼저 검토해서, 필요한 API 키·암호화 키·테스트 서버 환경까지 미리 정리해 기획 문서에 포함시켜 전달했습니다.
>
> 즉 같은 프로젝트라도 'C레벨에게는 숫자로 압축된 성과와 리스크', '팀장에게는 의사결정의 근거', '실무진에게는 구현 가능한 스펙'으로 정보의 단위를 다르게 가져가는 것이 제 소통 방식입니다."

## 핵심 키워드 체크리스트

1. **원칙 먼저 선언**: "상대의 의사결정 범위에 맞춰 정보 깊이를 조절한다"
2. **C레벨 사례**: 성과(CTR 7%p)+리스크(확장 전 검증 필요)를 숫자로 압축한 한두 줄
3. **팀장 사례**: 수치의 배경 근거(5배 차이, 85% 반복사용 패턴)
4. **실무진 사례**: API 키·테스트 환경 등 구현 스펙까지 준비(이미 포트폴리오에 있는 제휴쿠폰 사례 재사용)
