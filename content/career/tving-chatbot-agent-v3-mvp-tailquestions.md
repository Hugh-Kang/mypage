# 통합 챗봇 에이전트(V3) MVP 범위 — 예상 꼬리질문

> 작성 목적: `tving-chatbot-agent-v3-combined-problem-definition-mvp-segment.md`에서 설계한 MVP(고려 단계 사용자 + 팬톡 리뷰 기반 스포일러 방지 요약)를 기준으로, 2차 면접에서 나올 만한 꼬리질문과 대비 포인트 정리
> 작성일: 2026-10-16
> 근거자료: `tving-chatbot-agent-v3-combined-problem-definition-mvp-segment.md`, `tving-chatbot-agent-v3-interview-answer-short.md`

## 핵심 요약 (두괄식)

이 MVP는 세그먼트 정의의 정밀도, 팬톡 리뷰 데이터의 품질(콜드스타트·악성 리뷰), 스포일러 판별의 완성도, 그리고 "이미 보려던 사용자에게 보여준 것뿐 아니냐"는 증분 효과 의심이라는 네 축에서 꼬리질문이 집중될 가능성이 높습니다. 아래는 주제별 예상 질문과 대비 포인트입니다.

## 1. 세그먼트 정의/측정 관련

| 예상 질문 | 대비 포인트 |
|---|---|
| "상세페이지 진입 또는 찜 후 24시간"이라는 기준은 왜 24시간인가요? 더 짧거나 길면 안 되나요? | 24시간은 예시 기준이며, 실제로는 과거 데이터에서 "상세페이지 진입 후 시청 시작까지 걸리는 시간 분포"를 분석해 중간값 근처로 설정하는 것이 맞다고 답변 — 즉 고정값이 아니라 데이터 기반으로 캘리브레이션할 변수임을 분명히 함 |
| 단순히 보관함 용도로 찜만 해두고 볼 생각이 없는 사용자와, 정말 "볼까 말까 고민 중인" 사용자를 어떻게 구분하나요? | 상세페이지 재방문 횟수, 예고편·쇼츠 시청 여부 등 "관심 강도 신호"를 추가로 조합해 고민 단계에 가까운 사용자만 좁히는 2차 필터링을 추가한다고 답변 |
| 우연히 클릭만 하고 전혀 볼 생각이 없는 사용자에게도 노출되면 효과가 희석되지 않나요? | 바로 그 이유로 찜/관심 등록처럼 좀 더 명확한 의도 신호가 있는 사용자부터 좁혀서 시작하고, 단순 클릭만 한 사용자는 2차 확장 대상으로 미룬다고 답변 |

## 2. 팬톡 리뷰 데이터 품질/리스크 관련

| 예상 질문 | 대비 포인트 |
|---|---|
| 신작이라 팬톡에 리뷰가 아직 충분히 쌓이지 않은 작품은 어떻게 하나요? | 리뷰 수가 최소 임계치 미만이면 이 기능 자체를 노출하지 않고 기존 추천 방식으로 폴백한다는 조건을 추가해 콜드스타트 문제를 통제한다고 답변 |
| 부정적인 리뷰가 많은 작품은 그대로 요약해서 보여주나요? 마케팅 목적과 충돌하지 않나요? | 요약은 "사실 기반 화제성"에 초점을 맞추고, 노골적으로 부정적인 리뷰를 강조하지 않되 반응 자체를 왜곡하지는 않는 선에서 균형을 잡아야 하며, 이 기준 자체도 콘텐츠 운영팀과 협의가 필요한 정책 설계 영역이라고 답변 |
| 악의적이거나 도배성인 리뷰가 섞여 있으면 어떻게 걸러내나요? | 1차적으로 기존에 운영 중인 어뷰징·스팸 필터링 로직(있다면)을 재사용하고, 그 위에 리뷰 품질(좋아요 수, 길이 등) 기준으로 상위 리뷰만 요약 대상으로 삼는다고 답변 |

## 3. 스포일러 판별 완성도 관련

| 예상 질문 | 대비 포인트 |
|---|---|
| 결말 키워드 기반 규칙 필터링으로는, 명시적 키워드 없이 암시적으로 스포일러가 되는 리뷰는 못 거르지 않나요? | 맞는 지적이라고 인정하고, MVP는 보수적인 규칙 기반으로 "놓치는 것(재현율)"보다 "잘못 내보내는 것(정밀도)"을 우선 방지하는 데 집중하며, 이후 LLM 기반 판별로 재현율을 높이는 2단계 고도화를 계획한다고 답변 |
| 너무 보수적으로 필터링하면 요약할 내용이 하나도 안 남는 경우는 어떻게 하나요? | 필터링 후 남는 리뷰가 최소 기준 미만이면 해당 작품에는 이 기능을 노출하지 않고 기존 방식으로 폴백한다고 답변 |

## 4. UX/형태 관련 (이전 피드백과 연결)

| 예상 질문 | 대비 포인트 |
|---|---|
| 이것도 "챗봇"인가요, 아니면 자동으로 뜨는 카드인가요? | 사용자가 질문하지 않아도 해당 작품 페이지나 알림을 통해 선제적으로 노출되는 카드 형태이며, "챗봇"이라는 대화형 UI가 아니라 에이전트가 자동 생성한 요약 정보임을 명확히 구분해서 답변 |
| 사용자가 원치 않는데 넛지가 반복되면 스팸처럼 느껴지지 않을까요? | 동일 사용자·동일 작품에 대해 일정 기간 내 1회만 노출하고, 사용자가 닫거나 무시하면 해당 작품에 대해서는 재노출하지 않는 피로도 관리 규칙을 둔다고 답변 |

## 5. 비즈니스 임팩트/인과관계 관련

| 예상 질문 | 대비 포인트 |
|---|---|
| 이 세그먼트(상세페이지 진입·찜했지만 미시청)의 모수가 충분히 커서 투자 대비 효과가 있나요? | 정확한 규모는 실제 데이터 확인이 필요하다고 솔직히 인정하되, 이미 관심을 보인 고효율 구간이라 전환율 자체가 높을 가능성이 크고, A/B 테스트로 투자 대비 효과를 먼저 작게 검증한 뒤 투자 규모를 결정하는 것이 맞다고 답변 |
| 이 기능이 없었어도 어차피 볼 사용자와, 기능 덕분에 실제로 전환된 사용자를 어떻게 구분하나요? | 바로 이 증분 효과를 분리하기 위해 노출군과 비노출 대조군으로 나누는 A/B 테스트를 설계했다고 연결 — 단순 노출 후 시청률이 아니라 "대조군 대비 추가로 늘어난 시청 시작률"을 핵심 지표로 본다고 답변 |

## 6. 세그먼트 우선순위 관련

| 예상 질문 | 대비 포인트 |
|---|---|
| 원래 JD에서 강조한 건 "뭘 볼지 몰라 이탈하는 사용자"인데, 그 세그먼트를 2단계로 미루는 게 맞나요? | 1단계(고려 단계) 세그먼트를 먼저 선택한 것은 우선순위를 낮춰서가 아니라, 같은 인프라(반응 데이터 가공·노출)를 더 작고 측정하기 쉬운 범위에서 먼저 검증한 뒤 더 크고 복잡한 문제(방향감 없는 사용자)로 확장하는 리스크 관리 전략이라고 답변 |
