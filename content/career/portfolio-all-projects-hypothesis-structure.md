# 포트폴리오 전체 프로젝트 — 가설·방법론·결과·회고 구조화

> 작성 목적: 포트폴리오 9개 프로젝트 전체를 "가설 → 가설 설정 방법 → 방법론/접근 → 결과 → 회고"로 재구성
> 작성일: 2026-09-17
> 근거자료: Product Portfolio(28p, 강해우) 원문
> 주의: 포트폴리오 원문에 **회고가 명시적으로 기재되지 않은 프로젝트**는 추측해서 채우지 않고 "회고 없음"으로 표기함 — 이는 면접에서 즉석 답변 리스크가 있는 지점이므로 별도 표시

## 0. 설계 프롬프트

> 너는 지원자의 포트폴리오를 리뷰하는 PM 코치다. 포트폴리오에 실린 9개 프로젝트 전부를 "① 가설이 무엇이었는가, ② 그 가설을 어떤 근거로 설정했는가, ③ 어떤 방법론으로 접근했는가, ④ 어떤 결과를 얻었는가, ⑤ 어떤 회고를 거쳤는가"의 5단 구조로 재정리하라. 포트폴리오에 없는 내용은 지어내지 말고, 회고가 원문에 없으면 "회고 없음"이라고 명시하라.

## 1. AI 챗봇과의 상호작용 개선 (마인드로직)

- **가설**: 대화 주제를 사용자가 흥미로워하는 주제로 좁히고 관련 정보를 챗봇에 채워주면, 대화 만족도와 참여도가 오를 것이다.
- **가설 설정 방법**: 챗봇 평가자 18명 설문 결과 83%가 "흥미롭지 않은 대화 주제"를, 72%가 "아이돌에 대한 정보 부족"을 불만족 이유로 지적(평균 만족도 5.8/10). 과한 질문·이모지·긴 문장도 하위 이유로 확인.
- **방법론/접근**: 팬 20명과 30분씩 대화시키는 실험으로 관심 주제를 클러스터링해 TOP4 선정 → 아티스트 전용 챗봇·매니저 콘솔·AI 자동생성 3개 경로로 해당 주제 데이터를 수집하는 체계 구축 → 수집된 데이터를 챗봇 대화에 반영 → 10~20대 100명을 개선/기존 챗봇 그룹으로 나눈 between-subject A/B 테스트(5일)로 검증.
- **결과**: 대화 참여도 지표(linguistic/interaction cue) 25%↑(chi-square, p<0.05), 대화 만족도 30%↑(t-test, p<0.01), 중국 시장 출시 후 MAU 약 5,000명.
- **회고**: 참여자가 주관적으로 답한 "흥미로운 주제" 순위와 실제 채팅 로그상 대화 주제 순위가 달랐음 → 사용자는 본인이 원하는 기능을 정확히 모르는 경우가 많다 → 사용자 피드백을 그대로 수용하지 않고 데이터를 비판적으로 분석해서 적절한 값을 활용해야 한다는 교훈.

## 2. 홈화면 내 추천 충전구역 고도화 (LG유플러스 볼트업)

- **가설**: 즐겨찾기를 등록한 세그먼트에게는 즐겨찾기된 충전구역을 최우선으로 노출하면 CTR이 오르고 VoC가 줄어들 것이다.
- **가설 설정 방법**: 즐겨찾기 등록자(전체 활성 사용자의 16.6%)가 미등록자보다 추천 충전구역 CTR이 약 5배 높다는 것을 발견(18.2% vs 3.7%). 등록자의 85%는 특정 충전구역만 반복 이용. 관련 VoC는 월평균 15건.
- **방법론/접근**: 기존 추천 기준(거리·이용횟수 등 복합 조건)에서, 즐겨찾기 사용자에게는 즐겨찾기 충전구역을 우선순위 1위로 재배치하도록 추천 로직 변경.
- **결과**: 추천 충전구역 CTR 7%p↑(18%→25.2%), 관련 VoC 월평균 47%↓.
- **회고**: 정량 데이터 기반 개선은 확인했으나, 즐겨찾기 등록자(16.6%)라는 일부 세그먼트에 대한 개선이라 나머지 사용자 개선이 추가로 필요함. 즐겨찾기라는 고정 규칙의 재배치였을 뿐이므로, 추후에는 재방문·빈도·시간대 신호 등을 반영한 개인화 추천으로 고도화할 계획.

## 3. 상품 추천 시스템 기획 (건강 디저트 추천 플랫폼 — 빵그리의 오븐)

- **가설**: 방문 목적과 기피 재료에 맞춘 개인화 추천을 제공하면, 건강 디저트에 대한 낮은 접근성 문제를 해결해 재방문·구매 의사가 올라갈 것이다.
- **가설 설정 방법**: 건강 디저트 구매 경험자 100명 설문에서 63%가 "접근성이 낮다"고 응답(비싼 가격·다양성 부족·맛 정보 부족이 뒤를 이음). 추천 서비스 방문자 중 60%가 다이어트·근성장 목적, 27%가 유당불내증을 겪는다는 것도 확인.
- **방법론/접근**: 초기 데이터 부족(콜드스타트) 상황이라 상품 정보·리뷰를 크롤링해 자연어 특성+상품 특성 데이터를 인풋으로 사용 → 추천 모델 후보 2개(BoW+TF-IDF 0.8점, Word2Vec 1.2점, 내부 정성평가 2점 만점 기준)를 비교해 Word2Vec 채택 → 찜(긍정 반응) 행동 기반 유사 상품 추천 설계, 전체 211개 상품 중 82% coverage 달성 → Elbow method로 사용자 세그먼트 4종 군집화(근성장/다이어트 42.9%, 유당불내증 28.0%, 교집합 18.6%, 기타 10.6%) → 세그먼트별 찜 순위 기반 홈화면 추천 적용.
- **결과**: 재방문 의사 7.0점(10점 만점), 구매 의사 6.3점, 마케팅 없이 베타 출시만으로 MAU 약 1,300명 달성.
- **회고**: 제한된 데이터만으로 콘텐츠 기반 추천 시스템을 실제 서비스에 도입했다는 점에서 의의가 있었으나, 별도의 명시적 회고 문구는 포트폴리오에 없음 — **회고 없음(보완 필요)**.

## 4. 측정 장비 소프트웨어 사용량 대시보드 구축 (오비랩)

- **가설**: 사용량 데이터를 시각화한 대시보드를 제공하면, 영업팀이 크로스셀링 대상 고객을 빠르게 식별해 매출로 연결할 수 있을 것이다.
- **가설 설정 방법**: 영업팀이 크로스셀링 대상 고객을 파악하는 데 매월 1~2일이 소요된다는 문제 인식(기존 소프트웨어에 사용량 데이터 수집 기능 자체가 부재).
- **방법론/접근**: 이해관계자 요구사항에 맞춰 문제 정의 → 로그 데이터를 수집 가능하도록 소프트웨어 리뉴얼 기획 → SQL로 추출한 데이터를 Python으로 프로토타이핑 → 개발팀과 협업해 사용량 대시보드를 관리자 페이지에 추가.
- **결과**: 실시간 사용량 연동 대시보드로 실험량이 증가하는 고객을 식별 → 장비 추가구매·데이터 분석 서비스 제안 → 전년도 1분기 대비 크로스셀링 건수 130%↑, 매출 180%↑(데이터분석서비스 9건, 장비대여 15건, 장비추가구매 5건).
- **회고**: 포트폴리오에 명시적 회고 없음 — **회고 없음**. (다만 여러 면접에서 "매출과의 인과관계를 어떻게 검증했나"라는 질문을 반복적으로 받은 프로젝트이므로, 회고를 새로 정리해둘 필요성이 가장 높은 항목)

## 5. 쿠폰 발급의 인증 절차 간소화 (LG유플러스 볼트업, U+ 제휴)

- **가설**: 본인 인증된 전화번호(자동입력)+생년월일(최소 직접입력)로 인증 절차를 절충하면, 어뷰징 위험은 최소화하면서 쿠폰 발급 장벽을 낮춰 사용률과 매출을 높일 수 있을 것이다.
- **가설 설정 방법**: VIP멤버십 전용 쿠폰을 발급하는 타 서비스는 사용자가 멤버십 카드번호를 직접 조회·입력해야 하는 번거로움이 있다는 문제 인식. 다만 인증 절차를 완전히 간소화하면 본인 확인이 안 돼 어뷰징(중복 발급) 위험이 발생한다는 트레이드오프 인식.
- **방법론/접근**: 전화번호 자동입력 + 생년월일 최소 직접입력이라는 절충안 설계 → 본인 인증된 전화번호만으로 어뷰징 케이스를 방지하는 제휴 쿠폰 발급 기능 배포.
- **결과**: 출시 당월(U+ 통신사인 활성 사용자의 18%) 쿠폰 발급자 2,270명 중 87% 사용, 사용자의 14%가 휴면 회원, 쿠폰 출시 후 전월 대비 매출 16%↑ (단, 같은 기간 전기차 판매량·신규 충전기 설치 수는 감소).
- **회고**: 매출과 연관된 전기차 판매량·신규 충전기 설치 수가 감소한 상황에서도 매출이 늘었다는 점을 근거로 "쿠폰이 휴면 회원 복귀와 매출 성장에 기여했다"고 분석 — 다만 이는 포트폴리오 상 유일한 자체 반박·재반박 형태의 회고이며, **정식으로 리스크(카니발라이제이션, 순증 효과 미검증)까지 인정한 회고는 아님** (직전 검토 문서 `portfolio-new-projects-critical-review.md` 참고).

## 6. 언어 패키지로 협업 환경 구축 (마인드로직)

- **가설**: 화면 문구를 구글 스프레드시트 기반 key-value 협업 환경으로 옮기면, 개발 공수 없이 문구를 수정·배포할 수 있어 협업 비용이 줄어들 것이다.
- **가설 설정 방법**: 화면 문구가 빈번히 바뀔 때마다 스크립트 수정에 격주로 2시간 이상 소요됐다는 문제 인식. 해외 시장 출시 예정이라 한·중·영 다국어 문구 작성 환경이 필요하다는 요구사항.
- **방법론/접근**: 구글 스프레드시트에 페이지별 key-value 텍스트를 언어별로 입력 → submit 시 JSON 형식으로 저장 → 개발 스크립트가 이를 import해 key-value 기준으로 화면에 localize → OpenAI API로 한국어·영어 입력 시 중국어·일본어 자동 번역 → Make로 변동 발생 시 담당자에게 Slack 알림.
- **결과**: 구글 시트에서 누구나 문구를 직접 수정 가능한 협업 환경 구축, 문구가 수정돼도 추가 개발 공수 없이 배포 시 자동 적용, 해외 협력팀 4인·내부 10인의 커뮤니케이션 비용 절감.
- **회고**: 포트폴리오에 명시적 회고 없음 — **회고 없음**.

## 7. 측정용 소프트웨어의 사용성 개선 (오비랩, 뇌 측정 장비)

- **가설**: 이해관계자·사용자 인터뷰로 도출한 인사이트를 반영해 단계별 구조와 피드백을 제공하면, 전문 교육 없이도 측정 준비를 완료할 수 있어 소요 시간이 줄어들 것이다.
- **가설 설정 방법**: 사용자 설문(20명) 결과 "교육을 받지 않으면 이용이 어렵다" 37%, "장비 연결이 끊어져도 알 방법이 없다" 29%, "마커를 복수로 사용할 수 없다" 17%, "기능을 모르는 사용자 존재" 11% 등으로 문제 구조화.
- **방법론/접근**: Primary button을 따라가며 누르면 측정 준비까지의 모든 과정이 완료되도록 단계별 구조 설계, 장비 연결에 대한 실시간 피드백 제공.
- **결과**: 사용자의 측정 준비 소요 시간 70% 감소(평균 40초).
- **회고**: 포트폴리오에 명시적 회고 없음 — **회고 없음**.

## 8. 이탈률 퍼널로 문제 정의 (오비랩, AARRR 보드)

- **가설**: 마커 설정 구간의 어려움이 이탈의 주원인이며, 이 구간에 튜토리얼을 추가하면 이탈률이 줄어들 것이다.
- **가설 설정 방법**: 뇌 데이터 분석 서비스 특성을 고려해 AARRR 보드를 설계(Google Analytics 기반)한 결과, 사용자 70%가 마커 설정(버튼 클릭) 구간에서 작업을 완료하지 못하고 이탈. 행동 데이터와 추가 인터뷰로 "마커로 분석 구간을 설정하는 단계가 어렵다"는 원인 확인.
- **방법론/접근**: 화면 구조 자체를 수정할 개발 인력이 부족했던 상황이라, 튜토리얼 영상을 제작해 마커 설정 구간에 툴팁으로 추가.
- **결과**: 문제 구간 이탈률 70%→26%로 감소, MAU 160%↑(78명), 분석 서비스 CTR 1.8배, CVR 1.5배 증가.
- **회고**: 포트폴리오에 명시적 회고 없음 — **회고 없음**. (다만 면접에서 "개발 리소스가 부족한 상황에서의 최선의 선택이었다"는 취지의 답변을 여러 차례 한 바 있어, 사실상 구두 회고는 존재)

## 9. 어려운 정보를 쉽게 전달 (오비랩, 근육산소포화도 기반 러닝 보조 서비스)

- **가설**: 사내 체험단 인터뷰로 문제를 클러스터링해 재정의하고, 정보 재배치·UX 라이팅으로 개선하면 사용성·가치 평가가 오를 것이다.
- **가설 설정 방법**: 2021년 출시된 러닝 보조기구의 판매량이 초도 물량의 1/5에 그침. B2C 제품임에도 사용자가 어려움·복잡함·지루함을 느낀다는 문제 인식.
- **방법론/접근**: 사내 체험단 20명 인터뷰 결과를 클러스터링해 문제를 정의 → (체력측정테스트→강도 선택)을 (체력측정테스트→측정 데이터 기반 개인화 러닝 플랜)으로, 고정 추천 속도를 개인화 속도로, 복잡한 정보 화면을 재배치+UX 라이팅으로 개선.
- **결과**: 사용성·가치 평가 점수 45%↑(평균 8.5점, paired t-test p<0.05), 이후 크라우드펀딩으로 재출시해 $29,105 투자 유치.
- **회고**: 포트폴리오에 명시적 회고 없음 — **회고 없음**.

## 10. 종합 — 회고 공백 현황

9개 프로젝트 중 **명시적 회고가 원문에 기재된 것은 2건뿐**(①AI 챗봇 상호작용 개선, ②홈화면 추천 고도화)이고, 나머지 7건(③~⑨)은 회고 문구 자체가 없습니다. 이는 앞서 정리한 `interview-cross-company-pattern-analysis.md`에서 지적한 **"인과관계·표본규모 방어 논리가 매번 즉석에서 만들어진다"**는 문제와 정확히 맞닿아 있습니다. 특히 ④사용량 대시보드, ⑤U+쿠폰은 여러 회사 면접에서 반복적으로 공격받은 프로젝트인데도 회고가 비어 있어, 우선적으로 회고를 정식으로 작성해두는 것을 권장합니다.
