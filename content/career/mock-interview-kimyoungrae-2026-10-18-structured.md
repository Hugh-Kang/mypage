# 김영래와의 모의면접 — 질문·답변 구조화 (2026-10-18)

> 작성 목적: 2026-10-18 진행된 모의면접(인사팀 실무진 1명 + CPO 1명 패널 가정) 녹취를 질문-답변 표로 구조화하고, 면접 중간중간 오간 실시간 코칭·리서치 세션 내용도 함께 정리
> 작성일: 2026-10-18
> 근거자료: 김영래와의 모의면접 녹취(Clovanote STT, 37분 50초)
> 참고: 참석자 1 = 김영래(인사팀 역할극 인터뷰어), 참석자 2 = 강해우(지원자)

## 핵심 요약 (두괄식)

이번 모의면접은 인사팀+CPO 패널을 가정한 구성으로, 강점·약점 같은 인성 질문부터 아이돌 챗봇 AB테스트 디테일, 개발자 협업 상황극, 데이터 vs 사업팀 의견 충돌 대응, AI 에이전트 성공/실패 정의, 비용 구조, 90일 계획까지 폭넓게 다뤘습니다. 가장 중요한 수확은 두 가지입니다. ① **MAU 5천 명(중국 아이돌 챗봇) 수치를 포트폴리오에는 넣었지만 구두로는 일부러 언급하지 않았다는 점을 본인이 먼저 솔직하게 밝혔고**, 면접관도 "거짓말은 아니니 모호하게 언급해도 된다"는 현실적인 코칭을 줬습니다. ② 면접 중간에 실제로 **"네이버웹툰이 왜 해외에서 성공했는가"를 함께 리서치하는 세션**이 진행됐는데, 그 결론("콘텐츠 수출이 아니라 플랫폼 수출", "현지 창작자가 만들고 현지 사용자가 소비하는 로컬 생태계 구축")이 제가 같은 날 별도로 조사해 정리한 `naver-webtoon-global-success-factors-analysis.md`의 핵심 결론과 **정확히 일치**합니다.

## 1. 질문·답변 구조화 표

| # | 질문 | 답변 요약 |
|---|---|---|
| 1 | 본인의 큰 강점은 무엇인가 | 서비스 완성도를 위해 필요시 업무 범위를 스스로 확장함. EV 충전구역 숏컷 고도화 시, 단순히 정책만 던지지 않고 데이터 엔지니어에게 선제적으로 데이터 근거(즐겨찾기 85% 집중 사용 패턴)를 요청해 확보한 뒤 설득 자료로 활용 |
| 2 | 보완해야 할 약점은 무엇인가 | 성격이 급해 회의록을 너무 급하게 공유하다 개발자들이 혼란을 겪은 적 있음. 이후 회의록에 맥락·목적을 명확히 적고, 주요 신기능은 별도 킥오프 미팅을 잡아 정보 전달 시점·양을 조절하는 방식으로 개선 |
| 3 | AI 챗봇 프로젝트 설명 요청 | 버블(아이돌 1:다 메시지 구독 플랫폼)의 비개인화 문제를 페르소나 챗봇으로 해결. 대화 유지가 어렵다는 점을 발견해 개선, 만족도 30%↑·대화참여도(Linguistic/Interaction Cue) 25%↑ |
| 4 | 만족도 30% 향상의 정확한 의미 | 기존 vs 개선 챗봇 AB테스트 비교 결과. "대화가 유의미했는지/가치있었는지/몰입해서 시간가는줄 몰랐는지" 3개 축 설문의 평균값 |
| 5 | 챗봇 AB테스트 자세히 설명 | 실험군·대조군 100명, 5일간 진행. Interaction Cue=5일간 대화 총 단어 수, Linguistic Cue=인지적 과정을 반영하는 단어(remind, think, because 등) 사용 빈도 |
| 6 | 몰입했다는 것에 대한 검증이 가능했는지 | 1차로 Linguistic Cue 정량 지표, 2차로 인터뷰를 통한 정성적 확인("실제 아이돌 말투와 비슷해 몰입됐다"는 피드백) 병행 |
| 6-코칭 | (면접관 제안) 아쉬웠던 점 | Linguistic Cue가 몰입을 보여주는 "직접적인" 지표인지는 한계가 있으니, "당시엔 못 봤지만 지금 돌아보면 이런 지표도 고려했을 것"이라는 회고형 보완 멘트를 준비하면 더 집요해 보일 것이라는 코칭 |
| 7 | (MAU 관련 질문) 중국 시장 MAU 5천 명 수치를 왜 말 안 했는지 | 챗봇 개선 출시 자체가 본인 퇴사(2025년 5월) 이후인 2025년 하반기였기 때문에, 본인 성과로 포장되는 걸 피하려 구두로는 의도적으로 언급하지 않음(포트폴리오에만 기재) |
| 7-코칭 | (면접관 제안) | 거짓말은 아니니(검색하면 확인 가능) 모호하게 "개선된 챗봇 출시 시점에 중국 팬덤 기준 초기 MAU 5천 명 정도가 몰렸던 기억이 있다"는 식으로 언급해도 된다는 현실적 코칭 |
| 8 | MAU의 정확한 정의 | 월간 활성 사용자 수(Monthly Active User). 단순 접속이 아니라 메시지창 진입 또는 메시지 발송 기준 등 서비스 특성에 따라 정의가 달라짐. 볼트업 기준 단순 접속 24만 명, 충전까지 완료한 사용자 기준 15~16만 명, 보통 "20만 명대"로 표현 |
| 9 | 라이브 서비스 특성상 주말·야근 비상 대응은 어떻게 할 것인가 | 비상 상황 시 PM이 빠르게 의사결정해 임시방편을 적용한 뒤 추후 재발 방지 설계. 현재 회사에서도 추석 연휴 요일별 비상 대응 당번제를 운영한 경험이 있어, 티빙에서도 당번제 도입을 제안 |
| 10 | 티빙에 AI 에이전트가 필요하다고 생각하는지 | 지금 당장 필수는 아니나, 검색형에서 대화형(클로드/챗GPT식)으로 바뀌는 추세를 고려하면 향후 필요하다고 판단 |
| 11 | AI 에이전트 도입 시 성공을 어떻게 측정할 것인가 | 콘텐츠 추천 챗봇 기준, 클릭률·재생전환율·재생시간을 1차 KPI로 보고, 최종적으로 광고매출·구독이탈률까지 연결해 평가 |
| 12 | 개발자가 요구사항이 어렵다고 하면 어떻게 할 것인가 | 기술적 문제인지 시간 부족인지 구분해 파악하고, 리소스 재할당 또는 차선책을 PM이 먼저 제안 |
| 12-코칭 | (면접관 제안) | "왜 어려운지"를 더 집요하게 캐묻는 태도를 보여주는 것이 중요하다는 코칭. 실제 사례로 쿠폰 어뷰징 방지 정책 설계 경험(난수번호 쿠폰을 사용자당 1개만 등록 가능하도록 쿠폰 종류를 여러 개 발급하는 방식으로 해킹 리스크 완화)을 추가하면 좋겠다는 제안 |
| 13 | 데이터는 A를 말하지만 사업팀은 B를 원하면 어떻게 할 것인가 | 상황에 따라 다르게 적용하되, 데이터와 직관을 무조건 하나만 따르지 않음. 아이돌 챗봇 인터뷰 사례(사용자가 말한 선호 주제 ABC vs 실제 데이터 BCD) — 교집합(BC)에서 공통분모를 찾아 "아이돌만 줄 수 있는 실시간 정보에 대한 갈증"을 발견한 경험으로 설명 |
| 14 | 티빙에서 하나만 개선할 수 있다면 무엇을 개선할 것인가 | 팬톡 기능 — 본인이 실제로 스우파 본방 중 팬톡에 들어갔다가 탈락자 스포일러를 당해 몰입이 깨진 경험을 근거로, LLM API 기반 스포일러 필터링/사전 경고 기능 제안 |
| 15 | 완성도 높은 3개월 기능 vs 1주 MVP 중 선택 | 1주 MVP 선택. 라이브 서비스는 빠르게 사용자 반응을 확인하고 워킹 여부를 파악한 뒤 점진적으로 확장하는 것이 적절하다는 논리(단, 결제처럼 안정성이 절대적으로 중요한 기능은 예외) |
| 16 | 디스커버리 PM 지원 맞는지, 역할 범위 확인 | 추천 프로젝트와 챗봇 AI 에이전트 설계 둘 다 포함. 1차 면접에서 팀장이 "하나는 메인, 하나는 서브"로 운영될 것이라며, 챗봇 쪽 확장 의지를 보니 챗봇이 더 적합할 수 있다는 뉘앙스를 전달받음 |
| 17 | 국내에서 잘 되는 티빙 서비스가 해외에서도 통할지 | K콘텐츠 인기로 긍정적이나, 한국 사용자 세그먼트를 그대로 적용하면 안 되고 현지 정서·문화를 고려한 현지화가 필요하다고 답변 |
| 18 | AI 에이전트의 "실패"는 어떻게 정의할 것인가 | 기존 홈 화면 추천 대비 추가 리소스(챗봇)를 투입했는데도 성과가 더 낮다면 실패로 간주. 이 경우 빠르게 철수(롤백) 후 원인 분석, 이후 단계적으로 재적용 |
| 19 | AI 에이전트 운영 비용 문제 | 메시지 1건당 LLM API 비용이 발생해 비용 부담이 작지 않음. 자체 모델 개발은 대규모 데이터가 필요하므로, MVP 단계는 LLM API 활용 → 효과 검증 후 필요시 더 저렴한 모델 전환·파인튜닝 검토 |
| 20 | 입사 후 90일 동안 무엇을 할 것인가 | 수습 기간 내 빠르게 MVP를 설계·적용해 성과를 내고 싶음. 예: 이탈 가능 사용자에게 팬톡 리뷰 기반으로 "진선규 연기가 화제" 같은 바이럴 포인트를 자연스럽게 노출해 유사 콘텐츠(백일의 거짓말 등) 추천으로 연결 → 클릭률·재생전환율·재생시간으로 효과 측정 |
| 21 | 역질문 | 입사 시 디스커버리팀 내 어떤 업무(추천 vs 챗봇)를 맡기고 싶은지, CPO의 생각을 여쭤봄 |

## 2. 면접 중 리서치 세션 — 네이버웹툰 해외 성공 요인 (실시간 조사)

면접 상황극 도중, 티빙 신임 CPO가 네이버 출신이라는 점에 착안해 즉석에서 "네이버웹툰이 왜 해외에서 성공했는가"를 함께 검색하며 논의하는 세션이 있었습니다. 이때 도출된 핵심 논지는 다음과 같습니다.

- **"콘텐츠 수출이 아니라 플랫폼 수출"**이었다는 점 — 특정 작품이 잘 팔린 게 아니라, 플랫폼 자체를 해외에 직접 운영하며 현지 창작자가 콘텐츠를 만들고 현지 사용자가 소비하는 로컬 생태계를 구축한 것이 핵심
- 도전만화 → 베스트도전 → 정식연재로 이어지는 **"작품을 만들어가는 생태계 구조 자체를 수출"**했다는 표현으로 정리됨
- 다만 티빙은 네이버웹툰처럼 "현지 창작자 승강제 생태계"를 그대로 복제할 수는 없으므로, **티빙 오리지널 콘텐츠 + 현지 로컬 콘텐츠 일부 계약을 결합해 자연스럽게 K콘텐츠를 홍보하는 방식**이 더 적절하다는 결론으로 이어짐(단, 이 부분은 PM보다 사업부 영역에 가깝다는 점도 함께 인지)

> 이 결론은 제가 같은 날 별도로 조사해 정리한 `naver-webtoon-global-success-factors-analysis.md`(플랫폼 수출, 아마추어 승강제 생태계 이식, IP 밸류체인 확장 등)의 핵심 내용과 거의 동일합니다. 다만 그 문서에서 추가로 짚은 **"수년간 해외 법인 영업손실을 감수해야 하는 장기 투자형 전략"이라는 비판적 한계**는 이번 모의면접 세션에서는 다뤄지지 않았으므로, 실제 면접에서는 이 현실적 리스크까지 언급해 균형 잡힌 답변으로 보완하는 것이 좋습니다.

## 3. CPO 성향에 대한 예측 (면접관 코멘트)

- CPO가 올해(2026년) 3월 말에 합류한 지 얼마 안 된 인물이라는 점에서, 아직 조직 파악 단계일 가능성이 언급됨
- CPO가 **UX 디자이너 출신**이므로 기술적 디테일보다 **협업 스타일·컬처 핏**, 사용자 분석·인터뷰·문제 정의 과정을 더 비중 있게 볼 것이라는 예측 — 이는 `tving-cpo-parkjieun-profile-analysis.md`에서 이미 짚은 "UX적 설득력이 중요할 수 있음"이라는 분석과 일치하는 교차검증 결과
- CPO 앞에서는 **두괄식으로 요약 먼저 → 궁금해하면 뒤에 디테일 추가**하는 방식이 적절하다는 조언

## 4. 긍정적으로 평가된 라포 형성 사례

- 실무진(면접관 역)이 "컴공과신가요?"라고 묻자 즉답으로 "부전공이 컴공, 주전공은 산업공학(인간공학)"이라 답하며 UX 전공과의 연결고리를 자연스럽게 설명 → "역시 영래 쌤"이라는 반응으로 좋은 인상을 남긴 것으로 평가됨
- 첫 질문("JD에 챗봇 AI 에이전트가 있는데 실제 도입 계획이 있는지")에 대한 답변이 자연스럽게 후속 질문("합류 시 어떤 역할을 기대하는지")의 답까지 겸하게 되는 흐름이 만들어져, 질문 설계 의도를 스스로 파악하고 있다는 점이 긍정적으로 언급됨
