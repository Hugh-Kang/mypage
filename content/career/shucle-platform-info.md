# 셔클(Shucle) 플랫폼 정보 — 현대자동차 지원 참고자료

> 출처: 셔클 공식 사이트(사용자 제공, 2026.08 기준)
> 용도: 현대자동차 [AVP] 모빌리티 서비스 UX 기획 자소서·면접 준비용 레퍼런스

## 1. 플랫폼 정체성

현대자동차의 통합 모빌리티 플랫폼(MaaS). AI 기술 기반 모빌리티 솔루션으로 지역 교통 문제를 해결하고, "모든 사람이 제약 없이 자유롭게 이동하는 도시"를 만드는 것을 비전으로 함.

## 2. 핵심 기술 구조 (4대 축)

셔클은 단일 앱이 아니라 **AI 알고리즘 + 데이터 파이프라인 + 운영 자동화 + 지역 맞춤 정책**이 결합된 시스템이다.

### ① AI Dynamic Routing (수요응답교통 핵심기술)
- 실시간 수요를 AI가 분석해 불필요한 운행을 최소화하고, 이용자 경험을 최대화하는 최적 경로 생성

### ② 수요 예측 및 운행 시뮬레이션 (Demand Prediction & Operation Simulation)
- 모빌리티 데이터 + 인구통계 모델링으로 지역 이동 수요 예측
- 실시간 운행 시뮬레이션으로 플랫폼 도입 효과 사전 분석
- **활용 데이터**: 버스·지하철 노선, 대중교통 승하차/환승 데이터, 택시 이동·승하차 데이터, 교통 거점 수요, 주거·교육·상권 POI, 인구밀도·세대수·연령대
- **모빌리티 데이터 파이프라인**: 위 데이터를 통합 수집·분석하는 인프라

### ③ 수요 기반 운행 최적화 (Demand-based Optimization)
- **AI assisted scheduling**: 수요 데이터 기반으로 최대 수송 + 근무조건을 동시에 만족하는 운행 스케줄 자동 생성
- **최적 노선 및 운행 방식 추천**: 고정 노선 ↔ 수요응답형을 유연하게 혼합하는 복합 운행
- **지역 맞춤형 정책**: 지역별 교통정책·이동수요·인구분포에 따라 배차·운영 정책을 세밀 조정

### ④ 데이터 기반 운영 자동화 (Data-driven Operation) — "관제" 영역
- **실시간 데이터 분석**: 운행 현황·추이를 지표/차트로 시각화, 지역별 이동 패턴 파악
- **비정상 운행 탐지(Anomaly Detection)**: 이상 운영 이벤트 자동 감지 + 관리자 알림
- **맵데이터 편집(Intelligent Map Editor)**: 도보 접근성·이동수요 분석 기반 정류장 추천 + 관리자용 맵 편집 도구

> **주목할 점**: ④가 곧 공고에서 말한 "관제 툴" 영역이다. 실시간 분석·이상탐지·맵 편집이라는 명확한 관리자용 제품이 존재하므로, 이 공고의 "복수 접점 플랫폼 시나리오 설계"는 실제로 이 프로젝트의 핵심 축이 맞다.

## 3. 보유 특허 (7건)
수요 예측 기반 정차지 운영/안내, 차량 정차지 결정방법, 예상 수요 고려 경로탐색 알고리즘, 최적 승하차 지점 생성, 승하차 지점 사진 자동 추출, 승하차 지점 자동 추출, DRT 운행 스케줄링 방법.
→ **정류장 위치 자체를 AI가 설계**한다는 것이 셔클의 기술적 차별점(단순 배차 앱이 아님).

## 4. 지역별 도입 사례 (문제 유형 → 해결 → 정량 효과)

| Case | 지역 특성(문제) | 솔루션 방향 | 정량 효과 |
|---|---|---|---|
| ① 거점 중심 이동 (양주 옥정신도시) | 지하철역 집중 수요, 기존 버스노선의 긴 대기·비효율적 환승 | 시간대·목적지 집중 → 자연스러운 합승 경로 생성 | 총 통행시간 51.5% 단축 |
| ② 고연령 농촌 (안산 대부도) | 저밀도·고령인구, 배차간격 20~120분, 도보접근성 열악 | 앱 호출 + **전화 호출**(고령층 접근성 보완) | 도보 이동 80.3% 단축 |
| ③ 다양한 이동수요 대응 (세종 1·2생활권) | 고밀도·다양한 연령 패턴, 승용차 분담률 46.9%로 교통체증 | 산발적 수요에 유연 대응 | 자가용 이용 42.1% 감소, 차외 통행시간 70.3% 단축 |
| ④ 긴급 교통문제 해결 (김포시) | 신규 입주 급증, 김포골드라인 혼잡도 250% | 70일 만에 긴급 DRT 도입, 시간대별 유연 운행 | 혼잡도 250%→200%, 지정좌석 쾌적 출퇴근 |

→ 4개 사례 모두 **"지역 특성 진단 → 문제 정의 → 맞춤 솔루션 → 정량적 효과 검증"** 구조로 서술되어 있음. 이 구조 자체가 셔클 팀의 기획 방법론을 보여주므로, 자소서·면접에서 이 구조를 참고해 자신의 사례를 서술하면 결이 맞는다.

## 5. 자소서/면접 활용 포인트

- **문항1(지원동기)**: 기존에 "예약 대신 실시간 호출 방식 고수" 사례를 썼는데, 위 4개 케이스 중 **김포시 사례(70일 만에 긴급 도입, 혼잡도 250%→200%)**가 "데이터 기반 판단이 실제 사람들의 일상을 얼마나 빠르게 바꾸는가"를 보여주는 더 구체적이고 강력한 근거가 될 수 있음.
- **문항2(직무강점)**: "관제 툴" 요건에 대해 이전에는 마인드로직(팬앱+아티스트챗봇+매니저콘솔)만 근거로 쓰기로 했는데, 셔클의 관제 영역이 "실시간 분석 + 이상탐지 + 맵 편집"으로 꽤 구체적이므로, 마인드로직의 매니저 콘솔 사례를 이 세 기능(특히 실시간 모니터링·데이터 시각화)과 더 정교하게 연결할 수 있음. 오비랩의 AARRR 보드(실시간 사용자 행동 대시보드 설계) 경험도 "실시간 데이터 분석" 요건에 직접 연결 가능한 카드로 재검토할 가치가 있음.
- **인구통계·POI 기반 수요예측**은 지원자의 포트폴리오 중 "건강 디저트 추천 플랫폼"의 세그먼트 군집화(Elbow method, 사용자 특성 기반 클러스터링) 방법론과 결이 비슷함 — 방법론적 친숙도를 보여줄 수 있는 보조 소재.
