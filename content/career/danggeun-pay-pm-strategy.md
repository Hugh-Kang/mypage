# 당근페이 Offline Payment PM — 지원 전략

> 채용공고: 당근페이 Product Manager, Offline Payment (2026.08 기준)
> 작성일: 2026-08-15
> 성격: 자가 준비용 지원 전략 (서류 → 과제 → 직무 인터뷰 → 컬처핏/레퍼런스체크 → 처우협의)

## 0. 설계 프롬프트

> 당신은 당근페이 채용 담당자 출신의 커리어 코치입니다. 아래 채용공고 원문을 분석해, 이 공고에 지원하는 5년차 이상 PM이 최종 합격까지 도달하기 위한 단계별 전형 대응 전략을 설계하세요.
>
> ① 공고 문장에서 **필수 요건 / 우대 요건 / 팀 문화 시그널**을 각각 근거 문장과 함께 분리하고, ② 지원자가 자신의 경험을 어떻게 매핑해야 하는지 포지셔닝 표를 만들고, ③ **서류·과제·직무인터뷰·컬처핏/레퍼런스체크·처우협의** 각 단계마다 평가 포인트·준비 액션·예상 질문을 구체적으로 제시하고, ④ 우대사항 중 지원자에게 없을 가능성이 높은 도메인(핀테크/결제)을 어떻게 2주 안에 보완할지 학습 플랜을 포함하고, ⑤ STAR 형식으로 준비할 핵심 경험 슬롯 3개를 제안하세요. 추측이 아니라 공고 원문에 실제로 등장하는 표현을 근거로 삼으세요.

## 1. 채용공고 해부

**필수 요건 (없으면 탈락)**
- 모바일 서비스(웹/앱) 기획·PM 경력 5년 이상
- 현장에서 고객 문제를 직접 듣고 실행으로 해결한 경험
- 도전적 목표를 끝까지 파고들어 수치로 증명한 임팩트
- 복잡한 제약·다수 이해관계자 사이에서 논리적 근거로 설득한 협업 리드 경험

**우대 요건 (동점자 사이 차별화)**
- 금융·핀테크, 특히 결제 도메인 이해/경험
- 리텐션·리워드 등 그로스 실험 설계 + ROI 측정 경험
- 오프라인 결제 또는 사업주(B2SMB) 향 제품 기획·운영
- 먼저 의견을 내고 주도적으로 일하는 성향

**팀 문화 시그널** (팀원 코멘트 근거): 주도성, 데이터 기반 의사결정, 빠른 실험, 솔직한 회고, 직군 간 벽 없음, 현장 검증.

## 2. 포지셔닝 — 요건을 경험으로 번역하기

| JD 요구사항 | 증명 방법 | 준비 액션 |
|---|---|---|
| 현장 고객 문제 해결 | CS/현장 인터뷰에서 발견한 불편을 다음 스프린트에 반영한 사례, 반영 전후 지표 | 3문장 요약 + 지표 그래프 1장으로 카드화 |
| 수치로 증명된 임팩트 | 목표 → 실험/실행 → 결과(%) 순서의 이력서 불릿 | "무엇을 해서 → 얼마나 바뀌었다" 구조로 재작성 |
| 이해관계자 협업·설득 | 엔지니어/디자이너/사업/외부 파트너 등 3개 이상 축 조율 사례 | 이해관계자 지도를 1장으로 시각화 |
| 그로스 실험·ROI (우대) | A/B·코호트 실험 설계 → 가드레일 지표 → ROI 계산 경험 | 부족하면 리워드 가상 실험을 스스로 설계해 연습 |
| 결제·핀테크 도메인 (우대) | 없다면 "제한된 도메인에서 빠르게 학습해 의사결정한 경험"으로 대체 | 아래 6. 학습 플랜으로 2주 내 보완 |

## 3. 전형 단계별 대응 전략

### ① 서류 전형
- 이력서 최상단 3줄: 5년+ 모바일 PM · 임팩트 수치 1개 · 오프라인/결제 또는 그로스 실험 키워드
- 자기소개서: "왜 당근페이 현장결제팀인가"에 대한 관점(오프라인 상권 x 모바일 경험의 교차점)
- 포트폴리오 3사례: 현장 문제 발굴형 / 수치 임팩트형 / 이해관계자 조율형

### ② 과제 전형
예상 과제: 현장결제/당근카드 리텐션 리워드 실험 설계, 오프라인 결제 신규 기능 기획, 우선순위 로드맵.

답안 구조: 문제 정의(정량+정성) → 가설 → 실험 설계(북극성+가드레일 지표) → 이해관계자 영향(카드사·파트너사) → ROI/우선순위. 1p 요약 + 상세 로직 분리 제출 권장.

### ③ 직무 인터뷰
예상 질문:
- 수치로 증명한 임팩트가 본인 기여분인지 어떻게 구분하는가?
- 통제 불가능한 이해관계자(카드사·파트너사)와 갈등 시 무엇으로 설득했는가?
- 결제 도메인 경험이 없는데 왜 이 역할을 할 수 있다고 보는가?
- 가설→제품 반영까지 가장 빨랐던 사이클은?

모든 답변은 STAR, Result는 숫자로 종료.

### ④ 컬처핏 인터뷰 · 레퍼런스체크
- "내 담당이 아니었지만 먼저 나선" 사례, "실패를 인정하고 회고에서 방향을 바꾼" 사례 준비
- 레퍼런스체크 대상자에게 사전에 강조 포인트 공유

### ⑤ 처우 협의
- 현재 연봉/오퍼 근거자료 정리, 3개월 수습기간 평가기준 사전 질문, 시장 밴드 조사

## 4. STAR 스토리 3슬롯 (템플릿)

1. **현장 문제 발굴형** — S: 불편의 데이터/CS 신호, T: 목표, A: 원인 규명 방법, R: 지표 변화(%, 기간)
2. **이해관계자 설득형** — S: 충돌 상황, T: 지켜야 했던 원칙, A: 합의 과정, R: 실행/출시 결과
3. **그로스 실험형** — S: 배경, T: 가설+성공지표, A: 실험 설계/운영, R: ROI 환산 결과

## 5. 실전 사례 — 카카오T 결제수단 연동 프로젝트

볼트업 앱 내 카카오T 연동(회원가입/로그인·결제), 충전 프로모션(카카오T 결제수단 충전 시 1천원 할인), 결제수단 변경·추가 버튼 툴팁 UX, 복잡한 결제 정책 설계 경험.

**포트폴리오에 넣을 항목**
- 배경 & 스코프: 왜 카카오T 연동이 필요했는지, 본인이 리드한 정확한 범위
- 결제 정책 설계: 인증/정산주기/취소·환불/한도 제약을 정리한 의사결정 플로우
- 프로모션(그로스 실험): 가설, 대상 세그먼트·기간·예산 상한, 채택률·거래액·ROI
- UX 설계: 툴팁을 결제수단 변경/추가 버튼에 배치한 이유, 배포 전후 지표
- 당근페이 JD와의 연결: 정책 설계 = 카드사/파트너사 협업, 프로모션 = 리텐션·리워드 그로스 실험 우대요건과 직접 매칭

**대비해야 할 비판적 질문 3개**
1. 카니발라이제이션 — 1천원 할인으로 늘어난 채택/충전이 신규 행동인가, 다른 결제수단에서 갈아탄 것뿐인가? 할인 비용을 제하고도 순증분이 있었는가?
2. 인과관계 검증 — 툴팁과 프로모션이 동시에 나갔다면 지표 상승 원인을 어떻게 분리했는가? A/B였는가, 전후 비교뿐이었는가?
3. 기여분 분리 — 정책·프로모션 중 본인이 최종 의사결정한 지점은 정확히 어디인가?

이 세 질문에 먼저 스스로 답한 뒤 Slot 2·3의 Result를 실제 수치로 채울 것.
